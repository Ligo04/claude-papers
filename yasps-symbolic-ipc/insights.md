# 洞见 —— 把核心思想讲清楚

## 一句话

> 如果你把仿真的 *结构关系*——谁和谁交互、每个东西如何参数化—— **显式化且可微**(而不是藏在手写
> kernel 里),那么一份描述就能机械地产出导数、稀疏模式、装配规则 *以及* GPU 代码——而那个臭名昭著的
> 组合爆炸会直接坍缩。

## 真正被解决的问题是什么

很容易把它读成"更快的 IPC"——但不是。IPC 作为物理表述已经是成熟的。痛点是 **软件工程** 层面的,
具体说是一种 *可扩展性税*:

每个快速 IPC 系统都把三类结构信息隐式编码、散落在 CUDA kernel 和装配例程里:

1. **连接关系** —— 一个 tet 的能量读取它的 4 个顶点;一个点-三角碰撞读取 4 个顶点。
2. **参数化** —— 位置 *如何* 计算出来。自由顶点直接存 `p`(3 DoF)。仿射体存 `p = A·r + t`(12 DoF)。
   笼形点是 8 个笼顶点的加权和。等等。
3. **局部→全局映射** —— 这个 12×12 的局部 Hessian 块落在全局稀疏矩阵的哪里。

因为是隐式的,新增 *一种* 参数化就要重新推导导数 **并且** 写新的装配逻辑 **并且**——对碰撞而言——处理
参与顶点之间参数化的每种 *组合*。这就是那个 **3⁴ = 81** 的怪物:一个点-三角碰撞能量,每个顶点 3 种可能
参数化,81 套独立的导数/装配/kernel。

## 概念性转变

**从命令式、按类型特化的 kernel → 到关系式、声明式、可微的 IR。**

之前的仿真 DSL(Ebb、Simit)已经用 *关系* 方式建模网格(一个 tet 是 4 个顶点上的超边),但它们描述的是
**命令式模板计算**。之前的 autodiff/形式编译器(FEniCS/UFL、TinyAD、Herholz et al.)对 **声明式能量** 求导,
却把一组固定的图元类型写死。

YASPS 把两者融合:**在关系数据模型之上的声明式能量**,然后追问了一个别人没回答的硬问题——
*微分如何与关系运算交互?* 答案是两个带有干净微分规则的算子:

- **`JOIN`** = "沿关系收集"。微分规则:它是结构重排(拼接),所以 `∂JOIN_C(α) = JOIN_C(∂α)`——收集的导数
  就是导数的收集(块对角/恒等)。*微分与 JOIN 可交换。*
- **`UNION`** = "这个量是若干可选参数化之一"。微分规则:`∂UNION(α₁,…,αₘ) = UNION(∂α₁,…,∂αₘ)`。
  *微分也与 UNION 可交换。*

第二条是皇冠上的明珠。

## 为什么 `UNION` 是关键诀窍(以及它为何奏效)

考虑 soft↔affine 碰撞。两个碰撞顶点各自可能是自由或仿射——2×2 = 4 种情况。朴素做法都很糟:

- **按参数化分支** → 计算图分裂成 4 个子图,每个都要自己的导数 kernel 和装配。再求导一次又继续分裂 → 指数级。
- **数值上预计算世界坐标位置,然后忘掉它们从哪来** → 现在你 *无法* 把导数传播回 `A` 和 `t`。链式法则断了。

`UNION` 在针尖上穿了线:它保留 **一个** 符号节点,*记住* 每个元素的参数化血统(那个 `(j, i)` 标签——
哪个分支、哪个实例),却向下游计算呈现一个统一形状的单一属性(3×1 位置)。因为微分与 `UNION` **可交换**,
导数依然是单个 `UNION` 节点——那 4 种情况从不分裂成 4 个 kernel。运行时 `UNION` 做廉价的 *路径选择*,但
编译期只有 **一个** kernel。指数 → 线性。

`UNION` 付出的代价——以及如何收回:

- `UNION` 预留 **最大尺寸** 表示,所以符号 Hessian 按最坏情况尺寸构建(如 ABD-ABD 是 24×24,即使实际碰撞
  是 free-free 的 6×6)。用 O(n³) 的特征分解去投影一个 24×24 矩阵是极其浪费的。
- **两种方式收回:** (1)**块压缩**——运行时一旦知道实际碰撞类型,丢掉 UNION 失活分支引入的结构零行/列
  (24→15);(2)**降维投影**——当所有参数化都是 *线性* 的(自由和 ABD 都是!),二阶链式法则的曲率项消失,
  于是你可以投影那个小的 *内层* Hessian 再用 Jacobian 夹起来:`J^T · Project(H_inner) · J`(15→6)。
  净效果:投影最高快 **44×**。

所以深层要点是:**那份用来避免代码爆炸的结构信息,同时也精确告诉你如何缩小必须做特征分解的矩阵。**
结构不只是为了正确性;它就是性能杠杆。

## 它为什么根本上奏效(数学骨架)

一切都依赖 **二阶链式法则**:

```
∇²ₓ f(g(x)) = Jg(x)ᵀ · ∇²_g f(g(x)) · Jg(x)  +  Σⱼ (∂f/∂uⱼ) · ∇²ₓ gⱼ(x)
```

两个事实让它既好处理又可复用:

1. **JOIN 和 UNION 对其输入是线性的** ⇒ 它们的 `∇²g` 项(第二个求和)**消失** ⇒ JOIN/UNION 的 Hessian
   就是子节点 Hessian 的 JOIN/UNION。关系式地搬动数据不引入新的曲率。
2. 链式法则 **可递归组合**,所以 YASPS 可以在一小组 **边界节点**(能量节点、JOIN 节点、UNION 节点、数据节点)
   处拆分能量图,*每条边界边* 只计算一次局部 Jacobian/Hessian,并在经过共享子表达式的每个能量之间 **复用**
   (例如一个统一的顶点位置属性同时喂给弹性、点-三角、点-边能量)。

这是 autodiff 里"复用中间结果"的思想,但被提升到了 *关系* 层面,并且成为结构性的而非偶然的(因此即便对生成
代码做公共子表达式消除抓不到的情况,它也能复用)。

## 权衡

| 你得到 | 你付出 |
|---|---|
| 约 130 行 Python 就能新增一种参数化,后端零改动 | 要构建并维护一整套编译器/JIT 栈;首次 `minimizeEnergy` 触发代码生成+编译延迟 |
| 所有参数化组合共用一个 kernel(没有 81 路爆炸) | UNION 预留最大尺寸块 ⇒ 需要额外的压缩/投影机制把浪费收回来 |
| GIPC 级别的总运行时间,*快得多* 的 CG 求解 | 微分+装配阶段 **慢于** GIPC 的手工调优 kernel |
| 在图元/参数化上的通用性 | 必须 *排除* 与参数化耦合的部分:**碰撞检测 / CCD** 和 **牛顿步进/线搜索** 由用户负责 |

## 局限(诚实地说)

- **不是完整的仿真器。** YASPS 刻意只提供局部→全局的微分 + 装配 + 线性求解。CCD/CD 和牛顿步进在外部
  (他们的例子用了一个专门针对 *线性* 参数化的 CCD——所以真正非线性的参数化需要一个你不能白拿的兼容 CCD)。
- **降维投影只对线性参数化成立。** 自由顶点和仿射体是线性的;一个真正非线性的参数化会保留曲率项,放弃那个
  44× 杠杆(你只能退回到只做块压缩)。
- **编译期/JIT 开销** 以及对运行时碰撞类型(动态实例)的依赖,意味着收益要在长仿真上摊销,而非一次性求解。
- **绑定 GPU/CUDA**;设计假定局部计算是"高度并行"的,这契合 IPC 但并非所有负载都如此。
- 特征分解用 Eigen 在 GPU 上的模板化 EVD——鲁棒,但 O(n³) 成本正是所有尺寸缩减机制存在的理由。

## 与先前工作的对比

- **GIPC / Stiff GIPC、PolyFEM、Stark:** *单 kernel* 的微分更快(手工调优),但可扩展性以每种新参数化
  *上千* LOC 衡量,且把接触情况枚举写死。YASPS 牺牲一点微分速度换来 ~130 行的可扩展性 *并且* 靠求解器在总
  时间上取胜。
- **FEniCS/UFL、TinyAD、Herholz et al. 2024:** 形式编译/代码生成 autodiff,但绑定固定图元类型或要求用户手工
  指定装配结构;混合参数化仍按组合分裂成 kernel。
- **PyTorch / DiffTaichi / Warp:** 适合稠密/网格设置;装配大型不规则网格算子仍需自定义稀疏/布局基础设施。
- **Ebb / Simit:** 关系式网格 DSL,但是 *命令式* 模板,不是 *声明式可微能量*——它们从未需要解决"微分如何与
  JOIN/UNION 交互"。

## 实际意义

- **对框架构建者:** 教训是把 *参数化备选项* 当成一等的、可微的构造。接触的组合爆炸并非本质——它是 *分支
  分得太早* 的产物。把选择推迟到单个符号节点内的运行时路径选择。
- **对研究者/实践者:** 你可以在 Python 里原型化奇异设置(笼形控制、混合材料体、通过球面参数化做斥力曲线、
  FEM↔ABD 耦合)而不必碰 GPU 代码——论文的例子正是这些。
- **通用设计原则:** *你为正确性而暴露的结构,通常正是你为性能而需要利用的结构。* 让它显式且可微,你就同时拿到
  两者。
