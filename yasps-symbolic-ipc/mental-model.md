# 心智模型 —— 如何在脑中归类这项工作

## 这是 *哪一类* 问题?

这 **不是** 新的物理模型,**也不是** 接触的新数值方法。物理(IPC)和求解器家族(投影牛顿 + PCG)都是
现成拿来的。贡献落在 **编程系统 / 编译器** 领域,具体说:

> *如何构建一个领域专用语言 + 编译器,让用户能通用地声明富接触仿真,并机械地推导出导数、稀疏矩阵结构和
> GPU 代码——并且当参数化混合时不发生组合爆炸?*

所以这样归类:**一个面向 IPC 的、由符号微分驱动 JIT 编译的关系式声明式 DSL**。新的研究对象是
*微分与关系算子(JOIN/UNION)之间的交互*。

## 30 秒类比栈

- **它是面向接触的 FEniCS/UFL,但参数化多态。** 像 UFL 一样,你符号化地写能量,形式编译器生成装配代码。
  *不同* 之处在于图元类型和参数化不是写死的——它们是你定义的值,而 `UNION` 让一个能量横跨多种。
- **`JOIN` 是数据库 join / 一次 gather。** 一个连接关系就是外键关系(tet → 4 个顶点 id);`JOIN` 拉取被引用的
  行。对 gather 求导是平凡的(恒等/块对角)——这就是它能组合的原因。
- **`UNION` 是一个保持可微的带标签的和类型(discriminated union)。** 把一个位置想成 `Either<Free, ABD>`,
  你仍能反传到任一活跃分支。那个"标签"就是 `(j, i)` 索引。
- **整个后端是一个微型 autodiff 编译器**,把 autodiff 的"复用共享子表达式"思想提升到关系层(边界节点拆分),
  并配一个代码生成器,生成 **模块化的 `.o` 文件** 再链接——就像 C 的分离编译。

YASPS 恰好坐落在三条此前没被组合起来的脉络的 **交点**:IPC 物理、形式编译 autodiff、关系式网格 DSL。
它独特的主张是:首个 *同时* 拿到三方好处(可扩展 + GPU 快 + 无爆炸)的工作,做法是把参数化备选项作为
可微 IR 中的一等公民。

## 一个有用的"前端 vs 后端"划分

- **前端(Python,用户接触的):** scene → meshes → primitive types → attributes → connectivities →
  `JOIN`/`UNION` → energies → `addMinimizeTarget` → `minimizeEnergy`。声明式且小巧。
- **后端(自动,论文真正讲的):** 符号微分器 → 索引生成器(全局稀疏 & 局部→全局放置)→ 代码生成器/JIT
  (CUDA `.o` 文件、PSD 投影 kernel、压缩)→ 最小化器(带定制 SpMV + 块 Jacobi 预条件子的 PCG)。

读论文时一直问自己:*"这是前端的人机工程点,还是后端机制?"*——大部分智识重量在后端。

## 如果只记一件事

**过早按参数化分支会导致爆炸;`UNION` 把选择推迟到单个可微节点,因此编译期保持线性、运行时只做路径选择
——而同一份结构告诉你如何缩小要做特征分解的矩阵。** 其余都是为这个思想服务的工程。
