# 洞见 —— 这项工作为何重要

> 这是最重要的文件。它解释*思想*，而不仅仅是机械步骤。

## 1. 核心思想，用大白话讲

当你在浮点下做碰撞检测，微小的舍入误差会翻转一个 `<` 比较。对一个三角形来说，这只意味着一个本该略大于零的数
算出来略小于零——你通过**放宽阈值**来修：不测 `value < 0`，而测 `value < −(误差界)`。如果你可能偏差 `ε`，
就要求该值至少超过 `0` 达 `ε` 你才相信它。简单，而且鲁棒三角形 CCD 就是这么做的。

**本文的核心领悟是：这个技巧对参数曲面失效，因为这里的误差不只破坏*数值*——它破坏*结构*。**

TDIBM 算法判断"在这个时间窗内两个曲面的包围盒是否重叠"时，会构造两条**分段线性包络**（上方的凹"max-包络"
与下方的凸"min-包络"），并检查它们是否相交。构造每条包络都要**按斜率对一组线排序、只保留构成凸边界的那些**
——这是一个组合的、分支密集的过程（线段凸包栈机）。

如果一次舍入误差翻转了其中一个"保留/丢弃"决策，你得到的不是"正确的包络，偏差 ε"。你得到的是一条**线段集合
错误的不同包络**——可能非凸、可能少了一段、可能多了一段。几何在**拓扑上**就错了。这里没有单一阈值可放宽，
因为损害发生在"哪些线被纳入"，而非某个数值裕度。

所以本文的答案是一套两段式哲学：
1. **分解误差**，使可分析的部分能被定界；
2. **把每个不确定决策都偏向安全侧**（多报碰撞，绝不漏报）。

## 2. 关键概念动作：解耦误差来源

直接分析之所以难，是因为两件事*同时*出错：输入系数本就被舍入了，*而且*处理它们的算术又舍入一次，二者还通过
分支交织。本文的技巧（式 11）是插入一个**想象中的中间算法**：

```
f      = 精确 max-包络，精确系数，精确算术          （真值）
f̂₁     = max-包络，系数不精确但算术精确             （想象）
f̂      = max-包络，系数不精确且算术也不精确          （真正运行的）

总误差 ε_constr = max|f̂ − f|  ≤  max|f̂₁ − f|  +  max|f̂ − f̂₁|
                              =     ε_coeff     +     ε_arith
```

- `ε_coeff`——"如果我的系数略错但我算得完美，包络偏差多少？"这是一个干净的 Lipschitz 式界：一条线 `aₜ+b`
  在误差 `ε_a, ε_b` 下最多偏离 `t_U·ε_a + ε_b`。
- `ε_arith`——"如果我的系数精确但比较会舍入，包络偏差多少？"拓扑就藏在这里。洞见是：**排序和去重不引入算术
  误差**（它们只比较和重排）。误差*仅*通过决定一条线是否占优/是否入栈的 `Φ`、`φ` 量进入。所以你只需给*那些*定界。

为何重要：一个看似无望的问题（"误差与拓扑纠缠"）变成两个各自可定界的问题。**解耦就是全部的诀窍。**

## 3. 为什么偏向误报是安全的——以及如何做到

TDIBM 的凸包假设*本就*是保守的：用精确算术时它可能多报（FP），但绝不少报（FN）。是浮点打破了这个保证。所以
修法是让每个浮点决策都**朝算法本就偏向的方向出错**：

- **阈值偏移。** 每个谓词 `θ < 0`（用于添加/丢弃线、检测包络相交）改为 `θ < −ε_θ`。现在浮点谓词*只在精确值
  确定为负时*才触发。代价：你有时会*漏掉*一个真正的 `θ<0`（丢掉一条有效线）——但本文证明由此产生的包络误差
  本身有界（≤ 同一个 `ε`），而丢掉一条线会*增大* max-包络（图 2 左），只可能*扩大*碰撞窗 → FP，而非 FN。
- **包络平移（`ε_constr`）。** 构造完 max-包络后，把它**上移** `ε_constr`（min-包络**下移**）。这保证计算出的
  包络位于真实包络*之上*，于是任何相交测试都是保守的。
- **相交时的推开偏移（`δ`）。** 在*求两条包络交点*时，近平行的线段会让交点误差爆炸（除以 `c_β−c_{α+1} → 0`）。
  本文不去给这个爆炸的误差定界，而是在求交前把两条包络**额外推开 `δ`**。漂亮的结果（式 18）：取
  `δ = 2Δ_d[(1+ε)⁴−1]` 时，理论误差 `Δ_t` 被界为**恰好 0**——推开*抵消*了最坏情况的算术误差，而不是去度量它。
  且累积地，在 `I` 次迭代后推开 `Iδ` 仍然安全（附录 C.3 的望远镜求和证明）。
- **截断。** 最终的 ToI `τ_L` 被截断进 `[t_L, t_U]`，并通过 `nextafter` 把除法误差计入，因此它是供下游细分使用
  的可证明安全值。

反复出现的模式：**别和误差搏斗，要比它更保守。** 哪里容易定界，就定界并放宽；哪里定界会爆炸（近平行除法），
就重构使误差根本伤不到你。

## 4. 数据集洞见：把问题反过来

正向："给定曲面，算出精确碰撞"——需要符号代数，且在非孤立接触上卡死（>1 天）。**对基准而言是死路。**

反向（本文洞见）："给定我*想要*的碰撞，构造能产生它的曲面。"现在一切都是*线性*约束求解：
1. **规定**答案：选 ToI `t*` 与接触参数坐标 `(u*,v*)`。
2. **求解**控制点，使两曲面在该点该时刻重合（线性方程组）。
3. **抽取**接触附近的局部曲面片（避免无关碰撞）。
4. **推断**速度（另一个线性插值求解），回溯出初始状态。
5. **验证** `t*` 确实是*最早*接触（在 `[0,t*)` 上跑有理 TDIBM）。
6. **定型**：标 GT=1；把时间步缩小 `ε_T` 来制造对应的 GT=0 用例。

因为每一步都是精确有理算术（GMP），真值是*精确*的——没有数值伪影污染标签。这是公平测试浮点鲁棒性的唯一方式：
你的*测试预言机*本身必须无误差。

## 5. 微妙的精华：二进分数（dyadic）性质

一个面向浮点 CCD 的基准必须*给算法喂 double*。但有理构造产生的分数未必能用 IEEE-754 表示——把它们转成 double
会把截断误差注入*输入*，污染你正要度量的东西。

修法：让每个量都保持为**二进分数** `p/2^k`（`|p|<2⁵³`）——恰好是可用 double 表示的实数集合。难点工程在于：
要在高斯消元（其主元除数是任意多项式，几乎永远不是 2 的幂！）中保持这一性质。他们的方案：
- 把所有输入（控制点、UV 坐标、法向）限制在精心选择的二进分数值——例如法向分量限制为 `{0, ±2^k}`，常用轴对齐
  `(1,0,0)` 来*解耦*约束方程。
- 用 **2×2 子矩阵的克拉默法则**求解，只接受第一个有理残差*恰好为零*的——而非完整高斯消元。
- 最后一道**往返检验**：有理 → double → 有理必须是恒等。实测丢弃率：**0%**——纪律足够。

这是一个把*数学*与*数值表示*协同设计、使精确性一路存活到输入文件的漂亮例子。

## 6. 它引入了什么概念转变？

- **从"给量级定界"到"保护拓扑"。** 分支密集型几何算法的鲁棒性关乎保持组合结构，而非仅仅夹住数值漂移。
- **从"分析纠缠系统"到"解耦并分别定界"。** 适用于任何"表示误差与计算误差交织"的流水线的可复用模板。
- **从"正向计算真值"到"反向构造真值"。** 当正向预言机不可行时，反演它——并把反演与一种保持结果精确的数值表示
  纪律（dyadic）配对。
- **从"恰好有效的启发式"到"必然有效的保证"。** TDIBM-H 的 10⁻¹² 魔法常数被揭示为一个幸运的经验甜点；
  TDIBM-E 用一个*推导出的、逐用例*的界取代它。

## 7. 权衡

- **FP vs. FN。** 消除 FN 必然要接受一些 FP。本文有意付这个代价——FP 便宜，FN 灾难性——并证明其 FP 数仍 ≤
  不安全的基线。
- **速度 vs. 安全。** TDIBM-E 相对 TDIBM-H 增加 ≤40%、相对原始 TDIBM ≤120%。在*过度简化*的线性网格上它明显更慢
  更保守——保证不是免费的，且在几何平凡处性价比最低。
- **通用性 vs. 精确性（数据集）。** 二进分数纪律买来精确，却把可达几何限制在二进分数友好的构型；它也把基准
  限制在**孤立点接触**（暂无曲线/面接触）。

## 8. 局限（作者陈述 + 观察）

- 基准只覆盖**孤立点碰撞**——流形/面/曲线接触需要根本不同的代数构造（开放问题）。
- 系统性生成*对抗性*角落用例以真正压力测试 CCD 仍是开放的。
- 扩展到完整 **CAD**（复杂裁剪曲面、多片自碰撞）是未来工作；NURBS 可无损转为 Bézier 故原生支持，简单裁剪
  通过域裁剪处理。
- 在平凡的线性几何上，TDIBM-E 的保守性属于过度（更多 FP、更慢）。

## 10. 实践意义

- 任何在**光滑/CAD 几何**上构建仿真器的人（曲面体上的布料、等几何分析、高阶 FEM 接触）现在都能获得*有保证*的
  不穿透，而无需赌一个手调容差。
- **基准**成为可复用的标尺：任何新的参数 CCD 方法都能被精确度量 FN/FP 率，这在以前不可能。
- **"分解—再保守偏移"** 的配方可迁移到其他分支密集型鲁棒几何（布尔运算、网格排布、交线计算）。
