# 自测题 — KPM-FR（15 题）

> 5 基础 · 5 进阶 · 5 高级。先自己答，再展开对照。

## 基础（Basic）

### Q1. KPM-FR 的全称是什么？它想同时优化哪三个目标？

<details>
<summary>答案</summary>

**Kinetic Predicted-Moment Flux Reconstruction（动理学预测矩通量重构）**。它想在单一框架内同时优化流体仿真长期互斥的三个目标：**高保真度（低数值耗散）、大计算吞吐、小内存占用**。面向低马赫数弱可压等温流。

</details>

---

### Q2. KPM-FR 建立在哪两个已有方法之上？各贡献了什么？

<details>
<summary>答案</summary>

- **气体动理学格式 GKS**（Gas-Kinetic Scheme, Xu 2001）：贡献「通量中心、stream-free」哲学——从局部演化的 Boltzmann-BGK 直接构造宏观通量，**不存储分布函数** → 省内存；且统一处理无黏/黏性。
- **高阶通量重构 FR**（Flux Reconstruction, Huynh 2007）：贡献高阶谱类空间离散 → **低数值耗散**，弥补 GKS 二阶有限体积耗散大的缺点。

</details>

---

### Q3. 为什么标准 LBM（如 D3Q27）内存占用大？KPM-FR 相比省多少？

<details>
<summary>答案</summary>

标准 D3Q27 LBM 每个格点要存 **27 个分布函数** `f_i`（且常需两套避免写冲突），内存巨大。KPM-FR 用**矩表示**、不存分布函数，每点内存降到 **42 字节**，是标准图形 LBM 的 **18%**（约省 5 倍以上），MR-LBM 的 53%。

</details>

---

### Q4. KPM-FR 每个时间步用几个 GPU kernel？分别做什么？

<details>
<summary>答案</summary>

**两个融合 kernel**：
- **Predictor**：计算局部空间导数（FR 微分），把物理态编码成紧凑的**预测矩**，写入全局内存。
- **Corrector**：读回这些矩，闭式评估元内通量 `F(h)` 和公共通量 `F*(h)`，应用校正、单步更新宏观变量。

关键：FR 微分全在片上（on-chip）完成，梯度不溢出到 DRAM。

</details>

---

### Q5. KPM-FR 的吞吐和最大仿真规模是多少？在什么硬件上？

<details>
<summary>答案</summary>

单张 **NVIDIA RTX 4090**（消费级）上，完整时间步 **> 80 亿（8 billion）solution-point 更新/秒**，近 roofline 内存带宽利用。最大规模 **18 亿（1.8 billion）solution points**（单工作站）。赛车 demo：2000×332×800 ≈ 5.3 亿点、仅 21 GiB。

</details>

## 进阶（Intermediate）

### Q6. 写出 KPM-FR 的控制方程链：从 Boltzmann-BGK 到守恒型 NS。

<details>
<summary>答案</summary>

1. **Boltzmann-BGK**（式 4）：`∂f/∂t + ξ·∇f = -(1/τ)(f-g)`，`g` 为 Maxwell 平衡态，`τ=ν/(RT)`。
2. **矩关系**（式 5）：`U=⟨φf⟩`，`F_d=⟨ξ_d φ f⟩`，`φ=[1,ξ^T]^T`，`U=[ρ,ρu^T]^T`。
3. 对式 (4) 乘 `φ` 并对 ξ 积分（BGK 守恒质量动量）→ **守恒型控制方程**（式 6）：`∂U/∂t + ∇·F = 0`。

式 (6) 恢复等温弱可压 NS，通量 F 在单一动理学表达式内同时含无黏+黏性。

</details>

### Q7. 为什么 MR-LBM 虽然只存矩仍有性能问题？KPM-FR 如何避免？

<details>
<summary>答案</summary>

MR-LBM 只存宏观矩省了内存，但其 **streaming 步骤本身需要完整分布函数 `f_i`**，所以每个 link 都要**从矩即时重构 `f_i`**。重构有两个代价：(i) 引入**额外数值耗散**；(ii) 重构出的分布占用**共享内存**、常需半精度才能塞进片上 → 新瓶颈。

KPM-FR 是**通量式（stream-free）**，根本没有 streaming、**从不重构完整分布函数**——演化直接表达为矩/预测矩的代数运算，故无重构耗散与共享内存瓶颈。

</details>

### Q8. FR 半离散系统 `∂U/∂t = -(2/L)(QF + CF*)` 中 Q、C、F* 各是什么？为什么 Q=D-CR？

<details>
<summary>答案</summary>

- `D`：K×K 微分矩阵（Lagrange 基导数），只管单元内。
- `R`：2×K 外插矩阵（把多项式求值到左右边界 ±1）。
- `C`：K×2 校正矩阵（校正函数 `g_LB, g_RB` 在 SP 处的导数）。
- `F*=[F*_LB, F*_RB]^T`：左右界面的公共通量，负责所有单元间耦合。
- `Q=D-CR`：把「单元内微分 D」与「边界外插 R 经校正 C 的修正」合并——因为连续通量 `F̃=F+g_LB(F*_LB-F(-1))+g_RB(F*_RB-F(1))` 中含 `F(±1)=R·F` 项，求导后并入 D 得 Q。

取 Gauss-Lobatto + `g_2` 校正函数使 C 高度稀疏；D,R,C,Q 全局常量。

</details>

### Q9. 半时刻分布函数 `f(h) ≈ A f_s(h) + B g(h)` 中各项含义？A、B 怎么定？

<details>
<summary>答案</summary>

来自把 Boltzmann-BGK 在 `[0,h]`（`h=Δt/2`）有限差分积分（式 11）：
- `f_s(h) = g(0) - h ξ·∇g(0)`：**传播分布**，平衡态 `g` 沿粒子速度 ξ 的一阶 Taylor 展开（自由输运部分）。
- `g(h)=g(U(h))`：半时刻宏观态对应的平衡态（碰撞松弛目标）。
- `A=τ/h`，`B=1-τ/h`：由松弛时间 τ 与半步 h 决定，权衡自由输运与碰撞松弛。
- 未知 `U(h)` 由相容条件 `U(h)=⟨φ[g(0)-hξ·∇g(0)]⟩` 给出。

</details>

### Q10. 为什么单步中点更新比 RK2 省？省的是什么资源？

<details>
<summary>答案</summary>

因为在 `h=Δt/2`，`F(h)` 和 `F*(h)` 都有**闭式解**，可一步到位（式 10）得二阶时间精度。RK2 至少需**两次公共通量评估**，每次都要跨单元数据交换 → 两次 off-chip 内存流量。单步只算一次公共通量，**单元间数据交换/off-chip 内存流量减半**。

省的主要是**内存带宽和单元间通信**（不是算术）——因为 KPM-FR 是 memory-bound，带宽最稀缺。

</details>

## 高级（Advanced）

### Q11. 公共通量 `F*(h)` 为什么带来单元间数据依赖？朴素实现要传多少数据？

<details>
<summary>答案</summary>

元内通量 `F(h)` 自足（式 11 只需本地 `g(0), ∇g(0)`）。但 `F*(h)` 耦合相邻单元：构造界面公共分布 `f*` 需要**邻居单元的 `∇g`（进而 `∇U`）**，因为邻居的半时刻分布 `f_s_R/f_s_L` 是用它自己的梯度算的。

朴素实现下，**3D 每 solution point 需跨单元传 16 个标量**（梯度张量）。这些值 predictor 写、corrector 读，必经全局 DRAM，每个标量增加内存与带宽消耗——界面成为带宽受限信道。

</details>

### Q12. 「预测矩」如何把跨单元载荷压到最小？依据哪两个观察？

<details>
<summary>答案</summary>

两个观察：
1. **演化态恒等式**：算 `F*(h)` 真正需要的是邻居的**传播分布 `f_s`**，而非原始梯度 `∇g`。`f_s` 可用更紧凑的量编码。
2. **平衡/非平衡分解**：任意分布 = 平衡态 `g`（**完全由 U 决定，接收方能自己重建**）+ 非平衡偏离 `f_neq`（携黏性信息）。

于是只需把与 `f_neq` 相关的**少数预测矩标量**跨单元传输，`g` 部分由接收方从本地 `U` 重建。载荷从 16 标量压到几个预测矩 → 消除梯度流量，配合融合 kernel 逼近带宽 roofline。

</details>

### Q13. 写出公共态 `U*(h)` 和公共分布 `f*(h)` 的构造式，解释「迎风」的作用。

<details>
<summary>答案</summary>

界面两侧各重构半时刻分布 `f_L(h), f_R(h)`，公共态由**半程矩**逼近（式 14）：

```
U*(h) = ⟨φ f_L(h)⟩_+ + ⟨φ f_R(h)⟩_-
```

`⟨·⟩_±` 表示对半空间 `ξ·n≷0` 积分。公共分布（式 15）：

```
f*(h) ≈ B g(U*(h)) + A · { f_s_L(h)  if ξ·n>0
                           f_s_R(h)  if ξ·n<0 }
```

**迎风**（upwind）：传播部分 `f_s` 按粒子速度方向从**来流一侧**的单元选取——`ξ·n>0`（粒子从左向右穿过界面）取左单元的 `f_s_L`，反之取右单元的。这反映了信息沿特征线传播的物理，保证格式稳定（朴素平均两侧通量是无条件不稳定的）。

</details>

### Q14. 传统高阶 FR 处理黏性（二阶导）为什么麻烦？KPM-FR 如何「白捡」黏性处理？

<details>
<summary>答案</summary>

传统 FR/DG 中，各单元独立成多项式，**二阶空间导数在界面不连续**。要保证黏性通量的跨单元一致性，需 ad hoc 辅助过程：BR1/BR2（Bassi-Rebay）、LDG、IP（interior penalty，需依赖多项式阶数/网格的稳定罚项）、RDG（patch recovery，加宽 stencil）。这些增加算法复杂度、stencil 宽度、通信开销。

KPM-FR 用**动理学演化**：无黏与黏性通量由**同一个局部半时刻分布 `f(h)`**（式 11）统一给出——`f(h)` 里既有平衡（无黏）也有非平衡（黏性）部分，kinetic penalty 内置于 BGK 松弛。于是无需任何辅助梯度过程，黏性处理「白捡」。这是选 mesoscopic 基础的深层回报。

</details>

### Q15. 论文声称「数学紧凑性 = 硬件效率」。用 KPM-FR 的具体设计解释这个等价。

<details>
<summary>答案</summary>

三处体现数学决策直接等价于硬件目标：

1. **完全在矩空间演化** ⟺ **off-chip 只存/搬矩**：不实体化 6 维分布函数，最终量本就是低阶矩 → 内存 42 字节/点，带宽载荷小。
2. **预测矩只编码非平衡部分** ⟺ **唯一 off-chip 跨单元载荷是几个标量**：把传输压到物理必需最小，硬件上逼近内存带宽 roofline。
3. **单步 + 双融合 kernel + 片上 FR 微分** ⟺ **梯度不溢出 DRAM、公共通量只算一次**：算术全片上、off-chip 流量减半。

因为该问题是 **memory-bound**，性能上限由 off-chip 流量决定；而「把单元间传输载荷压到最小」既是数学上的紧凑表述，又恰好是硬件上的带宽最优目标——二者是同一件事的两种描述，故不是先有数学再调硬件，而是数学形式本身为硬件而设计。

</details>
