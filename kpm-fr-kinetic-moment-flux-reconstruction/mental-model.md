# 心智模型 — KPM-FR

## 这是什么类型的问题？

**高性能流体仿真中的数值格式设计问题**：如何构造一个显式、GPU 友好的求解器，在**低马赫弱可压**流下同时优化「保真度（低数值耗散）、吞吐、内存」这三个历来互斥的目标。它横跨：

1. **动理学理论**（Boltzmann-BGK、Maxwell 平衡态、矩、GKS）——提供「通量而非分布」的省内存基础与统一黏性。
2. **高阶数值方法**（Flux Reconstruction / DG / 谱元）——提供低耗散的空间离散。
3. **GPU 体系结构**（roofline、片上内存、kernel 融合、混合精度）——把数学紧凑性兑现成实际性能。

核心张力：**内存 × 耗散 × 吞吐三者被「单元间怎么传信息」这件事绑死。**

---

## 用一个类比来记

**KPM-FR = 「流体界的 GKS + 高阶 FR + 数据压缩传输」。**

想象单元之间要打电话交换信息：
- **LBM**：把整段录音（27 个分布函数）都存下来、逐方向搬运——音质好（低耗散）但硬盘爆炸（内存大）。
- **MR-LBM**：只存摘要（矩），但打电话前要把摘要**还原成完整录音**再传——还原既失真（引入耗散）又占内存。
- **GKS**：不存录音、每次现场重新合成——省硬盘，但合成算法极复杂（算术强度高）、音质二阶（耗散大）。
- **KPM-FR**：永远只用摘要（矩），且只把对方**必须知道的那几个关键数字（预测矩 = 非平衡部分）**发过去，平衡部分对方自己能算。摘要用高阶多项式表达（低耗散），整个通话压成两次片上运算（高吞吐），硬盘只记 42 字节/点（小内存）。

一句话：**别搬录音，也别还原录音，只发对方算不出来的那几个数。**

## 需要哪些前置知识？

**必备：**
- **Navier-Stokes 与不可压/弱可压**：投影法、压力泊松、数值耗散/色散概念。
- **动理学方法基础**：Boltzmann-BGK 方程、Maxwell 平衡态 `g(ρ,u)`、矩 `U=⟨φf⟩`、LBM stream-and-collide、GKS 通量思想。
- **高阶方法**：Flux Reconstruction（Huynh 2007）、Lagrange 基、solution points、Gauss-Lobatto、微分矩阵、correction function、DG/SD 关系。
- **GPU 性能模型**：roofline、memory-bound vs compute-bound、片上（寄存器/共享内存）vs 全局 DRAM、kernel 融合、带宽饱和。

**加分：**
- MR-LBM、cumulant/central-moment LBM；GKFS/LBFS/UGKS/DUGKS；GKS-FR 既有工作。
- 弱可压/人工可压方法（ACM）、LES 湍流。
- 半程矩积分、迎风格式、Riemann solver。

**只想抓主干**：理解「GKS 用通量省内存但慢又耗散 + FR 高阶低耗散但黏性麻烦 → KPM-FR 把演化搬进矩空间、只传预测矩、单步双 kernel，把三者优点合并」即可。

## 它在研究地图里的位置

```
流体仿真数值方法
├── 宏观 NS 求解器
│   ├── 投影法 / Stable Fluids (低阶, 需压力泊松)
│   ├── 高阶谱元 / FR / DG (低耗散, 黏性需 BR1/BR2/LDG 辅助)
│   └── flow map / covector / APIC (低耗散平流)
└── 动理学 (mesoscopic) 求解器
    ├── 流式 (stream-and-collide)
    │   ├── LBM D3Q27 (低耗散, 存 27 个 f_i, 内存大)
    │   ├── cumulant / central-moment LBM (更稳更低耗散)
    │   └── MR-LBM (只存矩, 但 streaming 要重构 f_i)
    └── 通量式 (flux-based, stream-free)
        ├── GKS (Xu 2001) (不存 f, 二阶 FV, 解析复杂)
        ├── GKFS / LBFS / UGKS / DUGKS (简化/多尺度变体)
        ├── GKS-FR (Xu2004/Ren2015/Zhang2018/Li2020b/Ma2022)
        │   —— 各有取舍: 解析复杂 / 多级RK / 解耦黏性通信
        └── ★ KPM-FR (2026) ← 矩空间演化 + 预测矩编码
                              + 单步 + 双融合kernel, 三者协同优化
```

KPM-FR 的独特坐标：**通量式动理学 × 高阶 FR × 矩空间预测矩编码 × 硬件感知双 kernel** 的交汇——把 GKS 的内存优势、LBM/FR 的低耗散、GPU 的带宽饱和三条线合流。

## 如何在脑中分类这项工作

- **一句话标签**：「low-dissipation, low-memory, high-throughput GPU 流体求解器」，或「矩空间的高阶气体动理学格式」。
- **方法论标签**：数值格式创新（kinetic-FR）+ 数据传输最小化 + 硬件协同设计。
- **贡献类型**：**新颖数值格式 + 系统/硬件协同**。价值不在单个新方程，而在「三难协同优化」这个此前未达成的组合，以及支撑它的「矩空间 + 预测矩」统一设计原则。
- **审稿视角看亮点**：42 字节/点、>80 亿更新/秒、内存 18% of LBM、耗散低于 cumulant LBM、18 亿点单 GPU、赛车 demo。
- **审稿视角看弱点**：限低马赫弱可压等温、二阶时间、弱可压误差、无公开代码、推导/实现门槛高。

## 判断题帮你确认理解

> Q1：为什么 KPM-FR 不像 MR-LBM 那样有「从矩重构分布函数」的代价？

A：MR-LBM 存矩但 **streaming 步骤本身需要完整分布 `f_i`**，所以必须重构。KPM-FR 是**通量式**（stream-free），根本没有 streaming 步骤——它从不需要完整分布函数在单元间流动，演化直接表达为矩/预测矩的代数运算。没有 streaming，就没有重构需求，也就没有重构带来的耗散与共享内存瓶颈。

> Q2：单步中点更新省的是算术还是内存带宽？为什么重要？

A：主要省**内存带宽和单元间通信**。RK2 要两次公共通量评估 → 两次跨单元数据交换 → 两次 off-chip 流量。单步只算一次公共通量，off-chip 流量减半。因为 KPM-FR 是 memory-bound（算术已被片上化和预积分压得很小），最稀缺的是带宽，所以省带宽 = 直接提速。

> Q3：为什么说「数学紧凑性 = 硬件效率」在这里不是口号？

A：因为「完全在矩空间 + 只传预测矩（非平衡部分）」这个**数学决策**，直接等价于「唯一的 off-chip 载荷就是那几个标量」这个**硬件目标**。数学上把传输压到物理必需最小，硬件上就逼近内存带宽 roofline——二者是同一件事的两种描述，不是先有数学再优化硬件。

> Q4：kinetic 基础相比纯宏观 NS-FR 的「白捡」优势是什么？

A：黏性通量的跨单元一致性。纯 NS-FR 处理二阶空间导需要 BR1/BR2/LDG/IP 等辅助过程（复杂、加宽 stencil、加通信）。GKS 的动理学演化里，无黏与黏性由**同一个局部分布函数演化**统一给出（式 11 的 `f(h)` 天然含黏性），kinetic penalty 内置，省掉全部辅助。
