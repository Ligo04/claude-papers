# 方法 — WALL-WM 详解

## 0. 总体形式化

WALL-WM 建模 `p_θ(V_e, a_e | V_0, s, c_e)`：
- `V_0`：当前多视角观测（每个相机一个关键帧）
- `s`：当前本体感知状态
- `(V_e, a_e)`：事件对齐的未来*多视角视频*与*末端执行器轨迹*（长度由事件决定，变长）
- `c_e`：描述同一个"动作对齐语义事件"的逐事件字幕

预训练以**事件**为单位：每个样本是从长程 episode 中切出的一个原子 `(V_e, a_e)` 事件，而非定长 chunk；模型被训练去从当前观测**去噪事件对齐的未来**。

---

## 1. 整体架构（先验对齐的层耦合去噪器）

```
            ┌─────────── 指令 (a) ───────────┐
  事件模式: 下一事件语言 ──► T5 文本条件器 ─┐
  统一模式: 全局指令 ──► Staircase 解码 ──► 潜 CoT ─┐
                                                   ▼
  当前多视角观测 V0 ─► (冻结)图像编码器 ─┐    ┌──────────────────────────────────┐
  本体状态 s ───────► 状态编码器 ───────┤    │  事件中心世界模型 (b)              │
                                       ▼    │  ┌──────────────┐  耦合  ┌────────┐│
                                            │  │ Multi-View    │ ─每层→ │ Action ││
                                            │  │ Video DiT     │ K/V    │ Trans- ││──► 动作 a_e
                                            │  │ (Wan, 冻结)   │ 单向   │ former ││
                                            │  │ 去噪视频 V_e  │ ─────► │ 去噪 a ││
                                            │  └──────────────┘        └────────┘│
                                            │     ▲ Execute / Rollout 闭合控制环   │
                                            └──────────────────────────────────────┘
  (c) 时空融合：Nv=3 路相机 → 视图折叠(S1) → 每层跨视角混合(S2) → ViewConcat(S3) → 单向块级耦合(S4)
```

- **视频塔**：继承 Wan 单视角 DiT，扩展到多视角、多本体视频生成；主配方中**冻结**。
- **动作塔**：随机初始化的 action DiT，与视频塔**等深**；每层动作 token 跨注意力读取*配对*视频块的特征，去噪末端执行器轨迹。
- **耦合单向**：动作读视频、**不**给视频 DiT 加任何辅助分支。

## 2. 多视角视觉世界事件建模

在 Wan 主干上嫁接三件事（保留视图内计算不变）：

### 2.1 单视角先验 → 多视角适配
当相机数 `Nv > 1`，每个 DiT 块在常规视图内 Wan 自注意力之后，多跑一个**跨视角分支**：把每个相机流作为独立 batch 项进入，在视图注意力块内*逐帧*重组隐状态，把 Nv 个相机在每个 latent 帧的所有空间 token 拼成一个序列做自注意力（旋转码同时编码相机轴）。

```
h_V_i ← h_V_i + g_i · W_view · CrossViewAttn_i(h_V_i),   W_view 初始化为 0   (式1)
```

**关键**：`W_view` 零初始化 → 初始时该分支贡献为零、跨视角交换不改变继承行为；随训练学习才逐渐开启。视图内 Wan 栈保持不变，外观与语言对齐先验被保留。

### 2.2 Camera RoPE（免标定的相机身份）
为支持大规模多本体训练，给每个视图一个*可学习的旋转身份*，而不在运行时喂标定：把 RoPE 扩展一个视图轴，按 (f, h, w, view) 划分每个头的频率库；视图旋转由一个跨所有视图注意力层共享的*可学习的逐视图嵌入*产生。**增删相机只改这张嵌入表。**

### 2.3 跨视角几何掩码（仅训练期）
两个互补掩码，推理期都丢弃以保持免标定：
- **视锥掩码（Sight-cone）**：把每个 patch 的视锥建模为一个锥 `C(u)=(p0, v̂, γ)`；当两个 token 的视锥在深度带 [d_min, d_max] 内相交（即可能在像素空间观测到同一 3D 区域）才允许跨视角 attend。以 `(1−M_sc)·(−∞)` 作为注意力偏置，禁止几何上不相容 patch 之间的跨视角路由。它*塑造注意力拓扑*，让跨视角图反映物理可见性。
- **管状掩码（Tube）**：以概率 `p_tube` 选一个视图 v\* 和一个 k×k 空间窗，把该窗在*所有 latent 帧*上的 token 替换为纯噪声——制造一个无法靠视图内时间捷径恢复、必须经由其它 Nv−1 个视图恢复的"洞"。它*作用于输入内容*，制造对跨视角注意力的显式需求。
- **互补性**：视锥管"能不能连"（拓扑），管状管"逼不逼着连"（内容）。主配方默认保留 border masking + sight-cone，关闭 tube（`p_tube=0`）；需强化跨视角对应时才开 tube。

### 2.4 视频流匹配目标
继承 Wan 式 v-prediction 流匹配。给定干净 latent `z_V0`、噪声 `ε_V`、采样视频时步 `t_V`，构造噪声 latent，回归流目标 `C_V★ = ε_V − z_V0`：
```
L_V = w_V(t_V) · ‖Ĉ_V − C_V★‖²    (式7；仅在有效空间 token 上)
```
开 tube 时，洞内 token 额外加权 `λ_mask`（式8）；out-of-frame / 合成边界区始终用 border masking 排除。

## 3. 事件中心的动作动态建模

动作塔是与视频塔等深的 action DiT。共享 MLP 编码器 `E_a` 把*本体状态*与*噪声动作*都嵌入到 transformer 宽度，得到 `Ts + Ta` 个 token（Ts 个状态 token + Ta 个动作 token），过 `N_DiT` 个块，每块做：

(a) 动作 token 间自注意力 → (b) 对*状态 token 单独*的跨注意力（让绝对本体感知在每一层都直接可达，不被长视频 K/V 稀释）→ (c) 对*配对视频 DiT 层*特征的跨注意力 → (d) 门控 FFN；最后 MLP 头解回动作。

```
h̃_V_i = ViewConcat(h_V_π(i)) + E_τ(τ_V) + E_abs(t_abs),   等深时 π(i)=i   (式9)
```
`ViewConcat` 把该层 Nv 个逐视图 token 序列沿序列轴拼接作为 K/V。**耦合仍是单向。**

### 3.1 两种窗口布局
- **事件中心窗口**（事件预训练用）：每个事件字幕已定位片段，**禁用 E_abs**，给每个 token 一个整数帧索引 τ；状态 token 与第 0 个 latent 帧共享 τ=0，动作 token 按 `Ta/Kp` 组对齐后续未来 latent（式10）。
- **观测中心窗口**（统一部署用）：在全局指令下滑动定长窗口，单靠 τ 无法区分是哪个 chunk。扩展为 M 个历史帧 + 1 个观测锚 + N 个未来帧，**同时启用** `E_τ`（窗口内索引 −M..0..+N）和 `E_abs`（标记当前是哪个滑窗）（式11）。一次 3D VAE 编码把 `1+4M+4N` 原始帧压成 `1+M+N` 个 latent，历史与未来之间无重编码缝。

### 3.2 视频-动作时步映射（核心训练设计）
动作每步要跨注意力读某个视频去噪步。`m(j)` 把动作步 j 映到它读取的视频步：
- **对称 1-to-1（验证用）**：`m(j)=j`（t_A=t_V），小数据端到端联合去噪、紧拟合。
- **非对称 1-to-Nd（默认，大规模）**：固定一个中等噪声锚 `s★`，广播给整个动作计划——`m(j)=s★ ∀j`。推理时每个去噪 pass 只把视频跑到 s★，动作完成全部 Nd 步、每步都读那一次锚定的视频前向。

```
m(j) = s★  ∀ j∈{0..Nd−1},   t_A_k ~ Φ_A,  k=1..K     (式12)
```

> **为何非对称？** 主配方视频塔冻结、动作监督来自真值。对称 1-to-1 不合适：高噪声视频特征不必匹配真值片段，而近乎干净的视频特征又保留太少结构无法指导控制。s★ 钉在"既保留可信视觉结构、又提供可用跨注意力证据"的平衡点。每个优化步：1 次视频前向 + K 次动作前向（K>1 仅是吞吐 trick，与 rollout 无关）。

### 3.3 动作目标
默认 v-prediction：`v_A★ = ε_A − a0`，加权 MSE（式13）。可选：
- **x-prediction**：直接输出干净动作（接触密集数据上、接触只占几帧时，v-prediction 在高噪声下对这些帧加权太轻，x-prediction 更稳）。
- **Type-II DCT 辅助**（式14）：在恢复轨迹上强调整体运动形状而非逐帧抖动，高噪声时按 `(1−t_A/T)²` 降权。
主配方用 v-prediction、`w_DCT=0`（默认关闭 x-prediction 与 DCT）。

## 4. 语言引导推理：Staircase 潜 CoT 解码

推理模块建在冻结 **Qwen3.5-9B/VL-9B** 上。给定多视角观测与指令，VLM 产出隐状态 `H_q`；用边界掩码取文本 token 投影到 DiT 条件空间 `c_ℓ = M_T(P_Q(H_q[m_txt]))`（式15），与图像 token 一起注入 WAM 跨注意力。

**Staircase 潜 CoT**：把推理建模为 Kc 个连续潜状态 `ŷ_{1:Kc}`，用耦合到冻结骨干的轻量 **MoT** 实现。在中继深度 `Nr` 切分 Transformer：
- 只有*第一个*潜位置走完低层，产出一个**共享的中继表示**，被所有推理位置复用；
- 其余潜状态在高层**并行**生成（各自独立的因果缓存更新）。

```
ŷ_{1:Kc} = F_stair(x; Nr)    (式17)
```
→ 把"串行推理"变成"深度并行潜 rollout"，避免为每个推理步重算低层视觉-语言特征。潜状态完全可微，直接注入 WAM 跨注意力（不离散采样）。

**冻结潜→文本重建监督**：把 `ŷ_{1:Kc}` 经前缀投影 `P_pref` 投到一个*冻结*小模型（Qwen3.5-0.8B）的嵌入空间，让它自回归重建对应的文本 CoT 轨迹，损失 `L_CoT`（式19）。只训 Staircase 分支与前缀投影；逼潜状态编码紧凑高层语义而非复刻逐 token 轨迹。

---

## 5. 两种推理模式

- **事件模式**：在事件空间 rollout。VLM/人/agent 对当前观测提出"下一事件"描述，WALL-WM 执行对应的*变长*视频-动作片段，再观测下一状态——rollout 跟随每个任务阶段的*自然时长*而非固定控制视野。
- **统一模式**：Staircase 解码一次并行产出 Kc 个潜 CoT 状态，恰好插入 WAM 跨注意力中"原子指令条件"该在的位置，驱动传统定长 chunk，并保持梯度连续。

两种模式通过同一推理接口条件化同一个事件预训练骨干。

## 6. 数据生态（五条轴）

(i) 来源覆盖：通用互联网视频（OpenVID 1.2M 片段、HD-VILA）、第一视角人类视频（Ego4D、EPIC-KITCHENS）、非具身 UMI 式录制（自研 XRZero-G0 可穿戴 VR 跟踪夹爪，毫米级位姿，IK 重定向到部署机器人 URDF）、异构遥操作/开放机器人数据（DROID、AgiBot World、自采）。
(ii) 时间同步与后处理（训练-部署对齐）。
(iii) **四级字幕**：Task / Subtask / Action / Segment（外加可选人工层）。
(iv) **视觉-语言聚类 × 动作聚类**：均衡 dataloader、surfacing 长尾非标称轨迹。
(v) **定向恢复增强**：覆盖接触密集动作区与几何/遮挡难采区（失败-恢复/接管 episode）。

## 7. 基础设施

- **Muon 优化器（DMuon）**：Newton-Schulz 迭代在分片训练下开销大（朴素实现优化器步可达前反向之和的 2×）。DMuon 通过专属 owner 分配（约束 LPT）、reduce/broadcast 替代 all-reduce、异步广播与前向重叠、CuteDSL 对称 Gram 核，把优化器步降为次要成本。
- **自定义 kernel 库** + **CUDA Graph**。
- **部署压缩**：蒸馏（去噪步数量级下降）+ **FP8 量化**（per-block scaling，权重离线预打包、激活量化融进上游算子 epilogue，约 2× 吞吐）→ 端到端 **10Hz** 闭环。
