# Reflection · 反思、扩展与开放问题

## 如果我要扩展这篇论文

### 方向 1：自适应 patch size
当前 patch size 是全局固定（默认 256）。但论文自己指出小网格敏感、大网格不敏感，且分隔集质量随 patch 边界变化。可以做**空间自适应**：在网格曲率高/连通复杂的区域用细 patch（保留分隔集灵活性），在平坦区域用粗 patch（省时间）。甚至随递归深度调整——顶层粗、底层细。

### 方向 2：学习驱动的 trade-off 选择
"何时该放松、放松多少"目前是手工默认值。可以训练一个轻量模型，输入网格统计量（顶点数、平均度、各向异性、应用类型）和工作负载（预期求解次数），**预测最优 patch size / nd_level / 是否该用本方法 vs METIS**。本质是预测"盈亏平衡迭代数"并据此选策略。

### 方向 3：把更多阶段 GPU 化
目前只有 patching 在 GPU，Step 2–4 在 CPU。SuperSeparator（提升回原图）是瓶颈且高度数据并行，值得 GPU 化。完全 GPU 的重排能消除 CPU-GPU 数据往返，对 cuDSS 管线尤其有利。

### 方向 4：动态/增量重排
结合同作者的 Parth（复用 etree 加速稀疏模式变化时的重排）。当网格被局部编辑（重网格化、自适应细分）时，只重算受影响 patch 的商图局部，而非全部。把"一次性快速重排"升级为"增量快速重排"。

### 方向 5：超越三角网格
推广到四面体网格、混合网格、甚至非网格但有自然聚类的稀疏系统（电路、社交图）。核心问题：当没有廉价的 GPU patching 时，粗化成本会不会吃掉收益？

## 还有哪些开放问题

1. **质量损失的理论刻画**：放松约束导致的 fill-in 增加目前只有经验数字（6%–15%）。能否给出 patch size 与 fill-in 增量的理论界？这关系到能否安全地自动调参。

2. **盈亏平衡点的预测**：盈亏平衡迭代数（53 到 108859 不等）跨应用差异巨大，目前只能事后测量。能否事前预测？

3. **最优调度的自动选择**：post-order/level-order 之外，是否存在针对特定硬件/求解器的更优调度？这是个组合优化问题。

4. **与迭代法的边界**：对超大问题，迭代法（CG + 预条件）vs 直接法的取舍。本文加速了直接法的预处理，是否改变了"何时该用直接法"的判断？

5. **数值稳定性**：放松分隔集质量是否在某些病态系统上影响数值稳定性？论文聚焦性能，未深入。

## 哪些假设是脆弱的

| 假设 | 脆弱点 |
|------|--------|
| "重排占 86%" | 强依赖 cuDSS + RTX 3080。换更弱 GPU、更老求解器、或 CPU-only，占比骤降，方法优势缩水（MKL 上只有 1.76×）。 |
| "网格顶点 ↔ 矩阵行列一一对应" | 仅对特定 FEM 离散成立。高阶元、混合离散、约束系统（鞍点问题）会破坏这个对应。 |
| "patch 划分廉价" | 依赖 GPU 和 RXMesh。无 GPU 或非三角网格时不成立。 |
| "fill-in 增加是温和的" | 在某些各向异性/退化网格上，粗 patch 可能导致分隔集质量灾难性下降（论文未充分探讨极端情形）。 |
| "求解次数少" | 逆向渲染等场景违反此假设，方法反而变慢。 |
| "patch 连通" | 用户提供的 patch 若不连通，质量明显退化。 |

## 它可能在哪里失败（实践中）

1. **逆向渲染 / 大量重复求解**：作者明说的失败场景。固定矩阵解上千次右端项，fill-in 劣势累积反噬。

2. **小网格批处理**：如果管线是处理海量小网格（每个 < 5万顶点），逐个用本方法反而比 METIS 慢，且 GPU patching 的固定开销摊不开。

3. **CPU-only 部署**：没有 GPU 做 patching 时，patching 成本上升、且失去 cuDSS 这个最佳搭档，优势大减。

4. **病态/退化网格**：极度各向异性、自相交、或低质量三角化的网格，patch 划分质量差 → 分隔集差 → fill-in 可能失控。

5. **鞍点 / 不定系统**：本文针对 SPD + Cholesky。不定系统需要 LDLᵀ 或带主元的分解，重排的 trade-off 结构不同。

## 我从这篇论文学到的可迁移教训

1. **优化的最优点会随硬件移动**：一个十年前"值得"的高质量预处理，在 GPU 时代可能"不值得"。要定期重新审视流水线里的成本分布。

2. **领域结构是免费的杠杆**：当问题有强结构（网格邻接），用它做廉价压缩往往比通用算法的通用优化更划算。

3. **诚实地报告 trade-off 边界会让工作更可信**：本文明确给出盈亏平衡点和失败场景，反而增强了说服力。

4. **"在哪做"和"做什么"同等重要**：把重排与符号分析融合（复用 etree）的系统层洞察，价值不亚于算法本身。
