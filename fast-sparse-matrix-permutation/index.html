重排（permutation）是隐藏的瓶颈

论文核心动机：数值阶段被 cuDSS/MKL 优化到极致后，重排反而占了端到端的大头。拖动滑块改变网格规模，看四个阶段的占比变化（趋势基于论文 Figure 2：平均 86.6%，大网格达 96.7%）。
Permute（重排） Symbolic Numerical Factor Substitution
重排占端到端时间：86%
这一比例随规模上升 —— 网格越大，重排越主导。
论文实测区间（cuDSS，mean curvature flow）：
· 平均 86.6% · 最小 38.9%（小网格）· 最大 96.7%（大网格）
所以：优化重排 = 优化整个求解器。这正是本文要做的。

把网格压成商图，缩小分隔集搜索空间

论文核心手段：把 ~256 个网格顶点打包成一个 patch，整张图压成一张小得多的"商图"。分隔集计算是 NP-complete，对规模高度敏感——在小图上做便宜一个数量级。拖动滑块看压缩效果。
左：全矩阵图 G（每点一个顶点）　右：商图 q（每点一个 patch）
全矩阵图 G 节点数：1,000,000
商图 q 节点数：3,906
节点压缩比：256×
分隔集计算搜索空间（∝ 节点数）随之骤减。
关键优化：商图只建一次，递归时只擦除已选分隔 patch 的权重/边来复用——避免 METIS 每层重新粗化整张矩阵。

Patch size：速度 vs 填充质量的核心旋钮

patch 越大 → patch 越少、商图越小 → 越快，但分隔集被迫沿更粗的边界走 → fill-in 增加。数据来自论文 Figure 15 / 16（patch size 64/128/256，大网格 n≈1.8M，小网格 n≈300K）。
分隔集数量示意（patch 越小 → 分隔越精细 → 质量越好）
绿点 = 分隔集（沿 patch 边界）。对应论文 Figure 16：patch 越小，patch 数越多，分隔质量越高。
相对排序时间（归一化到 patch 256）：1.00×
填充比 nnz(L)/nnz(A)（越低越好）：7.0
大网格总排序时间：1.717s（METIS：10.272s）
小网格总排序时间：0.207s（METIS：1.418s）
论文默认 256：大网格对 patch size 不敏感（patch 仍够多，保留灵活性），是速度/质量的好折中。小网格更敏感，粗 patch 会过度约束分隔集。

盈亏平衡：放松质量何时反噬

本方法用更高 fill-in 换更快重排。单次/少量求解时净赚；但同一矩阵被反复求解上千次（如逆向渲染），fill-in 劣势会累积。拖动滑块改变"求解迭代次数"，看本方法 vs METIS 的累计时间谁更优。模型基于论文 Table 1 的盈亏平衡迭代数。

直觉：本方法重排省下一大块固定时间（初始优势），但每次数值阶段因 fill-in 略高而稍慢（斜率略大）。两线交点 = 盈亏平衡。
