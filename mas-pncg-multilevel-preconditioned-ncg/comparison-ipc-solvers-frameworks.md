## 0. 一句话定位每一篇

| 论文 | 一句话 | 攻击的层级 |
|---|---|---|
| **YASPS** | 用关系算子 JOIN/UNION 让 IPC 能量/参数化"可符号微分",避免混合参数化的组合爆炸 | **前端 / 编译器**(怎么把方程写出来) |
| **AGIPC** | 在 Newton 求解内部做自适应代数粗化(选择性边坍缩),减自由度而不破坏 barrier 的 C² 连续性 | **求解器内循环**(怎么把线性系统解小) |
| **MAS-PNCG** | 干脆跳过 Newton,用 MAS 预条件的非线性 CG,靠 Woodbury 增量维护预条件器 | **求解器外循环**(怎么换掉 Newton 本身) |
| **Tac2Real** | 把 PNCG-IPC 当物理内核,做高保真视触觉仿真 + 多 GPU 在线 RL + 零样本 sim-to-real | **应用 / 落地**(怎么用这套求解器) |

**核心观察:四篇基本是互补的——它们攻击 IPC 流水线的不同环节,而非互相竞争。**

## 1. IPC 流水线:谁动了哪一段

一个标准的 GPU IPC 时间步可以拆成五段。下表标出每篇论文"动"了哪段(●=核心改造,○=沿用/受益,—=不涉及):

```
   ① 定义能量/场景   ② 组装梯度/Hessian   ③ Newton 外循环   ④ 线性求解(内循环)   ⑤ CCD 线搜索
```

| 论文 | ① 定义 | ② 组装 | ③ Newton | ④ 线性求解 | ⑤ CCD |
|---|:--:|:--:|:--:|:--:|:--:|
| **YASPS** | ● 符号 IR | ● 自动生成 | ○ 仍用 | ○ GPU PCG | — |
| **AGIPC** | — | ● 粗化后重组 | ○ 仍用 | ● 减 DoF 加速 | ○ 无栈 BVH |
| **MAS-PNCG** | — | ✗ **不组装** | ● **替换为 PNCG** | ✗ **无线性求解** | ● 逐子域 CCCD |
| **Tac2Real** | ○ 调用 | ○ (PNCG 内) | ○ PNCG-IPC | ○ | ○ 无 CCD 线搜索 |

要点:
- **YASPS 动的是①②**:把"手写导数/装配"换成"符号微分 + JIT CUDA",但**仍然**跑 Newton + PCG(④用块 Jacobi 预条件的 GPU PCG)。
- **AGIPC 动的是②④**:在 Newton **内部**自适应坍缩边、减自由度,让线性求解更便宜。
- **MAS-PNCG 动的是③④⑤**:**整段砍掉** Newton 外循环和线性求解(PNCG 只需梯度),把省下的算力投到一个强预条件器上。
- **Tac2Real 全程是消费者**:它不改求解器,而是把 PNCG-IPC 当黑箱物理内核,叠加触觉表征 + 并行 + sim-to-real 对齐。

## 2. 主对照表(13 维)

| 维度 | YASPS | AGIPC | MAS-PNCG | Tac2Real |
|---|---|---|---|---|
| **层级** | 前端/编译器 | 求解器内循环 | 求解器外循环 | 应用/系统 |
| **核心技术** | JOIN/UNION 关系算子 + 符号微分 | 自适应代数粗化(边坍缩)+ 仿射嵌入 | Woodbury 增量 MAS 预条件 + 2D 子空间 + CCCD | PNCG-IPC 内核 + 标记点位移场 + TacAlign |
| **求解范式** | Newton-PCG | Newton-PCG(减 DoF) | **非线性 CG(无 Newton)** | 非线性 CG(PNCG-IPC) |
| **组装 Hessian?** | 是(自动生成) | 是(粗化后) | **否** | 否(PNCG) |
| **解线性系统?** | 是(GPU PCG) | 是(粗化后更小) | **否** | 否 |
| **预条件器** | 块 Jacobi | (多重网格式粗化) | **MAS,Woodbury 增量维护** | 对角(PNCG-IPC) |
| **它消除/替代的** | 手写导数与装配代码;参数化组合爆炸 | Newton 解中的冗余自由度 | Hessian 组装 + 线性求解 + 启发式 β + 全局 CCD | 渲染逼真触觉图像;sim-to-real 差距 |
| **主打目标** | **可扩展性**(为主)+ 性能 | **性能**(减 DoF 加速) | **性能 + 鲁棒性** | **可迁移性 + 吞吐** |
| **代表加速** | 总时间 ↓(130 vs 199 s)* | 最高 **3.30×**(刚性球)* | 最高 **5.66×** vs GIPC / **2.07×** vs StiffGIPC* | **4465 FPS**;真机 **91.7%*** |
| **基线** | GIPC / Stark | 全分辨率 IPC(自身) | GIPC / StiffGIPC | TacSL / Tacchi / 无触觉 |
| **材料/能量** | 任意(用户符号定义) | 弹性体(刚性/大变形) | ARAP / SNH / Baraff-Witkin | 弹性体(GelSight gel) |
| **GPU 策略** | JIT 模块化 CUDA(.o 链接) | Warp 哈希聚合 + 无栈 BVH | GPU 并行的梯度/点积/Woodbury | Ray 多节点多 GPU |
| **代码/实现** | Python 前端 + CUDA 后端 | 全 GPU(Warp) | GPU 求解器 | Taichi(PNCG)+ Isaac Lab + Ray |

> *⚠️ **加速数字不可直接横比**:四篇用 **不同基线、不同场景、不同硬件、不同度量**(YASPS 是端到端总时间、AGIPC/MAS-PNCG 是相对自身基线的倍数、Tac2Real 是 FPS 与成功率)。表中只为说明各自"在自己设定下的收益量级",不构成"谁更快"的结论。

## 3. 同一个矛盾,四种回答

四篇其实都在回应 IPC 的**同一个根本张力:鲁棒(barrier)很贵 → 怎么变快**。但它们选了不同的下手点:

| 论文 | 它认为瓶颈是…… | 它的解法隐喻 |
|---|---|---|
| YASPS | "**写方程**太贵"——手写导数/装配 + 参数化组合爆炸 | 给 IPC 配一个**编译器**:你声明,它生成 |
| AGIPC | "**自由度**太多"——很多区域其实可以粗化 | 在求解中**动态抽稀**:该细的细,该粗的粗 |
| MAS-PNCG | "**Newton 本身**太贵"——组装 + 线性求解 | **换掉 Newton**:用更便宜的迭代 + 更强的预条件 |
| Tac2Real | "**仿真→真机**断链"——快/准/可迁移三难 | **不改求解器,改用法**:选对表征 + 系统消差 |

## 4. 它们能"叠"起来吗?(互补性矩阵)

这是这张对照表最有价值的部分——它们大多**可以组合**,因为动的是不同环节:

| 组合 | 是否互补 | 说明 |
|---|:--:|---|
| YASPS **+** MAS-PNCG | ✅ 强互补 | YASPS 负责"自动写出能量/梯度",MAS-PNCG 负责"高效解出来"。一个管①②,一个管③④⑤。理论上 YASPS 生成的符号梯度可直接喂给 PNCG(PNCG 只要梯度!)——**这是最自然的一对**。 |
| YASPS **+** AGIPC | ✅ 互补 | YASPS 管前端可扩展,AGIPC 管 Newton 内循环减 DoF。都保留 Newton-PCG 范式,拼接顺滑。 |
| AGIPC **+** MAS-PNCG | ⚠️ 部分冲突 | 都在求解器层,但**范式不同**:AGIPC 优化 Newton 内循环,MAS-PNCG 干脆不用 Newton。不能简单叠加;但"自适应粗化"的思想或可移植进 MAS 的子域构造。 |
| Tac2Real **+** MAS-PNCG | ✅ 直接受益 | Tac2Real 的物理内核就是 PNCG-IPC。把内核换成 MAS-PNCG,触觉仿真可直接获得更快收敛 + 跨刚度鲁棒性。**Xing Shen 是两篇共同作者**,这条线最现实。 |
| Tac2Real **+** YASPS | ✅ 互补 | YASPS 的符号框架可让 Tac2Real 更容易加新传感器/材料参数化(触觉 gel、被抓物体)。 |

**一句话:理想的"全栈 IPC"可能是 —— YASPS 写方程 → AGIPC 或 MAS-PNCG 解方程 → Tac2Real 式应用消费,且全程多 GPU。**

- **Kemeng Huang** 出现在 3 篇(YASPS、AGIPC、MAS-PNCG)——是这个 IPC 求解器簇的关键纽带,也是 GIPC/StiffGIPC 的作者(各篇的对照基线)。

## 6. 选型速查:什么时候想到哪一篇

| 你的处境 | 该看哪篇 |
|---|---|
| 我要给 IPC 加一种**新材料/新参数化**,但不想手写一堆导数/装配代码 | **YASPS** |
| 我的场景**自由度巨大**但很多区域变形平缓,想自适应减 DoF | **AGIPC** |
| 我的瓶颈在 **Hessian 组装 + 线性求解**,且场景**接触密集、刚度跨度大** | **MAS-PNCG** |
| 我要把触觉/接触仿真**用于 RL 并上真机**,愁的是吞吐与 sim-to-real | **Tac2Real** |
| 接触简单、刚度均匀、要二次收敛 | 都不一定划算 → 老老实实 Newton(MAS-PNCG 的 Armadillo 仅 1.03×) |

```

        └──────────────────────────────────────────────────────────┘
            ▲              ▲            ▲           ▲          ▲
            │              │            │           │          │
        ┌───┴───┐     ┌────┴────┐  ┌────┴──────────┴──────────┴───┐
        │ YASPS │     │  AGIPC  │  │          MAS-PNCG            │
        │符号IR │     │自适应粗化│  │ 跳过Newton:PNCG + MAS(Woodbury) │
        │避免爆炸│     │减DoF    │  │ + 2D子空间 + 逐子域CCCD       │
        └───────┘     └─────────┘  └───────────────┬──────────────┘
            可扩展        减自由度          换掉Newton │ 被消费
                                                      ▼
                                          ┌──────────────────────┐
                                          │      Tac2Real        │
```

## 附:关键数字备查(各自设定下,不可横比)

- **YASPS:** 端到端 130.2 s vs GIPC 199.06 s(39.6k 顶点);新增参数化 ~130 行 Python;PSD 投影 24×24→6×6(~44×)。
- **AGIPC:** 刚性球(E=10⁷)**3.30×**;多米诺(172K)**2.00×**;海豚穿漏斗 1.41×;粗化开销 <10ms;后粗化 CG ≤10 次。
- **MAS-PNCG:** vs GIPC 最高 **5.66×**(双 bunny 40K/160K),vs StiffGIPC 最高 **2.07×**;搜索方向 7.9s→0.39s;跨 **500× 刚度** 稳定收敛。
- **Tac2Real:** 16×RTX4090、4096 环境 **4465 FPS**(伪结构网格);真机插销零样本 **91.7%**(vs TacSL 15%)。
