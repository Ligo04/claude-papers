# 反思与延伸 — GPC

## 如果我要扩展这篇论文

### 方向 1：多模态 / 文本条件控制
论文明确把「文本条件」列为未来工作。自然的做法：在 Stage 2 的 GPT 上加文本 token 前缀（类似 text-to-motion 的 T5/CLIP 条件），或在 CoLA 的任务观测 `c` 里注入文本 embedding。挑战：文本语义与「物理可执行技能码」的对齐——需要 (文本, 运动) 配对数据，且要保证生成的技能仍可执行。

### 方向 2：人-物交互（HOI）
论文也承认只做了 locomotion。HOI 需要把**物体状态**纳入本体感知 `s_t` 与任务观测 `c`，且接触动力学更难。可能需要扩充 FSQ 词表（加入手部/接触技能）或引入接触感知的奖励。

### 方向 3：跨形态迁移（cross-morphology）
当前一套词表绑定一个角色骨架。能否学一个「与形态无关」的技能词表，让不同骨架/机器人共享？这会把 GPC 推向真正的「运动基础模型」。可借鉴 Won&Lee 的 body-shape 适配 + 形态编码。

### 方向 4：实时性与蒸馏
自回归采样比单次前向策略慢。可探索把生成控制器蒸馏成非自回归/并行解码版本（类似 NLP 的 speculative decoding 或 MaskGIT 式并行），以满足游戏级实时预算。

### 方向 5：Scaling law
论文用 600h。运动数据的 scaling law 是什么？token 词表、模型规模、数据量三者如何权衡？这是把「GPT for motion」做扎实的关键实证问题。

## 尚存的开放问题

1. **FSQ 隐式码本的语义结构**：`9^40` 网格里，相邻码是否对应相似技能？是否存在可解释的「技能维度」？论文未深入分析码空间几何。
2. **分组因子的最优性**：G=5 是经验甜点，但不同数据规模/角色下最优 G 是否变化？有无自适应分组？
3. **多样性 vs 精度的帕累托前沿**：G、top-p、SFT 权重都在调多样性与精度的平衡，缺一个统一的理论刻画。
4. **端到端 RL 的样本效率**：24× A100 的成本对多数团队是壁垒。能否用离线 RL / 模型基 RL 降低交互成本？
5. **失败模式分析**：0.02% 的失败案例是什么动作？高动态（后空翻类）是否是主要失败源？论文未给失败分布。
6. **CoLA 的能力上界**：<1% 参数能迁移多复杂的任务？当任务与预训练技能分布差异很大时（如全新技能），PEFT 是否够用，还是必须全量微调？

## 脆弱的假设（Fragile Assumptions）

1. **「预训练数据覆盖了下游所需技能」**：CoLA 本质是**重新组合已有技能**。若下游任务需要预训练中根本没有的技能，PEFT 会力不从心——这时 GPC 退化为需要重训。
2. **「跟踪奖励足够定义好技能」**：整个词表由跟踪奖励塑造。跟踪奖励难以捕捉的品质（如风格、意图、能耗最优）不会自动进入词表。
3. **「离散化不损失关键动态信息」**：FSQ 是有损压缩。对极高动态、需要精细连续调节的技能（如平衡在刀刃上的动作），离散网格分辨率可能不足——MLP 基线 MPJPE 更低正暗示量化有精度代价。
4. **「无条件生成模型引导采样能保住自然性」**：这依赖预训练分布本身自然。若预训练数据有偏（如缺少某类恢复），引导采样也无法凭空造出。
5. **「Isaac Gym 的仿真 = 真实物理」**：全在仿真中训练/评估，sim-to-real gap 未讨论（这对机器人应用是关键，对纯动画则无所谓）。

## 它在实践中可能哪里失效

- **新奇技能的下游任务**：需要词表外技能时，CoLA 不够，需回炉重训 Stage 1。
- **实时高帧率场景**：自回归 + 物理仿真的延迟可能超预算（虽然论文说单 4090 可跑，但未给具体 FPS/延迟数）。
- **极高动态 + 精细控制并存**：离散化的精度天花板（vs MLP）在这类任务上会暴露。
- **小数据 / 单一角色**：GPC 的优势在规模；在小数据上，简单的 DeepMimic + MLP 可能更省事且精度更高。
- **需要确定性 / 可复现行为的应用**：GPC 的随机采样带来多样性，但也意味着同输入不同输出——某些工业管线需要确定性，需固定种子或降 top-p。

- **[[paper-stable-pd-controllers]]**：GPC 解码器输出正是 PD 目标关节旋转；SPD（Stable PD）可作为其底层执行器的稳定化改进，是天然互补的一层。
- **[[paper-flash-gpu-deformable-simulation]]** / **[[paper-silr-cloth-simulator-in-the-loop]]**：都属「GPU 原生大规模仿真 + 学习控制」的大方向；GPC 是刚体角色版，FLASH/SILR 是可形变体版，可对比「离散技能 token」与「连续仿真回路」两种控制哲学。
- **[[paper-magicsim-executable-embodied-interaction]]** / **[[paper-embodied-r1-5-foundation-model]]**：同样在追「具身基础模型」；GPC 提供了「运动层的 tokenized 基础模型」，可作为这类高层规划模型的低层执行器（高层出意图/文本 → GPC 出可执行技能）。

## 一句话反思

GPC 最有价值的不是任何单个组件（FSQ、GPT、DoRA 都是现成的），而是**证明了「基础模型三段式」（预训练 tokenizer → 生成式建模 → PEFT 迁移）在物理控制上能干净跑通并规模化**。它的脆弱点也正来自这个范式的前提：**下游只是预训练技能的重组**。当这个前提成立时它极其强大；当需要真正的新技能时，它就退回到「重训」。这与今天大语言模型「能力边界 = 预训练分布」的处境如出一辙。
