# Reflection — 反思与扩展

## 1. 如果我要扩展这篇论文（Extensions）

### 方向 A：大规模多任务 steering 基座
作者已明示。把 DROID [44] / Open-X 规模的多任务真实数据训一个巨型 flow/VLA 基座，其支撑集覆盖极广，再针对具体任务在仿真里 steer。预期：单任务提升上限被大幅抬高，且跨任务模式复用带来涌现式泛化。挑战：巨型 flow 策略的隐空间 steering 是否仍稳定？z 的维度与语义结构如何影响 steering 难度？

### 方向 B：为"可 steer 性"设计数据与预训练
现有 flow 训练目标（Eq.4）只优化"复现数据分布"，并不显式优化"支撑集覆盖度"或"隐空间可控性"。可否设计一个**鼓励行为多样性/模式可分离**的预训练目标，让 steering 更容易挑到最优模式？例如在隐空间加结构约束，让不同模式对应可分离的 z 区域。

### 方向 C：自动化"人工失败"课程
当前失败注入是手工设计的。可否用一个**对抗性/好奇心驱动**的扰动策略，自动生成最有信息量的失败态，动态维持恢复行为？把它做成一个 min-max 课程（扰动者 vs steering 者）。

### 方向 D：主动扩展支撑集
SCORE 的天花板是覆盖度。能否在仿真里让 steering 策略**主动请求**新演示（active learning）——当它探测到"需要一个 base 不支持的动作"时，触发一次真机/遥操作采集来扩集？把"离域提升"和"最小真机数据采集"闭环起来。

### 方向 E：软/硬约束的自适应调度
RFS 残差幅度 a_r 现为固定旋钮。可否让它**状态相关且可学习**——高置信区域收紧（趋近 DSRL 硬约束保迁移），需要精修的接触瞬间放松（趋近 Residual-RL 求精度）？

## 2. 仍然开放的问题（Open Problems）

1. **支撑集覆盖度如何度量与预测？** 论文定性说"覆盖度 > 最优性"，但没有可计算的覆盖度指标来**事前预测** SCORE 在某任务上的提升上限。缺一个"给定 base + 任务，SCORE 能提升多少"的理论界（附录 E 给了些假设，但离可操作指标还远）。
2. **感知偏移的严格处理。** 全篇假设"充分视觉随机化下感知偏移最小"，distractor 实验已暴露其脆弱。感知层的 sim-real gap 如何与动作层的支撑集约束联合处理？
3. **z→a 映射的多对一/不连续性。** flow 的 z→a 映射可能高度非线性、甚至局部不连续，steering 策略在 z 空间做 PPO 的 landscape 有多崎岖？何时会陷入 z 空间的坏局部最优？
4. **软约束的迁移保证边界。** RFS 加残差破坏了严格支撑集约束，论文只在 Appendix E 做形式讨论。a_r 多大就"越界"、迁移保证何时失效，缺乏可验证的判据。

## 3. 脆弱的假设（Fragile Assumptions）

| 假设 | 为何脆弱 | 失效后果 |
|------|---------|---------|
| "充分视觉随机化 ⇒ 两域感知偏移最小" | 真实 distractor / 光照 / 遮挡难被随机化覆盖 | steering 无法探索，仅部分工作空间成功 |
| "仿真接触动力学足够可用" | 灵巧多指接触极难仿真，LEAP 手接触模型误差大 | 支撑集内挑出的"最优模式"在真机仍可能失效 |
| "base 支撑集包含足够好的模式" | 若演示全是次优，支撑集里没有好模式 | SCORE 无从放大，提升为零（cup→carrot 案例） |
| "z 空间 steering 的 landscape 可优化" | 高维非线性映射，PPO 未必稳定 | 样本效率/收敛不保证，依赖非对称 critic 兜底 |
| "一套超参跑所有任务" | 8 个任务同构性较高（同臂同手同工作台） | 迁移到差异更大的任务族时未必成立 |

## 4. 它在实践中可能在哪失效（Where it might fail）

- **需要全新技能的任务**：base 支撑集里没有的动作模式（如需要工具使用、双手协调而演示里没有），SCORE 无能为力。
- **强 OOD 部署**：post-training 环境显著偏离预训练分布时（论文自述），提升受限。
- **难仿真的接触**：软体、可变形物体、流体等仿真保真度差的场景，"仿真里的最优模式"可能是仿真伪影。
- **视觉主导的失败**：当失败源于感知（认错物体）而非动作（动作不够好），动作层的支撑集约束帮不上忙——distractor 实验正是此类。
- **base 极弱**：若 base 成功率接近 0、支撑集几乎不含成功模式，SCORE 没有可放大的信号（它是"放大器"不是"发生器"）。

## 5. 我的批判性评价（Critical Take）

**最漂亮的地方**：把一个原本需要复杂机制（判别器、保守 Q、多轮真实交互）的约束，通过"只在 flow 噪声空间做 RL"这个动作结构**免费**实现——这是真正的"用架构换算法复杂度"的优雅。support vs distribution 的概念区分也讲得干净、可证伪（Fig.2 玩具例子 + Fig.6 权衡曲线 + cup/carrot 对照）。

**需要保留的怀疑**：
1. "免 reward engineering"被反复强调，但仿真构建、域随机化、人工失败注入的工程量被淡化了——复杂度是转移不是消失。
2. 提升完全受限于覆盖度，而覆盖度既无度量也无保证，实践中"SCORE 能否提升某任务"更像试出来的而非设计出来的。
3. 8 任务均为同一硬件平台、桌面级操作，任务多样性有限，"89.9%"的普适性需更广验证。
4. 与 RFS [12]（Su et al. 2026）高度重叠——SCORE 的算法内核基本是"把 DSRL/RFS 从真机搬到仿真 + 非对称 critic + 失败注入"，其**新颖性更多在框架定位（off-domain improvement 的形式化 + 支撑集视角）而非算法本身**。这不贬低其价值，但读者应清楚创新的具体落点。

**一句话总结**：一个概念清晰、工程扎实、定位精准的"提升器"范式——它最大的贡献可能不是 SCORE 这个算法，而是把机器人预训练的目标函数从"最强零样本"重新校准为"最广可 steer 先验"这一**范式主张**。
