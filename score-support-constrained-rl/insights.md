# Insights — SCORE（最重要的一份）

## 1. 核心思想，用大白话讲

想象你有一个"菜谱库"（真实数据训出来的基座策略）。这个库里对同一道菜（同一个观测 o）记录了**很多种做法**（多模态动作分布）——有的快有的慢，有的精准有的马虎。传统做法有两种：

- **无约束 RL**：扔掉菜谱，自己在"仿真厨房"里乱试。仿真厨房的物理规则和真厨房不一样（灶火更旺、锅不粘），你可能练出一套"在仿真厨房超好吃、真厨房直接糊锅"的做法。
- **分布约束 RL**：要求你的新做法"整体上要像菜谱的平均水平"。可菜谱平均水平本来就慢、就马虎，你被强行拽回平庸。

**SCORE 的做法**：不要求你"像菜谱平均"，只要求你"每一步动作都必须是菜谱里出现过的某种做法"。于是你可以专挑菜谱里**最快的那一版翻炒**、借用**另一条轨迹里最精准的那个装盘**，把它们组合放大——但绝不会凭空发明一个"真厨房做不到"的动作。这就是**支撑集约束**：约束的是"动作的可能集合（support）"，不是"动作的分布形状（distribution）"。

## 2. 为什么这样能行（Why it works）

### （a）分布约束的根本矛盾

分布约束 `D(π, π_base) < ε` 把"提升"和"迁移"耦合成一对不可兼得的量：
- ε 太大（约束松）→ 策略可以远离基座 → 提升空间大，**但会跑到基座没覆盖、仿真才有的动作上 → 不迁移**。
- ε 太小（约束紧）→ 策略贴着基座 → 迁移好，**但被基座的次优模式（慢、马虎）拖住 → 不提升**。

论文 Fig. 6 用 RialTo 把这条曲线画得很清楚：BC 系数从 10 到 100k 扫一遍，没有哪个值能同时拿到"高提升 + 高迁移"，最好的折中（10k）真机 60%，仍被 SCORE 的 100% 碾压。

### （b）支撑集约束把耦合解开了

支撑集约束 `supp(π) ⊆ supp(π_base)` 只管"动作在不在先验的可能集合里"，**不管概率质量怎么分配**。所以：
- **可迁移**：任何被执行的动作都是基座"能生成"的，即真实数据里出现过的模式，天然可迁移（不会是仿真臆造的动作）。
- **可提升**：在这个集合内，RL 可以**任意重新分配概率**——把慢模式的概率压到 0，把快模式的概率拉到 1。这正是分布约束做不到的（它必须保留基座的概率形状）。

一句话：**分布约束限制了"你能多大程度改变概率"，支撑集约束只限制"你能用哪些动作"，把改变概率的自由完全还给你。**

### （c）Flow steering 是支撑集约束的"免费午餐"实现

关键工程巧思：一个 flow matching 策略 `a = π_base(o, z)` 是一个从隐噪声 z 到动作 a 的**确定性映射**（给定 o）。它能生成的动作集合恰好是 `A_base(o) = {π_base(o, z) | z ∈ Z}`。

于是——**只要我只调 z（而不改 flow 网络本身），无论 steering 策略把 z 分布搞成什么样，输出动作永远落在 A_base(o) 内**。支撑集约束不需要判别器、不需要改 Q 值、不需要额外正则项，它是"只在噪声空间上做 RL"这个动作结构**自动保证**的。这就是为什么 SCORE 能"极简"——它把一个原本需要复杂机制（offline RL 里的 discriminator / 保守 Q）的约束，变成了一个**参数化选择**。

## 3. 它引入了什么概念转变（Conceptual Shift）

| 旧范式 | SCORE 的新范式 |
|--------|---------------|
| 仿真用来**从零训练一个新专家**（再蒸馏回真机） | 仿真用来**提升一个已有的真实先验**（直接复用） |
| 约束**分布**（KL / JS / Wasserstein 到 base） | 约束**支撑集**（动作 ∈ base 可生成集合） |
| 需要蒸馏 / 真机微调 / 改基座 | **冻结基座、免蒸馏、免真机微调** |
| 数据目标 = 训出"最强的零样本策略" | 数据目标 = 提供"最广的行为先验"（覆盖度 > 最优性） |
| reward shaping 反复调 | **稀疏奖励 + 一套超参**跑所有任务 |

最深刻的转变是最后一条对**数据价值观**的重估：传统认为"更好的演示 = 更好的策略"，SCORE 说"**更多样的演示 = 更大的提升空间**"，哪怕那些演示本身是失败的（retry）或次优的（play）。因为在支撑集框架下，一条"失败后恢复"的轨迹不改善基座的平均表现，却给 RL 提供了一个"恢复动作"选项，让它在仿真里学会稳定触发这个选项。

## 4. 权衡（Trade-offs）

- **DSRL（硬约束） vs RFS（软约束）**：DSRL 严格落在 A_base(o) 内，最安全但精度受限于基座能生成的离散动作集；RFS 加小残差 a_r 做局部精修，牺牲一点"纯支撑集"的严格性换灵巧操作需要的精度。SCORE 选 RFS，说明**在实践中"软一点"的精修价值 > 严格支撑集的理论纯洁性**。
- **提升上限 = 支撑集覆盖度**：SCORE 只能在 base 支持的动作里挑，**base 做不到的动作它也变不出来**。这是它安全性的来源，也是它的天花板。跨物体实验证实：先验里"偶尔有捏取"→能放大成功（22%→67%）；先验里"根本没捏取"（cup）→彻底失败。
- **仿真设计成本仍在**：虽免了 reward shaping，但要从真实扫描构建仿真环境、做域随机化、加人工失败——工程量转移了而非消失。
- **感知鲁棒性是隐性前提**：论文假设"充分视觉随机化下两域感知偏移最小"。distractor 实验暴露：当 base 无法区分物体时，steer 也难在新设定下探索（只在半个工作空间成功）。

## 5. 局限（Limitations，作者自述 + 推断）

1. **OOD 环境提升有限**：post-training 环境显著偏离预训练分布时 SCORE 失效——它擅长"放大已有能力"，不擅长"获得新能力"。
2. **受限于先验广度**：扩展到更多样设定需要更强更广的行为先验；作者猜测 SCORE 在**大规模多任务**设定下会大幅受益。
3. **感知/视觉鲁棒性**：distractor 场景暴露视觉泛化短板。
4. **恢复行为遗忘**：一旦仿真里学会稳定首次成功，就很少访问失败态，会遗忘恢复行为——需人工失败注入来对抗（这本身是个补丁）。

## 6. 与先前工作的比较（Comparison to Prior Work）

- **vs BC 正则 / RialTo [3]**：同为 real-to-sim-to-real，但 RialTo 用 forward-KL 分布约束，落入提升-迁移权衡；SCORE 用支撑集约束避开。
- **vs Residual-RL（bounded residual ≈ Wasserstein-1）**：Residual-RL 只能在 base 选定动作附近局部扰动，无法切换到 base 的"另一个更快模式"；SCORE 能在整个支撑集内重选模式，故速度提升近乎翻倍（36.8% vs 19.0%）。
- **vs ExpertGen [24]**：ExpertGen 从**仿真里生成**的行为先验出发训练 state-based 策略再蒸馏部署；SCORE 从**真实数据**先验出发、直接复用、免蒸馏。角色不同：ExpertGen 是"造新专家"，SCORE 是"提升现有真实先验"。
- **vs offline RL 的支撑集约束 [11,31,32,33]**：思想同源（限制到数据支撑集内以防 value 外推错误），但那些方法常需 discriminator / 保守 Q / 多轮真实交互，超参多、不稳定；SCORE 用 flow steering 在**大规模并行在线仿真**里优雅实现同一约束。
- **vs FPO [9]（无约束 flow RL）**：直接印证"无约束→reward hacking→真机崩"的失败模式。

## 7. 实践启示（Practical Implications）

- 如果你已有一个**能用但不够好**的真机生成式策略（diffusion / flow），SCORE 提供了一条**低风险、免真机代价**的提升路径：搭个仿真、冻结策略、只训 steering。
- **数据采集策略应改变**：不要只追求"完美演示"，主动混入 retry / play / 多任务数据来扩大支撑集——它们对 SCORE 是宝藏（对传统 IL 是噪声）。
- **flow / diffusion 策略的隐空间是一个被低估的"控制旋钮"**：不必改网络权重，只在噪声上做 RL 就能安全地重塑行为。这对已部署、不敢重训的大策略尤其有吸引力。
