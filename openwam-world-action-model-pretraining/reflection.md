# 反思：如果要接着做

## 一、如果我要扩展这篇论文

### 立刻能做且论文明确留了口子的

1. **补上 LIBERO-Plus 的因果验证**。论文对掉队给了数据 + 架构双重归因，论证链合理但**没做直接控制实验**。最干净的补充实验：在现有混合里逐步加入多样单臂数据（视角/背景/光照变化），看 camera 与 noise 分项能否恢复。这直接检验 Takeaway 1 是不是因果。

2. **原生带时间压缩的表征式编码器**。这是论文点名的方向。现在 DINOv3 / V-JEPA 的 4× 时间压缩是"每 4 帧特征取平均"硬压的，而 Wan2.2-VAE 的时间压缩是学出来的——那 0.12 点的差距和 4 帧平均的粗糙一致。做一个原生时序压缩的表征编码器，理论上能同时拿到语义鲁棒性和紧凑性，正好对上 Takeaway 2 的诉求。

3. **软路由 MoE 与 tokenization 阶段早期融合**。论文承认六个变体只探索了跨模态注意力和硬路由 MoE，并明确建议借鉴 UMM 社区经验。有意思的是 Single-System MoE（硬路由）平均 84.63 **还低于** Vanilla 的 85.50——硬路由在这个规模下没起作用。软路由值得一试。

4. **UMI 式数据的共训消融**。论文说没包含 UMI / DexUMI 数据，并推测这类"有机器人可执行动作 + 场景任务多样"的数据可能是更数据高效的路径。这是一个可以直接做的三方对照：ego + robot vs ego + robot + UMI vs robot + UMI。

### 需要更多思考的

5. **把 VLA 和 WAM 的优势区拼起来**。Takeaway 3 说两者各有优势区且都能被数据补偿，并把"结合两者"列为值得追的方向，但没给具体设计。一个自然的想法：让视频预测在训练时作为辅助任务（拿 WAM 的 ID 优势），但推理时完全不跑视频流（避免 WAM 的 OOD 误差累积）——本质上是"训练时是 WAM，推理时是 VLA"。论文的加速栈里已经有"跳过 VAE 解码"，往前推一步就是"跳过整个视频流的前向"。**但这会破坏 mutual 掩码建立的双向交换**，所以需要重新设计信息流。

6. **预训练规模下重做 Finding 1 和 Finding 2**。Finding 3 已经证明了"偏好会随预训练翻转"（Mutual 的符号变了）。那么在小规模受控实验里得出的其他结论——编码器选择、架构族系、去噪调度——是否也会翻转？论文只回头验证了信息流掩码这一个。**这是论文自身方法论逻辑指向但没做完的事**。

7. **post-training 阶段**。论文明确说只覆盖预训练，post-training 与适配的配方和机制仍开放。特别是：具身预训练买的是 OOD 泛化，那 post-training（RL 微调、迭代式数据收集）买的是什么？两者的收益是叠加还是重叠？

## 二、还剩什么开放问题

| 开放问题 | 现状 |
|---|---|
| 像素级预测的鲁棒性天花板能否绕过？ | 论文诊断出这是架构性限制，只能靠数据补偿或换表征，但两条路都没走通 |
| 长时程双臂任务（RoboDojo）为什么所有模型都很差？ | 最强也只有 19.34，OpenWAM-α 11.92。论文没有分析这个基准的失败模式 |
| 视频流的容量该占多少？ | 5B 世界流 + 1B 动作流的比例从何而来没有消融，只知道"要有专属动作容量" |
| λ_v / λ_a 的平衡 | 直接用 1.0 / 1.0，未消融。视频损失和动作损失的量级本就不同 |
| 时间步 warp ρ | 固定 5 且两流相同，未消融。既然两流可以独立采样，warp 也可以不同 |
| 桥接层该放几个？ | OpenWAM-α 用了全部 30 对层，但"哪些层的桥接真正重要"没有测 |
| 统一动作空间的 12 个保留位 | 语义未定义，靠具身自己声明。跨具身的保留位冲突怎么处理？ |
| 第一视角数据的最优占比 | 论文用 30.1%，来自"ego 与 synthetic 各占总帧 30%"的分配规则，不是搜出来的 |

## 三、哪些假设是脆弱的

1. **"训练覆盖整个噪声平面 ⇒ 任何调度都分布内"**。数学上对，但"分布内"不等于"密度足够"。独立均匀采样两个时间步，落在平面**角落**（一流极干净、另一流极噪声）的样本密度和落在对角线附近是一样的——但极端异步调度走的正是角落区域。所以"异步全败"可能部分来自角落区域的**有效样本量**而非机制本身。ρ=5 偏向高噪声的采样会进一步扭曲这个分布。

2. **RoboTwin2.0 单一基准支撑全部 Finding**。Section 4 的三组受控实验**全部**在 RoboTwin2.0（双臂）上做。而 Section 5 恰好显示 OpenWAM-α 在双臂/灵巧手强、单臂弱。那么"在双臂基准上选出的配方"对单臂是否同样最优？**Takeaway 1 自己就在说数据-基准匹配决定一切**，这个逻辑同样适用于配方的推导过程。

3. **"5 点差距只由 action-sees-video 决定"的干净性**。Table 2 的分界确实非常干净，但 isolated（87.41）和 video-sees-action（87.63）几乎相同，action-sees-video（92.39）和 mutual（92.15）也几乎相同——**两个平台，中间没有过渡**。这种阶跃在真实实验里罕见，值得怀疑是否有别的因素（比如某种梯度路径的存在/不存在）在起作用，而不只是"动作能否读到世界特征"这个语义解释。

4. **同步推理的选择让延迟数字偏乐观**。全部评测用同步推理，执行会为推理停顿。170 ms/chunk 在"实时控制预算内"的说法成立，但这是**开了全部四项加速**（含牺牲精度的速度缓存）后的数字，而评测分数是否也在这个配置下取得的，论文没有明说。如果分数是在关闭速度缓存下取的，那么"170 ms + 表中分数"不能同时成立。

5. **基线比较很大程度是在比数据**。论文自己在 Takeaway 1/3 说了这一点，但分数表仍然按"谁高谁低"排列展示。当 Qwen-RobotManip 在 LIBERO-Plus 上 89.0 而 OpenWAM-α 69.2 时，这个 20 点差距有多少来自方法、多少来自数据，论文只对 OpenWAM-α 一侧做了归因。

## 四、实践中可能在哪里失效

| 场景 | 预期问题 | 依据 |
|---|---|---|
| **相机位置和标定与训练不同** | 显著退化 | LIBERO-Plus camera 分项只有 33.8，是全部扰动里最差的 |
| **图像有传感器噪声/压缩伪影** | 显著退化 | noise 分项 39.8，同样是像素级预测的软肋 |
| **需要长时程记忆的任务** | 大概率失败 | RoboDojo 11.92，且所有模型都差 |
| **具身与预训练混合差异很大的单臂平台** | 中度退化 | 单臂数据仅约 1,100 小时且视角固定 |
| **完全没见过的具身** | 反而还行 | Wuji 手 + Tianji 臂（9D + 21 DoF，预训练混合中不存在）上全面超过 π0.5——统一动作空间的槽位设计起了作用 |
| **需要看到生成视频做调试/监控** | 延迟大幅上升 | 加速栈默认跳过 VAE 视频解码；要看视频就得关掉这项 |
| **指令高度多样、几乎不重复** | 延迟上升 | prompt embedding 缓存失效，文本编码器回到每请求路径 |
| **算力受限的部署** | 需要重新权衡 | 170 ms 是 RTX 5090 + 全加速的数字；关掉编译/缓存后基线约 430 ms |

## 五、一个值得注意的元观察

这篇论文最有价值的部分可能不是任何单个 Finding，而是它**演示了一种在具身智能领域做实验的纪律**：

- 每个决策都在前一个决策创造的条件下检验（不是各自最优的超参列表）
- 明确把"接近的选择"推迟到有足够数据时再做（Finding 2 明确 defer 了 mutual vs 单向）
- 发现偏好翻转后回头重做实验，而不是掩盖不一致
- 在自己模型明显掉队的基准上做详细归因，而不是略过

在一个"刷榜"压力极大的领域，这套做法本身就是贡献。LIBERO-Plus 那一节——**用一整页解释自己为什么在某个基准上比 baseline 差 20 点**——是很多论文不会写的。
