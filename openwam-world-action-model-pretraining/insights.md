# OpenWAM 核心洞察

## 一、用大白话讲核心思想

想象你要教一个机器人做家务。你有两种"老师"：

1. **看视频学的老师**：看过海量互联网视频，知道"杯子被推会倒、水会流、布会皱"。它对世界怎么变化了如指掌，但它从来没有手，不知道该发什么关节指令。
2. **摇操作学的老师**：跟着人类遥操作数据学过，知道该发什么指令，但见过的场景少得可怜。

WAM 的想法是把第一个老师"改造"成第二个：拿视频生成模型当起点，往上接动作生成，让它在预测未来画面的同时预测动作。这不是新想法——DreamZero、Fast-WAM、LingBot-VA、Cosmos Policy 都在做。

**OpenWAM 的真正贡献不是又造了一个 WAM，而是把"WAM 到底哪个设计选择在起作用"这个问题变成了可以做实验回答的问题。**

现有 WAM 系统全是单体式的：你换个骨干，同时也换了编码器、注意力模式、数据配比、去噪调度。论文报告"我们比 baseline 高 3 点"，但没人知道这 3 点从哪来。OpenWAM 把这些耦合的选择拆成正交的模块（`C(E, S, M)` 三元组），配一套不感知架构内部的 trainer / server / 评测协议，然后**逐个变量做受控实验**。

这是把模型设计当经验科学做——Cambrian-1 对多模态、Physics of Language Models 对 LLM 做过的事，OpenWAM 对 WAM 做了一遍。

## 二、三个 Finding 的机制，以及为什么它们能成立

### Finding 1：继承什么 —— 骨干要强，隐空间要"紧凑且信息丰富"

骨干规模的结论平淡（1.3B→14B 单调涨，90.14→93.79），但**视觉表征的结论反直觉**。

原本的直觉是：重建式编码器（VAE）只学压缩不学语义，表征式编码器（DINOv3、V-JEPA）学到语义结构，后者应该更适合世界建模。实验第一轮打脸：DINOv3 裸用 76.42，V-JEPA 裸用 80.91，都不如 FLUX.2-VAE 的 84.26。

原因不在语义，在**维度**。现代 DiT 是为重建式编码器的低维隐变量（Wan2.2-VAE 是 48 维）优化的；DINOv3 输出 768 维、V-JEPA 输出 1024 维，直接塞进 DiT 是架构不兼容。加上 S-VAE 适配器压到 48 维后，DINOv3 跳到 90.18、V-JEPA 跳到 88.46，双双反超 FLUX.2-VAE，DINOv3 已经贴住 Wan2.2-VAE 的 90.30。

**概念转变**：判断一个隐空间适不适合 WAM，不该问它"来自重建目标还是表征目标"，而该问两个操作性质——
- **紧凑性**：时间维度（帧压缩）和 token 维度（通道数）都要压
- **世界信息丰富度**：压缩后还剩多少可用于预测动力学的信息

Wan2.2-VAE 剩下的那 0.12 点优势也被解释清楚了：它是原生匹配视频骨干架构的重建式编码器，且它的 4× 时间压缩是编码器**学出来的**，而其他三个是靠"每 4 帧特征取平均"硬压的。作者由此点出一个明确的研究方向：**做原生带时间压缩的表征式编码器**。

### Finding 2：怎么交互 —— 训练时要硬通路，推理时不要软门控

这个 Finding 由两个实验拼成，方向相反，正是它有意思的地方。

**训练时（硬掩码）**：分界干净得不像真实实验数据。
- 动作流看不到世界流（isolated 87.41、video-sees-action 87.63）→ 塌到 87 附近
- 动作流看到世界流（action-sees-video 92.39、mutual 92.15）→ 稳在 92 以上

约 5 点的鸿沟只由一个二值问题决定：**动作 token 能不能 attend 到视频 token**。反向通路（action→world）在 from-scratch 下只值 ±0.2 点。

**推理时（软门控）**：直觉说，既然 world→action 这么重要，那推理时让视频流先去噪干净、动作流后跟（video-lead），不就是给动作提供更清晰的世界信息吗？这就是 planning-then-IDM 的隐式版本。

实验结果：**16 种异步调度全部不如同步的 93.0**。两族参数化（variance-shift、linear-offset）、两个引领方向都试过，无一改善。有意思的是两族的方向偏好还相反——variance-shift 下 video-lead 好于 action-lead，linear-offset 下 action-lead 好于 video-lead——这种不一致本身就说明"引领哪条流"不是一个有真实机制的旋钮。

**为什么？** 论文的解释是这支持**表征学习假说**而非**测试时规划假说**：
- 规划假说说：WAM 之所以有效，是因为它在测试时先"想象"未来，再从想象中反推动作（IDM 式）。若如此，video-lead 应该有优势。
- 表征学习假说说：WAM 之所以有效，是因为视频预测这个**辅助任务**在训练时塑造了更好的表征。一旦表征学好了，测试时两条流应该在同一噪声水平上互相精炼，人为拉开它们只是偏离了训练分布的中心区域。

Table 1 里 IDM 变体只有 87.95（比 joint self-attn 低 4.4 点）也是同一结论的独立证据：显式的"先生成视频再反推动作"就是不如联合去噪。

**这里有个设计上的精巧之处**：因为训练时 t_v 和 t_a 独立采样，覆盖了整个二维噪声平面，所以**任何**推理调度（同步的对角线、异步的曲线）都是分布内的。同步只是 (α, o) = (1, 0) 的特例，不是单独的代码路径。这让"同步最优"成为一个干净的结论，而不是"异步调度碰上了分布外状态"的伪影。

### Finding 3：怎么扩展 —— 预训练买的是 OOD，不是 ID

600 小时等预算下的四组对照，数字讲得很直白：
- ID（Clean2Clean）：87.00 → 最好 88.50，增益 ≤ 1.5 点
- OOD（Clean2Random）：14.50 → 最好 26.62，增益 **+12.12 点**

**具身预训练贡献的主要是"能迁移到下游训练分布之外"的知识，而不是把一个已经饱和的 ID 基准拟合得更好。** 这对怎么花预训练预算是个很实际的指导：如果你的部署场景和微调数据分布一致，具身预训练的性价比不高；一旦要面对新场景、新物体、新光照，它就是决定性的。

两种数据源的分工也清楚：
- **机器人轨迹**：Robot-only 的 ID 最强（88.50）→ 提供**可执行的动作接地**
- **第一视角人类视频**：混合策略的 OOD 更好 → 提供**视觉与交互分布的广度**（它没有动作标签，动作与本体感通道全部掩掉，只监督世界流）

两阶段（ego→robot，OOD 26.50）和单阶段共训（26.62）几乎打平，说明**用不用两种数据比怎么排序重要得多**。共训微弱领先且省掉了课程切换，所以成为默认。

**最微妙的发现是信息流偏好的反转**：from-scratch 时 RoboTwin-Full 略微偏好单向（Mutual 比 action-sees-video 低 0.24 点），预训练后同一协议翻转为偏好 Mutual（+0.16），且在 C2R 的 ID（+0.70）和 OOD（+0.72）上都成立。

翻转发生在 ID 和 OOD 上幅度相当，这就排除了"域偏移伪影"和"评测协议伪影"两种解释，留下的是一个真实的机制：**预训练让世界–动作交互变成真正双向的交换**。预测的未来帧为动作生成提供视觉引导；预测的动作反过来告知那些帧中机械臂运动该怎么合成。数据稀缺时两条流建立不起这种对应，反向通路只是噪声；数据充足后缺口填上，Mutual 的优势才兑现。

**这是一个关于"架构选择依赖数据规模"的干净案例**。你在小规模受控实验里选出的最优架构，可能在预训练规模下就不是最优了。论文的处理方式很老实：Finding 2 明确写了"defer the close choice between one-way and mutual visibility to pretraining"，把这个决定推迟到有足够数据时再做。

## 三、Trade-off

| 维度 | 选择 | 代价 |
|---|---|---|
| 骨干规模 | 5B 而非 14B | 少 1.40 点性能，换约 3× 参数与训练/部署成本 |
| 编码器 | Wan2.2-VAE（像素重建） | 对视角/噪声扰动不鲁棒（LIBERO-Plus camera 33.8 / noise 39.8） |
| 架构 | Dual joint self-attn 而非 Tri | 少 0.24 点，换掉 VLM 骨干的复杂度与理解特征的混杂 |
| 预测目标 | 长时程像素级未来 | ID 拟合更好，但 OOD 误差累积更重 |
| 推理模式 | 全部评测用同步推理 | 执行会为推理延迟停顿，换"报告的是模型自身性能"的干净性 |
| 数据配比 | 第一视角 + 双臂 + 灵巧手为主 | 单臂覆盖薄（约 1,100 小时），LIBERO-Plus 因此掉队 |

## 四、局限

### 论文自己承认的（附录 A）

1. **只覆盖预训练阶段**：post-training 与适配方法（RL 微调、DAgger 式迭代等）对具身基座模型可能有显著提升，其经验配方与底层机制仍是开放问题。
2. **模态融合方式有限**：六个变体基本只探索了跨模态注意力和硬路由 MoE。作者建议借鉴统一多模态模型（UMM）社区的**tokenization 阶段早期融合**和**软路由 MoE**。
3. **数据缺 UMI 式采集**：UMI / DexUMI 这类手持式接口采集的数据，理论上能同时具备"人类第一视角的任务与场景多样性"和"机器人可执行的动作标签"，可能是通往具身智能更数据高效的路径。作者也期待仿真的突破——仿真能原生生成场景多样、运动真实的机器人数据，不受物理世界时间人力成本约束。
4. **视觉编码器是权衡而非最优解**：Wan2.2-VAE 是"当前可得的最佳折中"，而非最优。像素重建编码器对视角、噪声、场景变化不够鲁棒，"紧凑且携带充分环境信息"的隐表征仍待探索。

### 从结果读出来的额外局限

5. **像素级预测的鲁棒性天花板是架构性的**：Fast-WAM / ABot-M0.5 / OpenWAM-α 三个共享"Wan2.2-VAE 隐空间上的像素级未来视频"这一预测目标的模型，在 LIBERO-Plus 的 camera 与 noise 扰动上呈现相同的性能签名。只有 ABot-M0.5 靠 8,000+ 小时的单臂数据把损失补回来大半。**这意味着这不是一个能靠调参解决的问题，只能靠数据补偿或换表征。**
6. **RoboDojo 绝对分数极低**：OpenWAM-α 11.92，最强基线 19.34。这个基准上所有模型都很差，说明现有范式在长时程、需要记忆的双臂任务上离可用还很远。
7. **"最强 WAM"的措辞值得注意**：在 RoboTwin2.0-C2R（69.0 vs Qwen-RM 77.1）和 RoboDojo 上，OpenWAM-α 都只是"最强的 WAM"而非最强模型，最强的是 VLA。这个诚实的表述正好对应 Takeaway 3。

## 五、与前作的对比

| 维度 | 传统单体 WAM（DreamZero、Fast-WAM、LingBot-VA、Cosmos Policy） | OpenWAM |
|---|---|---|
| 定位 | 一个具体模型 + 一份实现 | 一套受控实验基础设施 + 一个由实验推导出的模型 |
| 设计选择 | 骨干/编码器/注意力/调度/数据紧耦合 | 因子化为 `C(E, S, M)` 正交模块，配置装配 |
| 结论可归因性 | "我们比 baseline 高 X 点"，来源不明 | 每个 Finding 对应一组单变量受控实验 |
| 训练/部署/评测 | 每个系统各自一套 | 一个 trainer、一个 policy server、一套 WebSocket 协议 |
| 跨具身 | 通常单具身或少数具身 | 80 维统一动作空间，21 种具身，8 个仿真基准 + 真机同接口 |
| 开放程度 | 部分开源 | 基础设施 + 评测协议 + 预训练权重 + 数据配方全开 |

对比开放生态类工作：OpenVLA 建立了开源权重基线，StarVLA 提供了模块化 VLA 平台，XPolicyLab 统一了评测部署。**这些都在 VLA 侧，WAM 侧此前几乎没有对应物**——OpenWAM 填的是这个空缺。

方法论上的同族工作：Cambrian-1 与 Beyond Language Modeling 系统研究视觉表征、模态容量、数据组成；Towards Physics of Multimodal Pretraining 隔离知识流动、协同与竞争、模态统一时机。OpenWAM 把这套"分解成受控变量 → 检验机制 → 推导配方 → 验证配方能否扛住规模"的方法论搬到 WAM 上。

## 六、实践含义

### 如果你要训一个 WAM

按论文的配方顺序做决定，每一步都在前一步的条件下：
1. **选骨干**：能承受的最大规模，但注意收益递减（5B → 14B 只值 1.40 点）
2. **选编码器**：紧凑（时间 + token 双维压缩）且信息丰富。表征式编码器可用，但**必须配降维适配器**
3. **给动作专属容量**：独立 ActionDiT，别指望参数共享自动产生协同（Single-System 只有 85.50）
4. **确保 world→action 通路**：这是 5 点的差距，不是可选项
5. **推理用同步去噪**：别设计花哨的异步调度，16 种都试过了
6. **预训练用 ego + robot 单阶段共训**：不用纠结顺序
7. **预训练规模下用 mutual 掩码**：小规模时用单向

### 如果你在评估一个具身基座模型

**Takeaway 1 是最有操作价值的一条**：模型在某基准上泛化得如何，最终由"预训练混合中是否含有接近该基准测试条件的数据"决定——具身与环境两方面都算。OpenWAM-α 在双臂/灵巧手基准上强、在单臂 LIBERO-Plus 上弱，就是数据配比的直接投影。

推论：看到一个模型在某基准上的分数，先去查它的预训练数据配比，再决定这个分数说明了什么。

### 如果你在 VLA 和 WAM 之间选

Takeaway 3 给了一个可操作的二分：
- **部署分布与训练分布接近** → WAM 的视频隐变量监督带来更好的 ID 拟合
- **要面对显著分布偏移** → VLA 不背长时程误差累积的负担，OOD 更稳

但更重要的是后半句：**两个缺口都能用足够大且多样的预训练数据补偿**。所以真正的建议是——先把数据搞对，再纠结范式。两者都是从观测到动作的端到端模型，如何结合两者互补优势是值得追的方向。

### 工程上可直接拿走的

- **80 维统一动作空间的槽位语义设计**：2 × 34 维镜像臂块（EEF 位置 3 + 6D 旋转 6 + 夹爪 1 + 灵巧手 24）+ 12 保留位。固定槽位语义让不同具身共享的结构落在同一坐标上，validity mask 保证未映射坐标不接收梯度、推理时留在解析噪声路径上。这个设计让"从未见过的具身"（Wuji 手 + Tianji 臂，9D + 21 DoF）也能微调上去并超过 π0.5。
- **自包含 checkpoint**：权重 + 完整重建规格 + 动作归一化统计三件套。部署时缺归一化记录直接硬报错。这消除了"评测时静默改了编码器/动作布局/缩放"这类最难查的实验污染。
- **推理加速栈**：prompt embedding 缓存 + 跳过 VAE 视频解码（控制只消费动作不消费像素）+ 固定形状 torch.compile + CUDA graph + DiT 速度缓存（余弦相似度稳定时跳过前向）。合起来 2.0–2.6× 加速，RTX 5090 上约 170 ms/chunk。
- **数据清洗协议**：视觉级（不可解码/冻结帧/纯色/过曝欠曝/闪烁/模糊/突跳）+ 信号级四步（信号完整性检查、state-first 空闲检测、视觉交叉验证、片段级删除）。特别值得抄的两条：**中段暂停绝不剪**（剪了会拼接时间上不相邻的帧）；**state 动但所有相机都静止 → 判为传感器抖动剪掉，机械臂真动但相机冻结 → 判为采集缺陷删整段**。
