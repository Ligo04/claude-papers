# OpenWAM 方法详解

## 一、组件拆解：`C(E, S, M)` 三元组

OpenWAM-Infra 把一个 WAM 表达为三类可互换模块加一条组合规则：

```
架构 = C( E , S , M )
        │   │   │
        │   │   └── 可见性注意力掩码：流之间/token 之间谁能 attend 谁
        │   └────── 流骨干集合：世界流 W、动作流 A、可选理解流 U
        └────────── 视觉编码器（始终冻结）：把观测映射成世界流要预测的隐序列
```

**关键设计约束**：组合规则 `C` **自身不带任何参数**，所有可学习容量都在流骨干里。`C` 只做三件事——排列各骨干的 `prepare` / 逐层 `block step` / `finalize` 阶段的执行顺序；当交互必须发生在注意力内部时，把 block step 拆成 pre-attention 半和 post-attention 半来替换注意力计算本身；**永不修改骨干内部**。

### E：视觉编码器（4 个 + 1 个适配器）

| 类别 | 编码器 | 原生隐维度 | 时间压缩 |
|---|---|---|---|
| 重建式 | Wan2.2-VAE | 48 | 4×（原生学习） |
| 重建式 | FLUX.2-VAE | — | 无（靠 4 帧平均硬压） |
| 表征式 | DINOv3 | 768 | 无（靠 4 帧平均硬压） |
| 表征式 | V-JEPA 2.1 | 1024 | 无（靠 4 帧平均硬压） |

**S-VAE 适配器**：把表征式编码器的高维特征压到 48 维（对齐 Wan2.2-VAE）。这是让表征式编码器可用的**必要**组件，不是可选优化——没它 DINOv3 只有 76.42，有它 90.18。

默认情况下视频骨干配原生匹配的编码器，此时基础 DiT 的预训练参数直接复用，完整保留预训练收益。换 E 时可选择把基础 DiT 重新随机初始化，以排除预训练参数的影响（4.1.2 的消融就是这么做的）。

### S：流骨干

**视频骨干 W**（5 个，参数递增）：Wan2.1-VACE-1.3B、Cosmos-Predict2.5-2B、Cosmos3-Edge-4B、Wan2.2-TI2V-5B、Wan2.1-I2V-14B

**动作骨干 A**（2 种形态）：
- 独立参数：单独的 ActionDiT
- 共享：动作 token 加入视频 token 序列，被同一 transformer 处理

**理解骨干 U**（可选）：目前仅支持 Qwen3-VL 系列，冻结，喂给一个独立可训练的理解流

**统一执行契约**（trainer 不感知架构内部的关键）：
```
prepare       # 栈前调用一次：把输入嵌入成初始 token 状态
block step    # 每层调用一次：把状态推进一个 transformer 层
  ├─ pre-attention   # 发出该层的 Q/K/V
  └─ post-attention  # 消费注意力输出
finalize      # 栈后调用一次：把最终状态映射为该流的预测
```
把 block step 劈成前后两半，使得**两半之间的注意力可以跨流联合计算**——这是 joint self-attention 的实现基础。

### M：可见性注意力掩码

掩码在视频/动作两个模态上因子化为 2×2 块：

```
        ┌                    ┐
   M =  │  M_V←V    M_V←A   │
        │  M_A←V    M_A←A   │
        └                    ┘
```

**两个模态内块固定**：
- `M_V←V`：**首帧因果**注意力。噪声帧之间互相可见、且都能看到干净首帧；干净首帧只看自己 → 保护干净条件不被噪声污染
- `M_A←A`：**双向**注意力。一个 chunk 内的噪声动作 token 互相可见 → 预测的动作彼此告知

**两个跨模态块给出 4 种模式**：

| 模式 | M_A←V | M_V←A | 含义 |
|---|---|---|---|
| isolated | ✗ | ✗ | 两模态独立去噪 |
| video-sees-action | ✗ | ✓ | 动作特征暴露给世界流 |
| action-sees-video | ✓ | ✗ | 世界特征暴露给动作流，视频生成不受干扰 |
| mutual | ✓ | ✓ | 双向 |

### 六个架构变体

```
Single-System（只有视频骨干，动作 token 注入视频序列，参数大部分共享）
├─ Vanilla   视频/动作/本体感 token 走同一注意力和同一 dense FFN，零模态专属容量
└─ MoE       保留共享序列与自注意力，但动作 token 硬路由到专属 FFN 专家
             代表系统：Cosmos Policy、DreamZero

Dual-System（独立视频骨干 + 独立 ActionDiT，两套参数）
├─ Joint self-attention   在指定桥接层把两流隐状态并成联合序列，双向 token 级交互后各自返回
├─ Joint cross-attention  动作流在桥接层通过 video→action 交叉注意力查询视频特征
│                         端到端训练时动作梯度会更新视频流；可选在视频特征处 detach 以隔离
└─ IDM                    动作模块建成逆动力学模型，以视频特征为条件
                          训练用 teacher-forced 视频状态，推理分两阶段：先生成视频轨迹再预测动作
             代表系统：Fast-WAM、LingBot-VA

Tri-System（在 dual 基础上加 VLM 骨干）
└─ Joint self-attention   联合序列扩展到三条流，各流保留专属参数
                          理解流作为只读尾部加入：其他流可以 attend 它，它只 attend 自己
             代表系统：Motus
```

## 二、训练：一个目标覆盖整个噪声平面

### 样本契约

```
sample = (ℓ, o_{1:T}, a_{1:H}, q, m)
          │   │        │        │  └── 逐维有效性掩码
          │   │        │        └───── 可选本体感状态
          │   │        └────────────── 动作 chunk
          │   └─────────────────────── 视频窗口
          └─────────────────────────── 语言指令
```

### 联合 flow matching 目标

约定 `t = 0` 为纯噪声、`t = 1` 为干净数据。两条流各自噪声到**独立采样**的时间步：

```
z_{t_v} = t_v · z + (1 − t_v) · ε_v     # 视频隐变量插值
a_{t_a} = t_a · a + (1 − t_a) · ε_a     # 动作 chunk 插值
```

**一次联合前向**同时预测两个速度：
```
(v̂_z, v̂_a) = v_θ(z_{t_v}, a_{t_a}, t_v, t_a, c)
```

损失（式 2）：
```
L = λ_v · E_{t_v, ε_v}[ w(t_v) · ‖ v̂_z − (z − ε_v) ‖²₂ ]
  + λ_a · E_{t_a, ε_a}[ w(t_a) · ‖ m ⊙ (v̂_a − (a − ε_a)) ‖²₂ ]
```

- `m ⊙` 把动作项限制到该具身实际填充的坐标上
- 干净条件帧从视频项中排除
- OpenWAM-α 用 `λ_v = λ_a = 1.0`，`w(·)` 为峰值在中等噪声的钟形权重

### 为什么"独立采样两个时间步"是整个设计的枢纽

因为 `t_v` 与 `t_a` 独立采样，训练**覆盖了整个 (t_v, t_a) 噪声平面**：

```
t_a (动作时间步)
 1 ┤ · · · · · · · · ·        训练样本散布在整个方形区域
   │ · · · · · · · · ·
   │ · · · ╱ ← 同步对角线（推理默认走这条）
   │ · · ╱· · · · · ·
   │ · ╱ · · · · · · ·        任何推理调度都是这个平面上的一条路径
 0 ┼─────────────────→        ⇒ 全部分布内
   0                 1  t_v
```

任何推理调度——不管是同步（对角线）还是异步（一条流领先）——都只是在这个平面上画一条路径，因此**始终分布内**。这带来两个直接后果：
1. 同步推理是 `(α, o) = (1, 0)` 的**特例**，不是单独代码路径；每个异步实验都有一个对齐的基线
2. "同步最优"成为一个干净结论，而不是"异步碰上了分布外状态"的伪影

此外，每条流的时间步 warp 是**存在 checkpoint 里的骨干属性**，推理时复用，所以训练与服务的噪声网格不可能漂移。

### 时间步采样（OpenWAM-α）

```
t_v = 1 − f_ρ(u_v),  t_a = 1 − f_ρ(u_a),   u_v, u_a ~ U[0,1],  ρ = 5
```
`f_ρ` 就是下面式(3) 的 variance-shift 曲线，同样施加到两条流，`ρ = 5` 使采样偏向高噪声。

### 训练工具

- **框架**：DeepSpeed ZeRO stage 1/2（经 Accelerate），bf16 默认，梯度累积，梯度裁剪，单入口从单卡扩到多节点
- **显存优化**：梯度检查点（可选把检查点激活 offload 到 CPU）、优化器状态 offload 到 CPU
- **三种工作流**：
  - `Pretraining`：全新开始
  - `Fine-tuning`：从 checkpoint 初始化新 run，架构按 checkpoint 自身记录重建，新配置叠加在上，**权重所属模块的身份受保护不被覆盖**
  - `Resume`：精确续跑，恢复完整优化器与调度器状态，从记录位置重入数据流；若数据集归一化统计与 run 记录的不一致则**拒绝继续**

### 自包含 checkpoint（三件套）

```
checkpoint = 模型权重
           + 完全解析的配置（每个模块的重建规格 + tokenizer 等 artifact 合并进来）
           + 动作归一化统计
```
Fine-tuning、resume、部署都先按这份记录重建架构再加载参数。部署时**缺归一化记录是硬错误**。这保证评测不可能静默改掉一个已训模型的编码器、动作布局或缩放。

## 三、部署：两个正交选择

### 推理模式

**同步**：buffer 空了就阻塞做一次新推理，执行为推理延迟停顿。

**异步**（记 `H` 为预测 chunk 长度，`n ≤ H` 为推理视野，`d < n` 为领先阈值，默认 `n/2`）：
```
buffer 剩 d 个动作时 → 后台 worker 预取下一 chunk，这 d 个继续执行
新 chunk 按序切成三段：
  ├─ 延迟前缀  d 个        推理期间已被上一 buffer 覆盖 → 跳过
  ├─ 执行窗口  接下来 n 个  成为新 buffer
  └─ 丢弃尾部  max{H−d−n, 0} 个
```
两种模式对客户端**不可区分**：每个请求都是一观测进、一动作出。

> ⚠️ OpenWAM-α 的**全部**基准评测（仿真与真机）都用**同步推理**，以最直接地反映模型自身性能。

### 去噪调度

调度是联合噪声平面上的一条路径 `τ = {(t_v^i, t_a^i)}_{i=0}^N`。

**sync**：两流沿对角线齐步走，每步一次联合前向 + 耦合 Euler 更新（各按自己的时间步增量移动）：
```
z_{t_v^{i+1}} = z_{t_v^i} + (t_v^{i+1} − t_v^i) · v̂_z
a_{t_a^{i+1}} = a_{t_a^i} + (t_a^{i+1} − t_a^i) · v̂_a
```

**异步两族**（式 3，`s = i/N` 为全局进度）：
```
variance shift:  f_α(s) = α·s / (1 + (α−1)·s)      α > 1 时领先流抬到对角线上方，更早到干净数据
linear offset:   h_o(s) = max{ (s − o) / (1 − o), 0 }   滞后流在全局进度超过 o 前一直保持纯噪声
```
把领先权分配给世界流或动作流，得到 video-lead 与 action-lead 两个 regime；`(α, o) = (1, 0)` 精确还原同步对角线。

### 四项服务端加速（各自独立可配）

| 加速 | 做法 | 前提/代价 |
|---|---|---|
| Prompt embedding 缓存 | server 生命周期内缓存 prompt→文本编码器嵌入，把文本编码器从每请求路径移除 | 指令重复出现时收益大 |
| 跳过视频解码 | 控制消费动作而非像素，服务路径完全跳过 VAE 视频解码 | 想看生成视频时得关掉 |
| 编译 | 每个架构注册固定形状 `torch.compile` 路径给内层联合去噪循环，在 CUDA graph 下重放 | **首个请求承担编译预热** |
| DiT 速度缓存 | 两流最近的速度预测余弦相似度超阈值时，跳过下次联合前向、直接积分缓存速度，连续跳过次数有上界 | 阈值与上界需调；牺牲少量精度 |

Wan2.2-TI2V-5B 骨干、RTX 5090 上的实测（prompt 缓存与跳解码默认开，图中消融编译与速度缓存）：

## 四、评测协议：客户端-服务端 + 80 维统一动作空间

### 客户端-服务端管线

基准作为**瘦客户端**通过一条持久 WebSocket 连接接入，**不 import 模型或训练栈的任何东西**。

```
控制步 k：
客户端 ──(o_k, ℓ, q_k)──→ Policy Server ──→ 单个动作 a_k（机器人原生物理单位）
         最多 3 路相机                        全部面向模型的转换都在服务端
         （head 必需，wrist 可选）
         语言指令 ℓ
         可选原始机器人状态 q_k

服务端内部：
  裁剪/缩放/合成为 checkpoint 训练时的 canonical 图像布局（缺失相机填黑帧）
  → q_k 归一化并映射进模型侧动作表示
  → 推理得到模型空间 chunk â_{1:H}
  → 映射回来并反归一化成原生单位
  → 填充 action buffer，服务端从 buffer 回答请求
  ⇒ 归一化后的数值永不到达机器人
片段之间：一个 reset 请求清空所有 per-episode executor 状态
```

**8 个集成的仿真基准**：LIBERO、LIBERO-Plus、VLABench、RoboTwin2.0、RoboDojo、RoboCasa365、RoboCasa-GR1、EBench。因为协议只交换图像、文本、动作向量，**真机平台走的是和仿真器完全相同的接口**。集成新基准 = 写一个 adapter（复现该基准训练 reader 的观测预处理），模型与两个 runtime 都不动。

### 80 维统一动作空间

```
┌──────────── 左臂 34D ────────────┬──────────── 右臂 34D ────────────┬── 保留 12D ──┐
│ EEF位置 3 │ 6D旋转 6 │ 夹爪 1 │ 灵巧手 24 │ EEF位置 3 │ 6D旋转 6 │ 夹爪 1 │ 灵巧手 24 │ 移动底盘等   │
└───────────────────────────────────┴───────────────────────────────────┴──────────────┘
```

每个数据集声明一个索引映射 `π`（式 4）：
```
u = Scatter_π( Norm(a) )         # 原生动作 → 统一空间
a = Norm⁻¹( Gather_π(u) )        # 统一空间 → 原生动作
```
本体感沿同一映射的正向遍历。式(2) 的有效性掩码 `m` 精确标记被映射的槽位，**未映射坐标训练时不接收梯度、推理时留在自己的解析噪声路径上**。

槽位语义固定，所以不同具身共享的结构落在同一坐标上——这是"从未见过的具身也能微调上去"（Wuji 手 + Tianji 臂实验）的机制基础。

默认情况下每个基准保持原生动作空间（RoboTwin2.0 用 14D 关节空间或 20D 双臂末端空间，LIBERO 用 10D 末端空间），单基准训练的 checkpoint 直接透传。

## 五、OpenWAM-α 完整流程

### 架构装配

```
E = Wan2.2-VAE（冻结）
S = { W: Wan2.2-TI2V-5B DiT（从预训练权重初始化）
      A: 1B ActionDiT（专属参数） }
M = mutual + 首帧因果的模态内视频注意力
```

### Tokenization

```
o_{1:T}  ──Wan2.2-VAE 因果编码──→  T' = 1 + (T−1)/4 个隐帧 z
          （首帧单独，后续每 4 帧一组）      首个隐帧保持为"现在"的干净锚点

z ──(1,2,2) patch embedding──→ 世界流 token，宽 3072，3D RoPE over (帧, 高, 宽)
H 个噪声动作步 ──线性嵌入──→ 动作流 token，宽 1024，1D RoPE over chunk 索引

ℓ ──umT5（冻结）──→ 4096 维 context
q ──线性投影──→ 追加为一个额外 context token
两条流各自通过 per-block 交叉注意力消费 context c
```

### 流桥接

**全部 30 对层都是桥接层**：流自有的投影把两个残差宽度映射到共享注意力空间（24 heads × 128 dim）。在配置的 `M` 下两流自由互读，而干净首帧的行既不 attend 噪声未来帧也不 attend 动作。

AdaLN 注入各流自己的去噪时间步——`t_v` 逐 token 注入世界流（**首帧 token 钉在干净端点 `t_v = 1`**），`t_a` 注入动作流。线性头把两个最终状态解码成速度。

### 推理

```
同步调度，训练 warp 上实现为 t_i = 1 − f_ρ(1 − i/N)，ρ = 5，N = 10 步
起点：高斯噪声，首个隐帧钳到当前观测的编码，且每步后重新钉住
每步：一次联合前向 + 耦合 Euler 更新
     ⇒ 动作 chunk 对着逐步变干净的世界特征精炼，反之亦然，在全部 30 个桥接层上
完成的 chunk 经式(4) 逆映射回各机器人原生动作空间
```

## 六、伪代码

```python
# ============ 训练一步 ============
def train_step(batch, arch, opt):
    l, obs, act, proprio, mask = batch          # (ℓ, o_{1:T}, a_{1:H}, q, m)

    z     = arch.E.encode(obs)                  # 冻结编码器 → 隐序列
    ctx   = concat(umT5(l), proj(proprio))      # 语言 + 本体感 → context

    # 关键：两个时间步独立采样 → 覆盖整个噪声平面
    t_v   = 1 - f_rho(uniform(), rho=5)
    t_a   = 1 - f_rho(uniform(), rho=5)
    eps_v, eps_a = randn_like(z), randn_like(act)
    z_t   = t_v * z   + (1 - t_v) * eps_v
    a_t   = t_a * act + (1 - t_a) * eps_a

    # 一次联合前向：trainer 不知道内部是哪个架构
    v_z, v_a = arch.forward(z_t, a_t, t_v, t_a, ctx)

    loss = w(t_v) * mse(v_z, z - eps_v, exclude=clean_frames) \
         + w(t_a) * mse(mask * v_a, mask * (act - eps_a))     # 有效性掩码限制监督范围
    loss.backward(); opt.step()


# ============ joint self-attention 的桥接层 ============
def bridged_layer(layer_v, layer_a, h_v, h_a, M):
    # 每个骨干的 block step 劈成 pre/post 两半，注意力在中间跨流联合算
    q_v, k_v, val_v = layer_v.pre_attention(h_v)
    q_a, k_a, val_a = layer_a.pre_attention(h_a)

    # 流自有投影 → 共享注意力空间（24 heads × 128 dim）
    Q = concat(proj_v(q_v),   proj_a(q_a))
    K = concat(proj_v(k_v),   proj_a(k_a))
    V = concat(proj_v(val_v), proj_a(val_a))

    O = attention(Q, K, V, mask=M)              # M 决定 4 种跨模态可见性模式
    o_v, o_a = split(O)

    h_v = layer_v.post_attention(unproj_v(o_v))
    h_a = layer_a.post_attention(unproj_a(o_a))
    return h_v, h_a


# ============ 推理：同步去噪 ============
def infer(obs, l, proprio, arch, N=10, rho=5):
    z_clean_first = arch.E.encode(obs)[0]       # 当前观测的编码 = 干净锚点
    z, a = randn(...), randn(...)
    z[0] = z_clean_first                        # 首帧钳住
    ctx = concat(umT5(l), proj(proprio))

    for i in range(N):
        t      = 1 - f_rho(1 - i / N, rho)      # 同步：两流同一时间步
        t_next = 1 - f_rho(1 - (i + 1) / N, rho)
        v_z, v_a = arch.forward(z, a, t, t, ctx) # 一次联合前向
        z = z + (t_next - t) * v_z              # 耦合 Euler
        a = a + (t_next - t) * v_a
        z[0] = z_clean_first                    # 每步后重新钉住首帧
    return denormalize(gather_pi(a))            # 回到原生动作空间
```

## 七、实现陷阱

1. **首帧必须每步重新钉住**。它是"现在"的干净锚点，Euler 更新会污染它。同时 AdaLN 里首帧 token 的时间步要钉在 `t_v = 1`，而不是跟着当前去噪步走。
2. **表征式编码器不能裸用**。768/1024 维隐变量塞进为 48 维优化的 DiT 会掉 8–14 点。必须过 S-VAE 降维。
3. **有效性掩码要同时管两头**。训练时未映射坐标不接收梯度；推理时它们必须留在解析噪声路径上，不能当成有效预测读出。
4. **两个时间步必须独立采样**。如果偷懒共用一个 `t`，训练只覆盖对角线，异步调度立刻分布外，"同步最优"的结论也就无从检验。
5. **归一化统计必须随 checkpoint 走**。缺了它部署会静默出错——动作数值量级错了但代码不报错。论文的做法是硬报错。
6. **`torch.compile` 的首请求预热**。基准评测里第一个 episode 的延迟会异常高，别把它算进延迟统计。
7. **数据清洗里中段暂停绝不能剪**。剪掉会把时间上不相邻的帧拼在一起，制造出物理上不可能的运动。只剪首尾静止段。
8. **video-sees-action 单向掩码是个陷阱**。它看起来"也建立了跨模态通路"，但性能（87.63）几乎等于完全隔离（87.41）。方向错了等于没有。

## 九、复现风险

| 风险 | 说明 |
|---|---|
| **算力门槛** | 预训练 128×H200 约 7 天。按公开云价格粗估是数万美元量级的单次运行，学术组难以独立复现完整预训练。 |
| **数据可得性** | 第一视角数据是作者**自建**的（71.6K 段 0.25–6 分钟第一人称录制，3,006 个日常操作任务），占训练帧 30.1%。论文说会放 data recipe，但自建数据本身能否完整开放、以什么许可开放，决定了这 30% 能否复现。 |
| **数据清洗的阈值** | 清洗协议描述得相当细（幅度比 ≥3×、逐轴相关 <0.5、视频-信号错位 >2%、2 cm/s 与 5°/s、p99.5 校准、丢帧 >70% 删段），但"每机器人运动阈值从 p99.5 校准"意味着每个数据源都要单独定标，复现时容易产生偏差。 |
| **基准分数的可比性** | 表中基线（Qwen-RobotManip、X-VLA、ABot-M0.5、Xiaomi-Robotics-1 等）多为 2026 年新工作，各自训练数据与配置不同。论文自己在 Takeaway 1/3 里强调了这点：**跨模型比较很大程度上是在比数据**。 |
| **真机实验** | 三种平台（Franka-Research-3、RoboDojo 官方三具身、Wuji 手 + Tianji 臂）都是特定硬件，且灵巧手平台由 Wuji Technology 提供算力支持。真机数字不具备一般可复现性。 |
| **LIBERO-Plus 归因的确定性** | 论文对 OpenWAM-α 在 LIBERO-Plus 掉队给了数据与架构双重归因，论证链（三个共享像素级目标的模型呈现相同签名 + ImageWAM 单帧预测 / Being-H0.7 语义隐变量的两个旁证）是合理的，但**没有做直接的控制实验**（比如给 OpenWAM-α 补单臂数据看能否恢复）。这是一个有说服力的诊断，不是已验证的因果结论。 |
