## 基础题

### 1. WAM 和 VLA 分别从哪里继承知识？这个区别为什么重要？

<details>
<summary>答案</summary>

- **VLA** 从预训练**视觉语言模型**继承**语义与语言知识**（RT-2、OpenVLA、π0 系）。
- **WAM** 从**视频生成预训练**继承**视觉动态的生成式先验**（DreamZero、Fast-WAM、LingBot-VA、Cosmos Policy）。

重要性在于它对应具身学习的**根本数据不对称**：世界变化的视频极其丰富，带可执行动作标签的机器人轨迹相对稀缺。两种范式都是在用丰富的数据源给稀缺的动作学习提供"暖启动"，但选择了不同的暖启动来源。

WAM 的赌注是：视频生成被**显式训练来建模时间演化**，所以它天然是"学习动作如何与物理变化交互"的起点——比"懂语义"更接近"懂动力学"。

</details>

### 2. `C(E, S, M)` 三个符号各代表什么？为什么组合规则 C 本身不带参数？

<details>
<summary>答案</summary>

- **E**：视觉编码器，把观测映射成世界流要预测的隐序列，**始终冻结**
- **S**：流骨干集合——世界流 W、动作流 A、可选理解流 U
- **M**：可见性注意力掩码，规定流之间和 token 之间谁能 attend 谁
- **C**：组合规则，装配上述模块

**C 不带参数的原因**：所有可学习容量都必须留在流骨干里，这样"换组合规则"就是一个纯粹的结构变量，不会顺带引入新参数把消融污染掉。C 只做三件事——排列各骨干的 `prepare` / 逐层 `block step` / `finalize` 执行顺序；需要在注意力内交互时把 block step 劈成 pre/post 两半来替换注意力计算；**永不修改骨干内部**。

这是"受控实验"这个目标对实现的硬约束，不是审美选择。

</details>

### 3. 80 维统一动作空间是怎么划分的？validity mask 起什么作用？

<details>
<summary>答案</summary>

```
左臂 34D                          右臂 34D                          保留 12D
EEF位置3 + 6D旋转6 + 夹爪1 + 灵巧手24 | (镜像相同)                | 移动底盘等具身专属通道
```

每个数据集声明索引映射 π：`u = Scatter_π(Norm(a))`，反向 `a = Norm⁻¹(Gather_π(u))`。本体感沿同一映射正向遍历。

**validity mask m 的双重作用**：
1. **训练时**：式(2) 的动作项被 `m ⊙` 限制到该具身实际填充的坐标，未映射坐标**不接收梯度**
2. **推理时**：未映射坐标留在自己的**解析噪声路径**上，不被当作有效预测读出

**为什么槽位语义要固定**：这样不同具身共享的结构（比如"末端位置"）落在同一坐标上。这是"从未见过的具身也能微调上去"的机制基础——Wuji 手 + Tianji 臂（9D 末端 + 21 DoF，预训练混合中完全不存在）微调后全面超过 π0.5。

</details>

### 4. OpenWAM-α 的预训练规模和算力是多少？数据由哪几部分组成？

<details>
<summary>答案</summary>

**规模**：518.5M 帧 / ≈6,369 小时（从原始池 1.33B 帧 / 14,348 小时经清洗和逐源子采样得到），21 种具身。

**算力**：16 节点 × 8 张 NVIDIA H200 = 128 GPU，约 7 天。全局 batch 3,072 clips，155,862 步（1 epoch）。

**五个数据源**：
| 源 | 类型 | 占比 |
|---|---|---|
| 自建第一视角数据 | 人类视频 | 30.1% |
| InternData-A1 | 仿真机器人 | 30.0% |
| AgiBotWorld-Beta | 真实机器人 | 18.6% |
| RoboCOIN | 真实机器人 | 14.3% |
| DROID | 真实机器人 | 7.0% |

**配比规则**：第一视角与仿真各占总帧 30%，剩下 40% 按三个真机源的清洗后有效帧数比例分配。这样不同原生帧率的源按"模型实际消费的数据量"平衡。

第一视角数据是作者自建的：71.6K 段 0.25–6 分钟第一人称录制，覆盖 3,006 个日常操作任务。它**没有动作标签**，所以动作与本体感通道全部掩掉，只监督世界流。

</details>

### 5. 论文得出的三个 Finding 分别是什么？

<details>
<summary>答案</summary>

**Finding 1（继承）**：WAM 经由**足够强的生成骨干**和**紧凑、信息丰富的视觉表征空间**最有效地继承上游世界知识。重建式编码器不是唯一选择——表征式编码器配合维度压缩同样高性能。

**Finding 2（交互）**：世界–动作协同需要**训练时显式的 world→action 信息流**，以及**推理时同步联合去噪**。（mutual vs 单向的接近选择被明确推迟到预训练阶段再定。）

**Finding 3（整合）**：具身预训练**主要扩展 OOD 泛化**。机器人轨迹保住动作接地，第一视角视频拓宽迁移，**单阶段共训**有效整合两者。预训练规模下，**mutual 双向可见性一致更优**。

三者构成一个**顺序**而非独立最优超参列表：每个决策都在前一个决策创造的条件下检验。

</details>

## 中级题

### 6. 为什么 DINOv3 裸用只有 76.42，加了 S-VAE 就跳到 90.18？这说明了什么？

<details>
<summary>答案</summary>

**直接原因是维度不兼容**。现代 DiT 是为重建式编码器的低维隐变量优化的（Wan2.2-VAE 是 48 维）；DINOv3 输出 768 维、V-JEPA 2.1 输出 1024 维，直接塞进 DiT 是架构层面的不匹配。S-VAE 适配器把它们压到 48 维（对齐 Wan2.2-VAE），差距立刻消失甚至反超 FLUX.2-VAE。

完整对照（骨干权重随机初始化以隔离表征贡献）：
| 编码器 | 平均成功率 |
|---|---|
| DINOv3 w/o SVAE | 76.42 |
| V-JEPA 2.1 w/o SVAE | 80.91 |
| FLUX.2-VAE | 84.26 |
| V-JEPA 2.1 w/ SVAE | 88.46 |
| DINOv3 w/ SVAE | 90.18 |
| Wan2.2-VAE | 90.30 |

**说明的是一个概念转变**：判断隐空间适不适合 WAM，不该问它"来自重建目标还是表征目标"，而该问两个**操作性质**——
- **紧凑性**（时间维度 + token 维度双压缩）
- **世界信息丰富度**

Wan2.2-VAE 剩下的 0.12 点优势也被解释了：它是原生匹配视频骨干架构的编码器，且它的 4× 时间压缩是**学出来的**，而其他三个靠"每 4 帧特征取平均"硬压。这直接指向一个研究方向：做**原生带时间压缩的表征式编码器**。

</details>

### 7. 训练时四种注意力掩码的结果如何？为什么说"方向错了等于没有"？

<details>
<summary>答案</summary>

| 掩码 | Clean | Randomized | 平均 |
|---|---|---|---|
| Isolated | 88.08 | 86.74 | 87.41 |
| Video Sees Action | 87.92 | 87.34 | **87.63** |
| Action Sees Video | 92.98 | 91.80 | **92.39** |
| Mutual | 92.50 | 91.80 | 92.15 |

分界干净得罕见：结果**只按"动作流能否 attend 世界流"分成两个平台**，中间没有过渡。

**"方向错了等于没有"**指的是 `video-sees-action`：它确实建立了跨模态通路（动作特征暴露给世界流），看起来"也做了跨模态交互"，但 87.63 几乎等于完全隔离的 87.41。约 5 点的鸿沟只由一个二值问题决定——**动作 token 能不能读到视频 token**。反向通路在 from-scratch 下只值 ±0.2 点。

这是一个实现上的陷阱：如果你只检查"有没有跨模态注意力"而不检查方向，可能白搭一套机制。

</details>

### 8. 为什么"训练时独立采样两个时间步"是整个设计的枢纽？

<details>
<summary>答案</summary>

因为 `t_v` 与 `t_a` 独立采样，训练**覆盖了整个 (t_v, t_a) 二维噪声平面**，而不只是对角线。

后果链：
1. 任何推理调度都只是这个平面上的一条**路径** → **始终分布内**
2. 同步推理是 `(α, o) = (1, 0)` 的**特例**，不是单独代码路径 → 每个异步实验自动有一个对齐的基线
3. 因此"同步最优"是一个**干净的结论**，而不是"异步碰上了分布外状态"的伪影

如果偷懒共用一个 `t`：训练只覆盖对角线，任何异步调度立刻分布外，Finding 2 的后半部分（推理时同步最优）就完全无从检验——你无法区分"异步机制不好"和"异步偏离了训练分布"。

另外，每条流的时间步 warp 是**存在 checkpoint 里的骨干属性**，推理时复用，所以训练与服务的噪声网格不可能漂移。

</details>

### 9. 具身预训练在 ID 和 OOD 上的增益差多少？两种数据源分工如何？

<details>
<summary>答案</summary>

600 小时等预算，RoboTwin2.0-Clean2Random：

| 策略 | ID (Clean2Clean) | OOD (Clean2Random) |
|---|---|---|
| From Scratch | 87.00 | 14.50 |
| Robot Only | 88.50 (+1.50) | 23.80 (+9.30) |
| Ego → Robot（两阶段） | 87.10 (+0.10) | 26.50 (+12.00) |
| Ego + Robot 共训 | 87.68 (+0.68) | **26.62 (+12.12)** |

**ID 增益 ≤ 1.5 点，OOD 增益高达 +12.12 点。** 具身预训练贡献的主要是"能迁移到下游训练分布之外"的知识，而不是把一个已经饱和的 ID 基准拟合得更好。

**分工**：
- **机器人轨迹**：Robot-only 的 ID 最强（88.50）→ 提供**可执行的动作接地**，也提供机器人与物理世界交互的最真实视觉观测
- **第一视角人类视频**：混合策略 OOD 更好 → 提供**视觉与交互分布的广度**

**顺序不重要**：两阶段（26.50）与单阶段共训（26.62）几乎打平，说明**用不用两种数据比怎么排序重要得多**。共训微弱领先且省掉课程切换，成为默认。

**实践含义**：如果部署场景与微调数据分布一致，具身预训练性价比不高；一旦要面对新场景、新物体、新光照，它就是决定性的。

</details>

### 10. 论文的加速栈有哪四项？各自的代价是什么？

<details>
<summary>答案</summary>

| 加速 | 做法 | 代价/前提 |
|---|---|---|
| Prompt embedding 缓存 | server 生命周期内缓存 prompt→文本编码器嵌入，把文本编码器移出每请求路径 | 指令高度多样、几乎不重复时失效 |
| 跳过视频解码 | 控制消费动作而非像素，服务路径完全跳过 VAE 视频解码 | 想看生成视频做调试/监控时必须关掉 |
| 编译 | 每架构注册固定形状 `torch.compile` 路径给内层联合去噪循环，CUDA graph 下重放 | **首请求承担编译预热**（基准第一个 episode 延迟异常高，别算进统计） |
| DiT 速度缓存 | 两流最近速度预测余弦相似度超阈值时跳过下次联合前向、直接积分缓存速度，连续跳过有上界 | 阈值与上界需调；**牺牲少量精度** |

Wan2.2-TI2V-5B + RTX 5090 实测（prompt 缓存与跳解码默认开）：Dual-System Joint Self-Attn 从基线降到 **175 ms（2.45×）**；OpenWAM-α 的 10 步循环约 **170 ms/chunk**。其他架构 149–251 ms，加速 2.01–2.63×。

</details>

## 进阶题

### 11. 为什么 16 种异步去噪调度全部输给同步？这支持了哪个假说、反驳了哪个？

<details>
<summary>答案</summary>

**实验设计**：固定 mutual 可见性，两族参数化 × 两个引领方向 × 4 个参数值 = 16 种异步调度。variance-shift 试 α ∈ {4, 8, 16, 32}，linear-offset 试 o ∈ {0.2, 0.4, 0.6, 0.8}。

**结果**：同步 93.0 最优，16 种异步全部不如它（88.5–92.3）。而且两族的方向偏好还**相反**——variance-shift 下 video-lead 好于 action-lead，linear-offset 下 action-lead 好于 video-lead。这种不一致本身就说明"引领哪条流"不是一个有真实机制的旋钮。

**支持表征学习假说**：WAM 之所以有效，是因为视频预测这个**辅助任务在训练时塑造了更好的表征**。表征学好之后，测试时两条流应该在同一噪声水平上互相精炼；人为拉开只是偏离训练分布的中心区域。

**反驳测试时规划假说**：WAM 有效不是因为它在测试时"先想象未来、再从想象反推动作"（IDM 式的隐式 planning-then-IDM）。若如此，video-lead 该有明显优势。

**独立佐证**：Table 1 里 IDM 变体（显式的两阶段：先生成视频轨迹再预测动作）只有 87.95，比 joint self-attention 的 92.36 低 4.4 点。两条独立证据指向同一结论。

**一个值得保留的怀疑**：独立均匀采样两个时间步时，落在平面**角落**（一流极干净、另一流极噪声）的样本密度与对角线附近相同——但极端异步调度走的正是角落。所以"异步全败"可能部分来自角落区域的**有效样本量**而非机制本身，ρ=5 偏向高噪声的采样会进一步扭曲这个分布。

</details>

### 12. 信息流偏好为什么会在预训练后翻转？论文如何排除了伪影解释？

<details>
<summary>答案</summary>

**现象**（Figure 11，数值为 Mutual − Action-Sees-Video，百分点）：
| 设置 | 基线绝对值 | 差值 |
|---|---|---|
| From Scratch · RoboTwin-Full | 92.39 | **−0.24** |
| Pretrained · RoboTwin-Full | 92.34 | **+0.16** |
| Pretrained · C2R (ID) | 86.98 | **+0.70** |
| Pretrained · C2R (OOD) | 25.70 | **+0.72** |

**如何排除伪影**：翻转在 C2R 的 **ID（+0.70）和 OOD（+0.72）上幅度相当**。
- 如果是**域偏移伪影**，ID 和 OOD 的差值应该不同（OOD 才有域偏移）
- 如果是**评测协议伪影**，RoboTwin-Full 和 C2R 两个协议不该同向翻转

两者都被排除，留下的是真实机制。

**机制**：预训练让世界–动作交互变成**真正双向的交换**——预测的未来帧为动作生成提供视觉引导；预测的动作反过来告知那些帧中机械臂运动该怎么合成。数据稀缺时两条流建立不起这种对应，反向通路只是噪声；充足的预训练数据填上缺口，Mutual 的优势才兑现。

**更大的意义**：这是"**架构选择依赖数据规模**"的干净案例。小规模受控实验选出的最优架构，放大后可能不再最优。论文的处理很老实——Finding 2 明确写了要把 mutual vs 单向的接近选择"defer to pretraining"，而不是在小规模上强行拍板。

**但论文只回头验证了这一个变量**。按同一逻辑，编码器选择、架构族系、去噪调度是否也会在预训练规模下翻转？这是论文自身方法论指向但没做完的事。

</details>

### 13. OpenWAM-α 在 LIBERO-Plus 上为什么明显掉队？论文的双重归因和它的证据强度如何？

<details>
<summary>答案</summary>

**现象**：OpenWAM-α 69.2，而 Qwen-RobotManip 89.0。分项看，损失集中在 **camera（33.8）与 noise（39.8）**，background 与 layout 也有可见缺口。同一榜单上 ABot-M0.5（83.4）、ImageWAM（83.1）、Being-H0.7（82.1）——**全都是 WAM**——表现接近 SOTA。

**归因一：数据视角**
OpenWAM-α 的单臂数据仅约 **1,100 小时**，只有两个来源：DROID（固定单臂平台、固定相机视角）和 InternData-A1 的单臂部分。而 ABot-M0.5 用 8,000+ 小时、Being-H0.7 用 5,700+ 小时，且覆盖多样具身、场景、视角——预训练时它们**已经见过接近 LIBERO-Plus 测试场景的视觉信息**。

反面印证：OpenWAM-α 的混合富含第一视角、双臂、灵巧手数据，对应基准（EBench、RoboCasa-GR1、RoboCasa365）就都是 SOTA。

**归因二：架构视角**
Fast-WAM、ABot-M0.5、OpenWAM-α 共享同一预测目标——**Wan2.2-VAE 重建式隐空间上的像素级未来视频**。三者在 camera/noise 上呈现**相同的性能签名**（这两项明显低于其他扰动），只有 ABot-M0.5 靠数据把损失补回大半。

两个关键旁证：
- **ImageWAM**（未预训练却仍强）：预测目标也是像素级隐变量，但**只预测单帧未来**——更接近"编辑"而非"rollout"，所以**没有跨帧误差累积**
- **Being-H0.7**：用 V-JEPA 2.1 编码，中间隐变量仍是时序的（多帧联合编码），但是**语义级特征而非像素重建**，因此对 camera/noise 明显更鲁棒

**证据强度评估**：论证链合理且有两个方向的旁证（改变时程 → 改善；改变表征层次 → 改善），但**没有做直接控制实验**——比如给 OpenWAM-α 补充多样单臂数据，看 camera/noise 分项能否恢复。所以这是一个**有说服力的诊断，不是已验证的因果结论**。

最干净的补充实验就是这个：逐步加入带视角/背景/光照变化的单臂数据，观察分项恢复情况。

</details>

### 14. Takeaway 3 说 WAM 的 ID 更好、VLA 的 OOD 更好。两个机制分别是什么？最干净的对照是哪一组？

<details>
<summary>答案</summary>

**最干净的对照**：**StarVLA vs Fast-WAM**——两者都**没有具身预训练**，所以排除了预训练数据差异这个最大混淆因素。

| 基准 | 类型 | Fast-WAM | StarVLA |
|---|---|---|---|
| LIBERO Avg | ID | **97.6** | 96.6 |
| RoboTwin2.0 C2R Clean | ID | **77.8** | 46.5 |
| RoboTwin2.0 Full Avg | ID | **91.85** | 88.25 |
| LIBERO-Plus Avg | OOD | 51.5 | **74.1** |
| RoboTwin2.0 C2R Randomized | OOD | 1.9 | **3.2** |

ID 三项 WAM 全胜（C2R Clean 上领先 31 点），OOD 两项完全反转。

**ID 优势的机制**：WAM 训练里有**视频隐变量监督**。VLA 只针对动作监督优化，没有中间隐变量目标；视频隐变量项为参数优化**注入了额外的信息源**，让 WAM 能更紧地拟合训练数据。

**OOD 劣势的机制**：正是 ID 优势的另一面。**长时程未来预测在分布偏移下意味着更重的误差累积**——这是纯动作 VLA 从不背的负担。

**预训练模型侧的印证**：OpenWAM-α 在 ID 分片（LIBERO 99.3、VLABench In-dist.、C2R Clean）领先三个最强 VLA，**即使那些 VLA 的预训练数据超过本文**；而在 OOD 分片（LIBERO-Plus、C2R Randomized、RoboDojo Open）明显落后 SOTA VLA。

**结论的第二半更重要**：两个缺口**都能被足够大且多样的预训练数据补偿**——覆盖复杂环境变化、携带精确动作标注的数据，让任一范式都能同时拿到强拟合与强泛化。所以真正的建议是**先把数据搞对，再纠结范式**。两者都是从观测到动作的端到端模型，如何结合互补优势是值得追的方向。

</details>

### 15. 论文全部受控实验都在 RoboTwin2.0 上做，这对配方的普适性构成什么威胁？

<details>
<summary>答案</summary>

**事实**：Section 4 的三组受控实验（Finding 1/2/3）**全部**在 RoboTwin2.0 上完成——一个**双臂**操作基准。

**威胁**：Section 5 恰好显示 OpenWAM-α 在**双臂/灵巧手强、单臂弱**。而 Takeaway 1 自己说的是——模型在某基准上泛化得如何，最终由"预训练混合是否含有接近该基准测试条件的数据"决定。

**这个逻辑同样适用于配方的推导过程**：在双臂基准上选出的配方（5B 骨干、Wan2.2-VAE、dual joint self-attn、同步去噪、ego+robot 共训、mutual），对单臂任务是否同样最优？论文没有验证。

**具体可能受影响的选择**：
- **编码器**：双臂操作中相机视角通常较稳定；单臂基准（LIBERO-Plus）恰恰在 camera 扰动上暴露了 Wan2.2-VAE 的软肋。若配方在单臂基准上推导，可能会选出语义级编码器（如 Being-H0.7 用的 V-JEPA 2.1）
- **架构族系**：Tri-System（加 VLM）在 RoboTwin2.0 上只比 Dual 高 0.24 点因而被舍弃；但语言理解在指令更复杂的基准上可能价值更高
- **信息流**：Mutual vs 单向的差距本身就只有零点几点，且符号已被证明会随数据规模翻转——那它是否也会随基准/具身翻转？

**论文自身逻辑的内部张力**：它一方面证明了"偏好会随预训练规模翻转"（Finding 3 的信息流反转），一方面又把所有其他选择的推导留在单一基准的小规模设置里。**这恰恰是它自己方法论指向但没做完的事**。

**公允地说**：在单一基准上做完整的多变量受控实验已经是巨大的算力投入，跨基准重复整套实验在实践中几乎不可行。论文的价值在于建立了这套可复现的实验基础设施——**其他人可以在自己关心的基准上重跑这些消融**，这本身就是 OpenWAM-Infra 存在的意义。

</details>
