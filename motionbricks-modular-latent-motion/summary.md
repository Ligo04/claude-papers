# MotionBricks 论文总结

## 背景

运行时交互式运动控制是动画和机器人应用的基石。传统方案依赖**动画图/行为树**（如 Assassin's Creed 需管理 15,000+ 动画、5,000 状态、12 层嵌套），维护成本极高。现有生成式方法面临两个关键矛盾：

1. **实时可扩展性**：工业应用需要实时生成大量运动技能，扩散模型质量好但太慢
2. **控制整合性**：现有模型缺乏系统化运动设计接口，文本驱动难以提供细粒度控制

## 问题陈述

设计一个统一框架，同时满足：
- 产出质量媲美 SOTA 生成模型
- 吞吐量远超实时要求（>30 FPS）
- 支持细粒度多模态控制（速度、航向、风格、物体交互）
- 零样本泛化到新任务，无需 fine-tune 或标注

## 核心贡献

### 1. 模块化生成神经骨干
- **多头 tokenizer**：K 个独立 codebook 并行量化运动，容量可扩展至 10⁹ token
- **Root-pose 解耦**：根轨迹与身体姿态分开编码，解耦后生成更灵活
- **渐进式粗到细生成**：Root Module 预测时序+轨迹 → Pose Module 生成离散 token → Decoder 解码连续运动
- **灵活约束处理**：可变数量的关键帧约束，缺失项用可学习 mask embedding 替代

### 2. 智能原语（Smart Primitives）
- **Smart Locomotion**：
  - 临界阻尼弹簧模型生成初始轨迹 r_{g,1} → r_{g,2}
  - 风格关键帧放置到弹簧平滑轨迹上
  - 神经网络 root module 细化为 r_{g,3}，处理死区和不合理速度
  - Decoder 进一步细化为 r_{g,4}
- **Smart Object**：
  - **意图关键帧**：定义交互行为的关键姿态（硬约束 τ=0 或软引导 τ>0）
  - **交互绑定**：检测（碰撞体积）、放置（socket 系统）、锚定（物体坐标系旋转关键帧）

### 3. 机器人部署
- 通过 ONNX + TensorRT 导出
- 物理跟踪控制器驱动 Unitree G1
- Jetson Orin 上 5ms 推理延迟

## 关键结果

### 性能（350k 数据集, Table 3）

| 指标 | MotionBricks | 最佳基线 | 改进 |
|------|-------------|---------|------|
| FPS | **15,000** | 14,500 (Closd-DiP+5步) | 实时性最佳之一 |
| 延迟 | **2ms** | 4ms (Closd-DiP) | 2× 更快 |
| FID ↓ | **0.1056** | 0.1076 (Closd-DiP) | 分布匹配最佳 |
| 人类评价胜率 ↑ | **86.5%** | 19.9% (MMM) | 压倒性优势 |
| 人类评分 ↑ | **4.06** | 3.19 (MMM) | 显著更高 |
| 到达成功率 ↑ | **99.6%** | 85.7% (Two-stage) | 近乎完美 |
| 脚滑 ↓ | **0.003** | 0.004 (MMM) | 最低 |
| 穿透 ↓ | **0.008** | 0.011 (多方法) | 最低 |

### 可扩展性
- 多头 tokenizer 在 10³→10⁹ token 范围内 FID 持续改善
- 单头基线在 10⁴ 后饱和
- 最优配置：每头 128-256 token，总容量 ~10⁹

### 训练配置
- 4 节点 × 8 H100 GPU（32 GPU 总计）
- 200万步更新，batch size 256/GPU
- Tokenizer 7天，Root Module 3天，Pose Module 7天
- 16 GPU 训练视觉质量相当

- **BONES-SEED**：~140k 运动片段开源子集（350k 的 40%），通过 Bones Studio 发布
