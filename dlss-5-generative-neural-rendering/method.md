# 方法拆解：从渲染帧到受控的照片外观

> 说明：下面的流程图和伪代码只把报告明确披露的接口与约束串起来。报告没有公开完整网络层配置、训练数据、损失权重、采样参数或权重，因此凡是标为“未披露”的地方都不能当作官方实现细节。

## 1. 变量与接口

对第 `t` 帧，使用以下记号：

| 符号 | 含义 | 使用阶段 |
|---|---|---|
| `r_t` | 引擎渲染的 RGB 帧 | 运行时主条件 |
| `m_t` | 引擎运动向量 | 运行时，提供时序对应 |
| `h_{t-1}` | 上一时刻携带的时序状态 | 运行时，因果流式 |
| `a_t` | 艺术指导：外观模型、结构/色调强度、色度和掩码 | 运行时 |
| `q_t` | 渲染器导出的反照率 | 训练时一致性监督；不作为发布模型输入 |
| `n_t` | 渲染器导出的表面法线 | 训练时一致性监督；不作为发布模型输入 |
| `l_t` | 渲染器导出的光照相关信号 | 训练时一致性监督；不作为发布模型输入 |
| `x_t` | 最终显示 RGB 帧 | 运行时输出 |

部署接口可以抽象成：

```text
x_t, h_t = F_θ(r_t, m_t, h_{t-1}, a_t)
```

`F_θ` 是确定性的、因果的、一步生成映射。这里的状态更新形式是概念记号；报告没有公开状态张量的具体结构或更新方程。

## 2. 总体数据流

```text
                         ┌──────────────────────────────┐
                         │  训练阶段（额外的渲染器信号）  │
                         │  q=albedo, n=normal, l=light │
                         └──────────────┬───────────────┘
                                        │ 一致性监督
                                        ▼
场景/相机 ──> 传统渲染器 ──> r_t (RGB) ───────────────┐
     │                         │                    │
     └─────────────────────────┴─> m_t (motion)     │
                                                    ▼
                                      ┌────────────────────────┐
                                      │ DLSS 5 Transformer      │
                                      │ 一步、像素空间、因果   │
                                      │ + h_{t-1} + 艺术控制 a_t│
                                      └───────────┬────────────┘
                                                  │
                                           x_t (显示 RGB)
                                                  │
                                           h_t (携带状态)
```

关键边界是：传统渲染器仍然定义场景内容和物理参考；DLSS 5 只改变显示外观，不写回几何、场景状态或 G-buffer。

## 3. 训练侧：把“内容锚点”和“照片先验”分开

### 3.1 为什么 RGB 既必要又不够

RGB 是密集且像素对齐的证据，能直接指出物体支持区域、遮挡边界、构图和局部材质。文本、示例图、深度或姿态等通用条件往往不能唯一确定这些内容。可是 RGB 已经混合了材质、光照和渲染器的烘焙效果：如果模型只复制 RGB，它没有空间提升真实感；如果自由度过大，它会改变角色或布局。

### 3.2 训练时属性监督

报告给出的解决思路是让渲染器同时提供三类监督信号：

1. **反照率**：约束与照明无关的本征色度，让颜色增强不把物体身份改掉。
2. **表面法线**：约束局部方向，帮助保持几何和边界。
3. **光照相关信号**：约束直接光与阴影的组织，避免把光源关系完全重写。

这些信号只在训练阶段使用。照片真实感不是由它们直接定义，而是从大规模真实照片中统计学习；属性监督负责抑制与作者场景冲突的变化。报告没有披露监督损失的具体公式、权重或是否使用配对照片，因此不能写成一个可复现的加权损失。

## 4. 生成侧：一步扩散与像素空间

### 4.1 一步而非多步

常见扩散模型通过多次随机去噪换取分布覆盖，但每一帧多次采样会直接违反交互式延迟预算。DLSS 5 将任务限定为强条件的外观增强，使用一次确定性的去噪/生成评估。相同的渲染序列、状态初始化和控制设置应产生相同的输出序列。

### 4.2 为什么不用 VAE 潜空间

潜空间方案通常要经历 `RGB → VAE encoder → denoise → decoder → RGB`。编码与解码是有损的，细线、远处角色、嵌入文字、边缘和纹理会被重新合成；微小潜变量偏移也可能造成位置或身份漂移。DLSS 5 直接在像素空间处理，网络特征图只是中间计算，不是必须重建回来的有损图像瓶颈。报告甚至指出，输入中的单像素锯齿也可能被保留下来：这是内容保真优先于缺陷修复的刻意选择。

## 5. 时序侧：因果逐帧流式

### 5.1 与分块视频生成的区别

分块模型先缓存 `K` 帧、联合做时空注意力，再一起释放输出；额外显示延迟约 `K−1` 个帧间隔，工作集随 `K` 增长。图 2 以 `K=3` 作示意，并不是报告声称的部署超参数。

DLSS 5 在 `r_t` 准备好后就处理当前帧，不看未来帧。运动向量提供跨帧对应，携带状态提供历史上下文，而当前 RGB 继续钉住本帧的内容。于是输出是：

```text
收到 r_t → 更新/读取 h_t → 一次 F_θ → 立即显示 x_t
```

对序列长度而言，峰值工作集近似 `O(1)`；但这不意味着显存为零，报告实测 4K RTX 5090 峰值约 731 MB。

### 5.2 时序稳定不等于物理一致

逐帧确定性和状态传递可以抑制闪烁、游移和漂移，但它们只说明输出在时间上可重复、连续。模型仍可能学习到与物理光传输不同的照片统计规律；论文把这种“感知真实感”和“物理参考”明确分开。

## 6. Backbone 与数值实现

报告披露的硬件协同要点如下：

- Transformer 骨干约 **154M 参数**，继承 DLSS 4 注意力实现的速度/质量折中。
- 通过自动架构搜索和针对性消融寻找适合 Tensor Core 的拓扑。
- 当前面向带 TMA（Tensor Memory Accelerator）的 Blackwell GPU 优化，用 TMA 把全局内存数据搬到片上存储。
- 大多数 GEMM 与注意力使用 FP8；少量数值敏感 GEMM 使用 FP16。
- 相对等价 FP16 实现，FP8 产生小幅实测质量差异，推理速度约提升 **2×**。

“约 154M”“约 2×”和“约 8 ms”都是报告当前实现的量级描述，不是任意 GPU、任意编译器或任意分辨率的理论保证。

## 7. 艺术控制的实现语义

### 7.1 外观模型子集

照片分布包括胶片/数字相机、镜头、调色和 tone mapping 等大量选择。系统暂时用少量策展模型离散采样这个分布；不同模型在色调、植被、光照和皮肤外观上有不同倾向。

### 7.2 结构与色调

结构强度 `S` 偏向高空间频率的细节与局部对比；色调强度 `T` 偏向低空间频率的亮度和广义照明。`S=0` 或 `T=0` 时对应类别的增强关闭，`1` 时施加完整学习变换。两者作为学习到的条件输入，使频率分解操作融合进网络而非运行时另开昂贵 pass。

### 7.3 手工与自动掩码

- 手工掩码为每个像素提供结构/色调系数，能对角色、hero asset 与背景分别控强度；网络会把对象感知的过渡变得更平滑，但开发者要额外制作掩码。
- 自动掩码把“皮肤”作为学习到的语义组，换成一个只作用于皮肤区域的全局强度参数。报告还指出，在合理范围内，模型会把外星或爬行动物皮肤视作同一语义组；这来自观察，不是一个公开的分类器规格。

## 8. 评测管线与指标方向

```text
109 个对齐 CG 场景
       ├─> DLSS 5
       ├─> GPT Image 2（固定提示）
       └─> Gemini 3 Pro（固定提示）
            ├─ 感知真实感：盲法成对选择
            ├─ RGB 内容/身份：DINOv2 patch、Image LPIPS
            └─ 结构：估计 albedo / normal / depth 后比较
```

注意三种指标回答不同问题：

- 用户研究问“看起来像照片吗？”；
- DINOv2/LPIPS 问“还像原来的内容和身份吗？”；
- albedo/normal/depth 指标问“结构属性是否对齐？”。

把三者合成一个分数会丢失论文最重要的论点：真实感提升和内容保留可以同时发生，但不是同一个目标。

## 10. 敏感性与复现风险清单

### 可观察的控制敏感性

1. `S` 增大：更多表面细节和局部对比变化；过强时更容易暴露输入缺陷或不符合某个游戏的美术语言。
2. `T` 增大：更明显的整体亮度/照明变化；与 `S` 独立调节有利于定位问题。
3. 外观模型切换：改变色调、颜色、植被、皮肤和光照倾向；不是连续、无限的风格空间。
4. 掩码：改变空间或语义覆盖范围；边界质量和掩码制作成本会影响实际体验。
5. 输入分辨率/质量：缺失几何、错误边界和严重锯齿没有可靠的下游修复路径。
6. FP8/FP16 与 GPU kernel：改变速度、数值误差和可用显存；报告只给出当前 Blackwell 优化的量级。

### 复现风险

- 没有公开权重、训练集、训练步数、损失权重、完整层配置和 SDK 代码。
- 154M 参数、8 ms、731 MB 绑定到特定实现、4K 分辨率和 RTX 5090 共享游戏的场景。
- 结构评测使用作者训练的单一属性估计器，估计器误差会进入比较。
- 用户研究排除了 21 次 HUD 偏置判断，基线提示词固定且分别定制；改动这些条件会改变结论。
- 报告没有给出完整消融，无法从公开数字分离“像素空间”“一步扩散”“训练监督”各自的因果贡献。
