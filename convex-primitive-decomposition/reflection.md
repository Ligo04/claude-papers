# 反思与扩展

## 如果我要扩展这篇论文

### 1. 学习最优权重
当前基元类型权重 k(type) 是手动设定的。可以：
- 收集大量模型的"最优分解"（通过搜索得到）
- 训练一个小模型预测 k(type) 和目标 N
- 输入特征：面数、AABB 体积、连通分量数、曲率分布

### 2. 混合方法：基元 + 凸包
对大面积平坦区域用基元（快），对高度凹凸区域用凸包（贴合）。
- 需要一个"何时切换"的判据
- 可以用超量体积阈值：超过阈值的区域回退到凸包

### 3. 语义感知分解
利用模型的语义信息（材质、UV岛、命名约定）：
- 同一材质的面更倾向合并
- 可移动部件自动分离
- 与资产管理 pipeline 集成

## 哪些假设是脆弱的

1. **"物理引擎基元比凸包快"的假设**
   - 随着 GPU 物理加速的发展，凸包碰撞可能变得很快
   - 如果引擎开始优化凸包，本方法的性能优势可能缩小

2. **面邻接拓扑的可靠性**
   - 对于 kit-bashed 资产，面邻接可能不反映几何结构
   - 断开的组件需要特殊处理（已在论文中讨论）

3. **贪心策略的质量**
   - 论文没有证明近似比
   - 对某些病态输入可能严重次优
   - 无法保证输出在全局意义下"好"

4. **单一代价函数的适用性**
   - 超量体积不区分"无害的多余空间"和"填充了通道的空间"
   - 迷宫等模型需要额外的连通性检查

## 在实践中可能失败的场景

1. **薄壁结构**：墙壁两面的法线相反，Q 合并后特征向量可能不稳定
2. **高度对称模型**：多个等代价的合并选择，结果取决于优先队列的实现细节
3. **极大面数**：虽然论文说百万面约 5 秒，但内存使用（每面一个链表节点 + Q）可能成问题
4. **动态场景**：角色动画、可破坏物体等需要运行时更新碰撞体
5. **凹陷区域**：基元必然"填充"凹区域，对于角色站立的平台可能导致不正确的碰撞
