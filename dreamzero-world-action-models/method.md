# 方法 — DreamZero 详解

## 0. 问题形式化

DreamZero 联合预测视频 `o_{l:l+H}` 与动作 `a_{l:l+H}`，条件是：语言指令 `c`、本体感知状态 `q_l`、以及视觉观测（当前与历史）`o_{0:l}`。其中 `H > 0` 是固定时域，`l` 是从轨迹中随机采样的索引。

**核心分解（式 1）**——联合预测 = 自回归视频预测 × 逆动力学模型（IDM）：

```
 π(o_{l:l+H}, a_{l:l+H} | o_{0:l}, c, q_l)
└──────────── DreamZero ────────────┘
   =  π(o_{l:l+H} | o_{0:l}, c, q_l)   ·   π(a_{l:l+H} | o_{0:l+H}, q_l)
     └──── 视频预测 ────┘                └──── IDM（从视觉未来抽动作）────┘
```

不同于用*两个分离*模型（视频预测模型 + 独立 IDM）来建模这个分解，DreamZero 用**单一模型端到端**联合优化——作者认为这通过两模态深度融合带来更好的视频-动作对齐。由于预训练视频模型已在网络规模视频上优化好视频预测，DreamZero 只需额外学会：为机器人本体视频做预测、并从生成视频中抽出对应动作。

## 1. 模型架构

```
                       ┌──────── Causal DiT Blocks（因果自回归 DiT，14B）────────┐
  视觉上下文 o ─► VAE Encoder ─► 视频 latent ┐                                    │
  语言 c     ─► Text Encoder ──────────────┤  联合去噪                            │
  状态 q     ─► State Encoder ─────────────┤  noisy 视频 latent z + noisy 动作 a ─┼─► 视频 latent ─► VAE Decoder ─► 未来帧
  噪声动作   ─► Action Encoder ────────────┘  （teacher forcing：以干净历史为条件）│─► 动作 ─► Action Decoder ─► 动作
                                            └──────────────────────────────────────┘
  训练（左）：每个 chunk 在干净视频上下文条件下去噪带噪的视频与动作 latent
  推理（右）：联合去噪视频+动作 chunk，KV 缓存加速；执行后用【真实观测】替换缓存中的预测帧 → 防误差累积
```

**最小化新增参数。** 为保留视频模型的泛化能力，只引入：state 编码器、action 编码器、解码器。对多视角机器人数据，把所有视角**拼成单帧**，而不改动骨干。

**只对视频模态做自回归。** 目的是避免闭环动作预测带来的误差传播。视频按 **chunk** 预测：每个 chunk 有固定数量的 latent 帧 `K`，与动作时域匹配。分块生成支持变长视频训练（类似 LLM 在变长 token 上训练）。

**为何自回归（AR）优于双向（BD）？**
1. KV 缓存 → 更快推理；
2. 策略可利用视觉观测历史指导下一次生成；
3. 规避双向模型固有的（视频/动作/语言）模态对齐难题——双向扩散通常要定长序列、需视频下采样，扭曲原生 FPS，损害视频-动作对齐。AR + KV 缓存能在单次前向支持任意长上下文，**保留原生帧率**。

## 2. 训练目标：联合流匹配 + teacher forcing

采用**流匹配（flow matching）**。不同于近期一些 WAM，DreamZero **在视频与动作模态间共享去噪时刻**，以在训练初期更快收敛。并采用 **teacher forcing**：在*干净的历史 chunk* 条件下，去噪当前的*带噪* chunk。

给定 chunk 索引 `k > 0` 与去噪时刻 `t_k ∈ [0,1]`，带噪视频 latent `z^k_{t_k}`、带噪归一化动作 `a^k_{t_k}` 定义为干净向量与高斯噪声的线性插值（式 2）：

```
z^k_{t_k} = t_k · z^k_1 + (1 − t_k) · z^k_0 ,   a^k_{t_k} = t_k · a^k_1 + (1 − t_k) · a^k_0
其中 z^k_0, a^k_0 ~ N(0, I)；z^k_1, a^k_1 为干净视频 latent 与归一化动作。
```

> 注意此处约定：t=1 对应干净、t=0 对应噪声（与论文式 2 一致）；同一 chunk 内所有帧共享 `t_k`，不同 chunk 各自独立采样 `t_k`。来自前序 chunk 的干净上下文记为 `C_k = {(z^j_1, a^j_1)}_{j=1}^{k−1}`。

模型 `u_θ` 预测两模态的联合速度，最小化流匹配目标（式 3）：

```
L(θ) = E[ (1/K) Σ_{k=1}^K  w(t_k) · ‖ u_θ([z^k_{t_k}, a^k_{t_k}]; C_k, c, q_k, t_k) − v_k ‖² ]
速度目标：  v_k := [z^k_1, a^k_1] − [z^k_0, a^k_0]
```

`w(t_k) > 0` 是时刻权重函数。训练用**轨迹级更新** + 注意力掩码，使当前噪声 chunk 能 attend 到前序 chunk 的干净上下文。

## 3. 推理：闭环 KV 缓存替换

推理时联合去噪视频与动作 chunk，用 KV 缓存提速。**关键区别于纯视频生成**：闭环设定允许在每次动作执行后，用**真实观测**替换 KV 缓存中的生成帧——消除自回归视频生成固有的复合误差（WAM 独有优势）。作为有状态策略，DreamZero 还能利用视觉历史完成需要记忆的任务（本文未显式评估）。

## 4. 实时执行：从 5.7 秒到 150 毫秒

### 4.1 反应性鸿沟
反应式策略需在几十毫秒内响应。单 GPU 上 DreamZero 朴素实现约需 **5.7 秒/动作 chunk**，三大瓶颈：
1. 平滑动作所需的 **16 步**迭代去噪；
2. 14B DiT 骨干的算力开销；
3. 推理期阻塞机器人运动的串行执行。

### 4.2 异步闭环执行
解耦"推理"与"执行"：运动控制器持续执行*最近*的动作 chunk，推理在后台对最新观测并发运行。延迟约束从"推理必须先于机器人运动完成"放宽为"**推理必须在当前 chunk 用完前完成**"。实验中：动作时域 48 步、30Hz 控制频率（1.6 秒/chunk），故目标推理延迟 ≈ **200ms 以下**即可平滑反应。

### 4.3 系统级优化
- **CFG 并行**：无分类器引导需两次前向（有/无条件），分到两块 GPU → 每步延迟 −47%。
- **DiT 缓存**：利用流匹配中速度预测的*方向一致性*——当相邻速度的余弦相似度超阈值，复用缓存速度，把有效 DiT 步从 **16 降到 4**，对动作预测质量损失极小。

### 4.4 实现级优化
- **Torch Compile + CUDA Graphs**：消除 CPU 开销、融合算子；静态 shape 只在首条轨迹重编译。
- **训练后量化**：Blackwell 上把权重与激活量化到 **NVFP4**，敏感算子（QKV、Softmax）保 FP8、非线性算子保 FP16。
- **Kernel 与调度增强**：注意力用 cuDNN 后端；调度操作迁到 GPU，消除 CPU-GPU 同步停顿。

### 4.5 模型级优化：DreamZero-Flash
即便有系统优化，**去噪步数仍是首要延迟瓶颈**；但天真减步会损害动作质量——残留的视觉噪声会传播到动作预测。

**核心洞见**：推理时动作应去噪到最终值，但其条件是当前 chunk 内*仍带噪*的视频表示（因为极少步去噪时生成的视频 token 仍不准，是带噪条件信号）。标准 DreamZero 训练共享 `t_k ~ U(0,1)`，造成训练-测试错配：训练时模型学的是"视频和动作同噪声水平"，而少步推理要求"视频还噪、动作要干净"。

**Flash 的做法**：训练时把视频时刻偏向高噪声 `t_video_k = 1 − η, η ~ Beta(α,β), α > β`。论文用 **Beta(7,1)**（期望 `E[t_video] = 0.125`，即多数偏噪），动作时刻保持均匀（图 5）。这让模型在训练中就见到"必须从带噪视觉上下文预测干净动作"的配置，直接匹配少步/单步推理。于是去噪步 **4 → 1**，延迟 ~350ms → ~150ms，性能损失极小（表 3）。Flash 通常作为主训练后的*最后阶段*施加。

**动作 chunk 平滑**：把 chunk 上采样到 2× 分辨率，施加 Savitzky-Golay 滤波，再下采样回原分辨率，抑制高频噪声。

### 4.6 累积加速（表 1）
| 优化 | H100 | GB200 |
|---|---|---|
| Baseline | 1× | 1.1× |
| + CFG 并行 | 1.9× | 1.8× |
| + DiT 缓存 | 5.5× | 5.4× |
| + Torch Compile + CUDA Graphs | 8.9× | 10.9× |
| + Kernel & 调度 | 9.6× | 14.8× |
| + 量化（NVFP4） | — | 16.6× |
| + DreamZero-Flash | — | **38×** |

除 DiT 缓存与量化外，所有系统/实现级优化在数学上与基线等价，无可测性能退化。

## 5. 训练配置

- 骨干：**Wan2.1-I2V-14B-480P**（14B 图生视频扩散）。消融用 5B 版对比规模影响。
- AgiBot：100K 步、全局 batch 128；DROID：100K 步、全局 batch 128。
- **更新**所有 DiT 块 + state/action 编码器 + action 解码器；**冻结** text encoder、image encoder、VAE。
- 过滤 idle 动作；默认动作表示用**相对关节位置**。试过 LoRA，效果次优，故全参微调。

## 6. 实现陷阱与复现风险

| 陷阱 | 为什么会坑你 | 论文的处理 |
|---|---|---|
| 视频/动作头朴素拼接 | 会导致视频-动作错配 | 单一端到端模型 + 共享流匹配目标 |
| 对动作也做自回归 | 闭环动作预测误差会传播 | 只对视频模态做 AR |
| 自回归视频复合误差 | 越生成越漂 | 执行后用真实观测替换 KV 缓存中的预测帧 |
| 双向架构 + 视频下采样 | 扭曲原生 FPS，损害视频-动作对齐 | AR + KV 缓存，保留原生帧率 |
| 天真减少去噪步 | 残留视觉噪声传播到动作，质量骤降（83%→52%） | DreamZero-Flash 解耦噪声调度（单步 74%） |
| 串行"推理→执行" | 5.7s/chunk，闭环不可行 | 异步执行，把约束放宽到"chunk 用完前完成" |
| 用重复示范训 WAM | IDM 缺乏多样状态-动作对应，泛化差（33%） | 优先采集多样、非重复数据（50%） |
| 期望"只生成动作不生成视频"会更快 | 14B 规模下步数与 DiT 块数主导延迟，提速甚微；且破坏跨模态对齐 | 保留联合生成，改用 Flash 减步 |
