# NeuralActuator 反思与批判

## 一、如果我要扩展这篇论文

### 1. 学 effort 响应模型，解锁 MPC / 反事实 rollout

这是论文自己点名的最重要缺口（局限 3）。现在模型的输入里**必须含有当前的 effort 遥测**，所以它只能做"记录遥测条件下"的传播，不能预测"如果我发一条还没执行的指令，effort 会变成什么"。这直接堵死了 MPC——因为 MPC 要对候选指令序列做反事实 rollout。

扩展方向：额外学一个 **effort 响应模型** `u_{t+1} = h(q_cmd, s_t, u_t, ...)`，从"指令 + 状态"预测下一步的 effort 遥测。有了它，就能把 effort 通道从"实测输入"变成"内部预测量"，整个系统闭环成一个**纯前向可预测的动力学模型**，可以做 MPC、可以做规划、可以做反事实 what-if rollout。难点在于 effort 响应本身也带着迟滞和历史依赖，可能比学力矩代理还难。

### 2. 多点接触 / 全 6D wrench 估计

现在力头只给末端单一 3D 合力，假设参考点残余力矩可忽略（局限 4）。扩展成：
- **全 6D wrench**：同时估计力和力矩，放开"残余力矩可忽略"的假设。
- **接触定位 / 多点接触**：借鉴 contact particle filter (Manuelli & Tedrake) 的思路，从本体感知反推接触位置，而不只是末端合力。这对沿臂身发生的意外碰撞、抓取时的多指接触都重要。

挑战：更高维的输出需要更丰富的标签，而现在的标签来自固定夹具上的单个 6 轴力传感器——只能测末端、单点。要做多点/全 wrench，标注方案本身得重新设计。

### 3. 视觉监督替代力标签，走向可规模化

论文 IV-J 已经показал了可微渲染 + 轮廓损失能给 NeuralActuator 提供视觉训练信号（IoU 0.8515，但只评了对齐质量，没证明提升 rollout 精度）。这条线的潜力在于：**位姿标签虽然人人都有，但力标签依赖固定夹具 + 6 轴传感器，无法规模化采集。** 如果能用视觉（相机观测的运动、形变、接触）替代物理力标签，数据采集就能从"实验室固定工装"解放出来，走向大规模、野外、多样化。

扩展方向：从视觉形变反推接触力（类似 Visual Haptic Reasoning、Force Map 的思路），把可微渲染管线从"只精修手眼标定"升级到"真正监督力估计"。

## 二、尚存的开放问题

1. **代理的物理语义能否部分恢复？** `τ̄` 现在是纯集总代理，吸收了一切未建模效应。有没有可能通过在前向模型里显式建入负载/接触，让 `τ̄` 逼近可辨识的真实力矩？这会牺牲仿真器的简洁性，但换来可解释性和跨任务迁移性——值得研究这个权衡曲线。

2. **分布外泛化的边界在哪？** 论文只在 261 g 和 226 g 两个未见物体上做了很有限的泛化测试（预测力 2.80/2.40 N vs 真值 2.56/2.21 N）。对未见形状、未见接触方向、未见速度域的系统性泛化能力没有刻画。

3. **平台间迁移是否可能？** 现在每个平台（OMX/SO-101/Franka）都从头训练。执行器家族之间（DYNAMIXEL / STS3215 / Franka）有没有可迁移的共性表征？能不能预训练一个"舵机基础模型"，新平台只需少量微调？在线自适应（12 条轨迹 356 s）暗示了这个方向，但只是同平台内的自适应，不是跨平台迁移。

4. **门控与小力的根本矛盾。** ≤50 g 在噪声底之下（局限 5）。这到底是算法问题还是传感器物理下限？如果是后者，任何算法改进都撞墙——需要诚实地区分"能靠更好的模型解决"和"必须换硬件"。

## 三、哪些假设是脆弱的

### 1. recorded-telemetry conditioning（记录遥测条件）
离线评估喂的是**完整记录下来的 effort 遥测序列**，所以报告的多步结果是"记录遥测条件下的传播"，不是对未来的真正预测。这让离线数字看起来比真实在线部署乐观。在线部署虽然严格因果，但每一步都依赖实时遥测到达，一旦遥测有延迟/丢包/噪声，因果链就受影响。**这个假设让论文的强结果和真实闭环性能之间存在一道未完全跨越的鸿沟。**

### 2. Franka 的 `q̃_cmd = 1.03·q_rec(t+5)` 代理
Franka 实验里，指令位姿通道用了一个**依赖未来记录状态**的平滑代理（`1.03` 倍的未来第 5 步记录位姿）。论文诚实标注了这让 Franka 结果成为"future-state-conditioned 离线基准而非在线评估"。这意味着 Franka 那组漂亮的力估计数字（F MAE 0.26–0.42 N）**不能直接等同于在线可达性能**——它偷看了未来。跨平台的说服力因此打了折扣。

### 3. 无负载前向模型
OMX 的接触/负载实验，训练和评估都用无负载模型 + 关闭接触。这是个强假设：所有负载/接触物理都被塞进 `τ̄`。只要负载/接触的效应能被一个"等效关节输入"充分近似，就成立；一旦出现**关节输入无法等效表达**的效应（比如接触改变了系统的约束结构、或强耦合的多体接触），这个假设就会失真。

### 4. 力标签依赖固定夹具传感器
所有力标签来自安装在**固定刚性工装**上的 6 轴力/力矩传感器。这限制了：(a) 只能测末端、单点、准静态为主的接触；(b) 数据采集必须在实验室工装内进行，无法规模化；(c) 快速动态下的力（含物体惯性、抓取摩擦）标签本身就不准——论文明确说负载参考 `[0,0,-mg]` "在运动中只是名义监督，不考虑物体惯性和抓取摩擦"。**力头的训练质量受限于这个标注方案的物理局限。**

## 四、实践中可能在哪里失效

### 1. 硬件老化 / 分布漂移
舵机的摩擦、背隙、齿轮磨损会随使用时间演化。模型是在某个时间窗口的数据上训的，当硬件老化后，"电流→等效力矩"的映射漂移，模型精度会退化。论文的在线自适应（12 条轨迹、356 s、跟踪误差降 44%）是缓解手段，但它是**被动响应式**的——需要人察觉到退化并主动触发重标定。没有自动的漂移检测机制。

### 2. 温度域外
输入含线圈温度 T，但训练数据覆盖的温度范围有限。长时间高负载运行导致舵机过热、进入训练分布之外的温度域时，热漂移改变力矩特性，模型可能给出系统性偏差的力估计。这在连续作业场景（工厂、长时演示）里是现实风险。

### 3. 高速动态
数据以准静态、中低速运动为主（负载参考用的是静态 `-mg`，运动中承认不准）。高速运动时：(a) 物体惯性力显著，而力标签没建模惯性；(b) 舵机动态（电气时间常数、饱和）更突出；(c) 长视野 rollout 误差累积更快。模型在高速动态下的力估计和轨迹精度都可能明显劣化。

### 4. ≤50 g 小力
~0.5 N 以下在平台噪声底之下（局限 5）。轻柔操作（抓易碎物、精细装配、轻触探测）恰恰需要这个量级的分辨率，而这正是模型最不可靠的区间。接触门在这个区间也可能误开/误关。**想用它做"轻柔力控"的实践者会在这里撞墙。**

### 5. 遥测质量依赖
整个方法建立在"能读到 effort 遥测（电流/负载寄存器/指令力矩）"之上。如果目标平台的遥测通道噪声大、采样率低、或存在通信延迟（多drop 总线拥塞），输入质量下降会直接冲击力矩代理和力估计。不同舵机厂商的遥测质量参差不齐，换一款便宜舵机可能就不 work。

---

**总评**：这是一篇立场清醒、自我批判充分的工程论文——它没有假装 `τ̄` 是真力矩，没有假装离线数字等于在线性能，把每个"偷看未来"和"吸收未建模效应"的地方都标注了出来。它最脆弱的地方不在方法本身，而在于**评估协议与真实闭环之间的距离**（recorded-telemetry / future-state-conditioned）以及**力标注方案的物理天花板**（固定夹具、准静态、单点、≥50 g）。真正把它推向实用，最该攻的是 effort 响应模型（解锁 MPC）和视觉监督（解锁规模化力标签）这两条线。
