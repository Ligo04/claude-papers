## 基础题(Basic)

### Q1. 这篇论文的一句话核心贡献是什么?

<details>
<summary>答案</summary>

把"**仿真器在环(simulator-in-the-loop)**"的推理时优化范式**首次落地到真实世界的布料操作**,且只用**单张 RGB** 输入。构建了一个 real-to-sim-to-real 闭环,由 FLASH 仿真器 + RGB-native real-to-sim 模块 + 先验引导 MPPI 三支柱组成。据作者所知,这是第一个在实时机器人控制预算下直接用可变形仿真器作为推理时前向模型来做布料操作的框架。

</details>

---

### Q2. 三根支柱分别是什么?

<details>
<summary>答案</summary>

1. **(i) 仿真后端 FLASH**:可扩展合成数据生成 + 推理时并行 rollout 引擎,在物理保真度/数值稳定性/rollout 效率间平衡。
2. **(ii) RGB-native real-to-sim 模块**:纯合成数据训练,把单 RGB 映射为仿真兼容布料状态(融合冻结 DINOv2 特征 + 可学习 canonical tokens)。
3. **(iii) 先验引导 MPPI 控制器**:稀疏网格 rollout 后端 + 锚定离线蒸馏策略轨迹的 MPPI,在线精修名义动作。

</details>

---

### Q3. 为什么模仿学习/基础模型策略在部署布料操作时不够可靠?

<details>
<summary>答案</summary>

这些策略在部署时**缺乏自我纠错能力**。感知、抓取选择、时序、动作预测中的小偏差,会经由**接触丰富的布料动力学累积**,把系统逐渐推离目标状态。因此可靠的布料操作需要一个**推理时机制**来精修策略提议、从累积误差中恢复 —— 这正是本文的仿真在环精修要解决的。

</details>

---

### Q4. 为什么用单 RGB 而不是深度/点云来估计布料状态?

<details>
<summary>答案</summary>

① **薄织物对深度传感很困难**(thin fabric remains difficult for depth sensing);② 几何-only 的观测**丢失纹理线索**(discard texture cues);③ 近期基准也显示布料感知存在持续的 sim-to-real gap。RGB 保留纹理、避开薄织物深度难题;本文靠 DINOv2 预训练特征 + canonical tokens + 合成训练 + 强增广把单 RGB 提升为仿真兼容 3D 状态。Table 2 显示其误差比点云 DPM、深度 DeFM 都低,且延迟最快。

</details>

### Q5. 论文选了哪个仿真器?对比了哪些?关键结论是什么?

<details>
<summary>答案</summary>

选 **FLASH**。对比了 Genesis、Newton、Isaac Sim、FLASH(同一折叠任务 + 同一 MPPI 控制器,K=64–512 并行)。结论(Table 1):FLASH 在所有 K 下成功率 **95–100%**,而 Isaac Sim/Newton **低于 60%**,per-vertex MSE 和 EMD 低约一个数量级;Isaac Sim 每步快 1.5–1.9× 但最终状态保真差;Newton 偶发数值不稳定;Genesis 无法稳定折叠被排除。**启示:稳定性与最终状态保真比每步速度更决定闭环成功率。**

</details>

## 进阶题(Intermediate)

### Q6. canonical tokens 是什么?它如何处理布料的自遮挡?

<details>
<summary>答案</summary>

**canonical tokens** 是 N 个可学习 token,**每个对应 rest-shape 网格的一个材料顶点**,在训练中编码该物质点的持久身份与标准位置。它们与 M_v 个 DINOv2 视觉 token **拼接后一起过自注意力**:每个 canonical token 既从图像聚合视觉证据,又与其它顶点 token 交换结构上下文,最后取前 N 个输出经共享 MLP 解码出 3D 形变位置(式7–8)。

**处理自遮挡**:被遮挡的顶点缺乏直接视觉证据,但可借助①其它可见顶点的结构上下文、②canonical token 编码的标准位置先验来推断 —— 注意力机制让信息在顶点间传播,从不完整观测恢复完整状态。

</details>

### Q7. 写出先验引导 MPPI 的四步,并解释"先验引导"为何重要。

<details>
<summary>答案</summary>

四步(式10–13):
1. **采样**:在名义序列 Ū_t 附近采 K 条候选 `U^(k)=Ū_t+ε^(k), ε~N(0,Σ)`。
2. **rollout**:每条在 FLASH 并行仿真 `τ^(k)=F_{0:H}(ŝ_t,U^(k))`,赋代价 S(τ^(k))。
3. **加权**:`w_k = softmax(−S/λ)`(温度 λ)。
4. **合成 + 执行**:`U*_t=Σ w_k U^(k)`,滚动时域执行首动作 U*_t[0]。

**为何重要**:布料状态高维、几何目标非凸,**无引导采样极低效**,以往只能退化为开环原语或大随机化策略。以离线策略的名义轨迹为**锚点**做局部采样,把搜索集中到任务相关的动作邻域,使**单 GPU 有限 rollout 预算**下也能产出高质量精修。

</details>

### Q8. real-to-sim 模块为什么能"纯用合成数据训练"还能在真机工作?

<details>
<summary>答案</summary>

三方面支撑:
1. **冻结 DINOv2**:用其在海量真实图像上预训练的通用视觉特征,本身就缩小 sim-to-real 视觉鸿沟,只训练投影层/canonical tokens/注意力/解码器。
2. **相机姿态对齐**:合成渲染相机姿态匹配真机标定,几何上一致。
3. **鲁棒增广**:输入级图像空间随机化 + 隐层级视觉 token 加噪与掩码(含**随机抓取点掩码**),迫使模型从不完整/损坏视觉证据推断,提升对真机视觉漂移的鲁棒性。

</details>

### Q10. FLASH 在闭环里扮演"双重角色",是哪两个?

<details>
<summary>答案</summary>

① **离线**:提供**合成监督**(渲染图 + GT 顶点)来训练 real-to-sim 模块,并**定义仿真兼容的状态空间**(rest-shape 网格顶点);
② **在线**:作为 MPPI 的**推理时 rollout 引擎**,对候选动作序列并行仿真。

正因这双重角色,FLASH 的物理保真度、数值稳定性、rollout 效率**直接决定整个管线性能** —— 训练用的状态空间和推理用的前向模型是同一个仿真器,保证 real 与 sim 的状态表示一致。

</details>

## 高级题(Advanced)

### Q11. 论文主张"仿真器本身是最自然的前向动力学模型",相比"用仿真数据训练学习型动力学模型",这样做的利弊各是什么?

<details>
<summary>答案</summary>

**利**:① 避免任务/资产特定的动力学训练;② **去掉学习型预测器的额外近似误差**(学习模型只是仿真的有损拟合);③ 可作跨可变形资产的**通用**物理推理引擎(换布不重训动力学);④ 不被训练分布与源仿真器绑定。

**弊**:① 物理仿真**每次 rollout 成本高**,而学习型模型(如扩散动力学)单次 rollout 更便宜;② 仿真器必须**够快够稳**才能在线用,把压力转移到仿真器选型与优化上;③ 可变形仿真**并行性差**,单 GPU 下 batch size 受限,封顶控制频率(§6 局限)。

本文的下注是:只要选对仿真器(FLASH)并用稀疏网格,保真度收益 > 速度损失。

</details>

### Q12. 闭环控制频率受什么因素上限约束?为什么布料比刚体更受限?

<details>
<summary>答案</summary>

控制频率 ≈ 1 / (单步 real-to-sim + MPPI 的 K×H 步 rollout 时间)。其中主导项是 **MPPI 并行 rollout 的可达 batch size**,而 batch size 上限来自**单 GPU 显存/算力预算**。

**布料更受限的原因**(§6):可变形动力学的求解**远不如刚体可并行** —— 刚体每个物体状态紧致(如 6D 位姿),而布料是数百顶点的耦合非光滑接触系统,稀疏矩阵求解 + 接触迭代难以像刚体那样大规模并行。于是 rollout 容易**饱和单 GPU 预算**,batch size 上限直接封顶闭环控制率。未来方向是多 GPU 分布式 rollout + 后端优化。

</details>

### Q13. 用稀疏网格做 rollout 是一个关键权衡,它在交换什么?如果网格过密或过疏会怎样?

<details>
<summary>答案</summary>

稀疏网格在交换:**状态粒度/动力学保真 ↔ 并行候选多样性 + rollout 速度**。论文论证只要保留"操作相关"的形变与接触即可,无需全分辨率。

- **过密(N 太大)**:每步仿真更贵 → 同样 GPU 预算下 K(候选数)和 H(时域)被压缩 → 采样多样性不足,MPPI 探索差;且 real-to-sim 要回归更多顶点,延迟上升。
- **过疏(N 太小)**:丢失操作相关的局部形变与接触细节 → 仿真孪生与真实布料偏离 → rollout 代价排序失真,精修方向错;状态估计也无法表达精细褶皱。

网格粒度(remeshing 目标)= canonical token 数 N,是平衡保真与并行的核心旋钮。

</details>

### Q14. 先验引导 MPPI 依赖一个"足够好"的基础策略。如果基础策略严重错误会发生什么?这暴露了什么假设?

<details>
<summary>答案</summary>

先验引导是在 Ū_t **附近**做高斯**局部**采样(Σ 控制小邻域)。若基础策略的名义轨迹离正确解太远,候选都集中在错误邻域,rollout 再准也**跳不出去** —— 精修无法把全局错误的提议救回来。

这暴露的假设:**基础策略至少在正确解的"采样可达邻域"内**。证据见 Table 3:去掉 MPPI 只用基础策略仍有 1–3/10 成功,说明先验本身携带了大部分任务结构;反过来,若先验完全错误,局部精修收益有限。

**潜在改进**:自适应增大 Σ 或退火式采样以扩大探索、用多模态/有偏提议、或在检测到高代价时触发全局重采样 —— 但都会增加 rollout 预算压力。

</details>

### Q15. 该框架对"全新衣物"的泛化受限于哪两个 per-asset 阶段?作者设想如何消除?

<details>
<summary>答案</summary>

两个 per-asset(每件衣物各做一次)阶段(§6):
1. **离线布料网格重建**:为每个 garment 从 RGB-D 重建固定拓扑 rest-shape 网格(SAM2 分割 → 点云 → ball pivoting → remeshing)。
2. **per-garment 训练的 real-to-sim 模块**:当前 f_θ 是逐件衣物训练的。

换新衣物就要重做这两步,不能即插即用。这也是为什么 Table 4 的泛化是在"已构建资产"上做折叠变体/扰动,而非任意陌生衣物。

**作者设想**:用**图像条件的网格基础模型**(从单张观测直接产出仿真兼容资产),配一个**类别级 real-to-sim 模块**(去掉 per-garment 训练步)。两者结合可望实现对新衣物的零额外训练泛化。

</details>
