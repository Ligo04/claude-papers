# MotionBricks — 总结

## 背景

运行时交互式动作控制是动画和机器人领域的基础支柱。传统方法依赖**动画图(Animation Graphs)**——由预录制动作片段组成的层级状态机。例如《刺客信条》需要管理超过 15,000 个动画、5,000 个状态和 12 层嵌套图，使得高质量行为系统几乎成为大型工作室的专属能力。

近年来，生成式模型在动作合成领域取得了突破性进展，但面临两个核心障碍：
- **扩散模型**：质量优秀但推理太慢（数秒到数分钟），无法实时
- **文本驱动模型**：缺乏工业级应用所需的细粒度控制

## 问题陈述

如何构建一个系统，同时满足：
1. **实时可扩展性**：单一模型实时生成海量动作技能（35万+片段）
2. **细粒度多模态控制**：支持速度指令、风格选择、精确关键帧等多种控制模态
3. **零样本泛化**：无需微调或任务特定标注即可适配新的下游任务

## 主要贡献

### 1. 模块化潜在生成骨干网络
- **结构化多头 Tokenizer**: 用 K 个独立码本沿特征维度分别量化，容量可扩展到 10^9 token
- **Root-Pose 解耦**: 编码器仅编码姿态，根轨迹作为条件注入解码器
- **渐进式粗到细生成**: Root Module → Pose Module → Decoder 三阶段流水线

### 2. 智能原语 (Smart Primitives)
- **Smart Locomotion**: 临界阻尼弹簧模型 + 神经根轨迹精炼 + 风格关键帧
- **Smart Object**: 意图关键帧（硬/软约束）+ 交互绑定（检测、插槽、锚定）

### 3. 机器人部署
- 在 Unitree G1 人形机器人上通过物理跟踪控制器实现真实世界全身控制

## 关键结果

### 性能指标 (350k 数据集)

| 指标 | MotionBricks | 最佳基线 |
|------|-------------|---------|
| FPS | **15,000** | 27,000 (Cond. Inbtwn., 但质量极差) |
| 延迟 | **2ms** | 15.3ms (Closd-DiP) |
| FID ↓ | **1.054** | 1.201 (CondMDI+CFG) |
| 人类评估胜率 | **86.5%** | 19.9% (MMM) |
| 人类评分 (1-5) | **4.06** | 3.21 (MMM) |
| 到达成功率 | **99.6%** | 87.7% (Cond. Inbtwn.) |
| 脚部滑动 ↓ | **0.003** | 0.004 (MMM) |
| 关节抖动 ↓ | **3.38** | 5.40 (MMM) |

### 跨数据集一致性
- 在 HumanML3D、LaFAN1-G1、70k 子集上均取得最优或接近最优
- 唯一同时在速度、质量、精度三方面全面领先的方法

### 工程规模
- 训练: 32 GPU (H100), 约 17 天 (tokenizer 7天 + root 3天 + pose 7天)
- 模型: Tokenizer 23.5M + Root Module 50M + Pose Module 150M 参数
- 数据: 700 小时动捕数据, 350k 片段, 9,300 个技能, 36 个类别, 163 名表演者
