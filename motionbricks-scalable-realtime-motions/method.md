# MotionBricks — 技术方法详解

## 整体架构

MotionBricks 的推理流水线包含四个阶段：

```
Stage 0: Smart Primitives    用户指令/游戏事件 → 关键帧约束 T
         ↓
Stage 1: Root Module          约束 T → 帧数 T2 + 根轨迹 {r_g}
         ↓
Stage 2: Pose Module          根轨迹 + 约束 → 多头姿态 token {z_q}
         ↓
Stage 3: Token Decoder        token + 根轨迹 + 关键帧 → 连续动作
```

## 1. 状态表示

每帧动作状态为六元组 (r_g, r_l, p, q, v, c)：
- **r_g** (全局根): 骨盆关节的投影全局位置 + 朝向角的 cos/sin
- **r_l** (局部根): 骨盆的位置速度和角速度（全局坐标）
- **p** (关节位置): 所有关节的全局坐标位置（相对于根位置）
- **q** (关节旋转): 所有关节的全局坐标旋转（避免 heading canonicalization 问题）
- **v** (关节速度): 全局坐标系下的速度
- **c** (接触标签): 脚部接触地面标签

关键设计决策：使用全局坐标表示旋转和位置，不做 heading canonicalization，而是通过随机旋转增强来学习所有方向的动作。这样可以正确处理爬行、翻转等非标准动作。

## 2. 结构化多头 Tokenizer

### 编码器

仅编码姿态信息（不包含根），将 T 帧降采样为 T/4 个 token：

```
{z_e^t} = enc({p^t, q^t}, t=1..T)
```

采用 1D 卷积或 Transformer，以 2x 和 4x 的速率逐步降采样。

### 多头量化

连续嵌入 z_e 沿特征维度被 K 个独立码本分别量化：

```
z_q = [z_q,1; z_q,2; ...; z_q,K]

其中 z_q,k = argmin_{e_k in E_k} ||z_e,k - e_k||^2
```

与手动按身体部位划分不同，网络自主学习特征分解方式。

**优势对比**:
- 单头 16,384 tokens → 16,384 种表达
- 多头 K=4, 每头 256 → 256^4 = 4,294,967,296 种组合
- 多头的码本利用率更高，且单头预测错误时优雅退化

### 解码器

逐步上采样（4x → 2x → 1x），在每层通过 skip connection 注入：
- 根轨迹条件（时间维度对齐后拼接）
- 关键帧约束（稀疏，零填充到长度 T）
- 可用性布尔掩码决定使用关键帧嵌入还是隐藏状态

```
{r_l, p, q, v, c} = dec({z_q}, {r_l_hat}, {p_check}, {q_check})
```

### 训练

使用标准 VQ-VAE 量化损失 + running-mean codebook update。训练时随机采样 0-10 个关键帧约束注入，增强泛化性。也支持 FSQ tokenizer（性能相似）。

Tokenizer 架构：U-Net，每层 3 个残差 1D 卷积块，1024 通道，约 23.5M 参数。

## 3. Root Module

两步设计：

### Step 1: 时序预测
- 输入: 16 个可学习帧槽嵌入 + 关键帧约束全局嵌入 f(T1,T2,T3) + 时序嵌入 g(T1)
- Transformer 编码器输出帧数分布（4帧分辨率）
- 推理时采样或 argmax 得到预测帧数 T2
- 支持 bit-wise masking 控制有效帧数范围

### Step 2: 条件根轨迹估计
- Step 1 的中间帧槽嵌入传入 Step 2
- 掩蔽超出预测帧数的嵌入
- 时序 Transformer 预测初始根轨迹

```
{h2}, T2 = F1({h1}; g(T1); f(T1,T2,T3))
{r_g}  = F2({h2}; g(T2); f(T1,T2,T3))
```

Root Module: 512 嵌入维度, 12 注意力头, 约 50M 参数。

## 4. Pose Module

框架中最大的 Transformer，建模姿态 token 分布。

帧槽嵌入编码三类信息：
1. 局部/全局根值 r_l, r_g
2. 局部姿态关键帧约束 p, q
3. 姿态 token 嵌入（训练时余弦调度混合真值和掩码；推理时全部初始化为掩码）

采用 masked token modeling 策略，基于置信度迭代预测。实践中单次前向传播即可生成高质量动作。

```
{h_p} = P(phi({r_l}; {r_g}; {z_q}))
p(z_q,k^t) = softmax(f_k(h_p,k^t)),  k = 1, ..., K
```

Pose Module: 1024 嵌入维度, 16 注意力头, 16 层, 约 150M 参数。

## 5. 灵活的约束处理

核心设计：所有模块接受**任意子集**的约束。

约束集 T = {T1, T2, T3}：
- T1: 局部根约束
- T2: 全局根约束
- T3: 姿态约束

Context 关键帧（帧 0-3）始终可用，Target 关键帧（帧 4-7）按任务变化。未提供的约束用**可学习掩码嵌入**替代。

支持 12-64 帧（30 FPS）的 in-betweening 片段。

## 6. Smart Locomotion

### 临界阻尼弹簧模型

```
r(t) = e^{-gamma*t} * ((r0 - r_g1) + (v0 + gamma*(r0 - r_g1))*t) + r_g1
```

设 t=1.0s 得到弹簧平滑目标 r_g2。

### 风格控制

通过在弹簧平滑轨迹上放置参考风格关键帧实现。无需手动对齐步态相位。

### 神经根轨迹精炼（四阶段）

| 阶段 | 符号 | 描述 |
|------|------|------|
| 朴素外推 | r_g1 | 速度 x 时间直接外推 |
| 弹簧平滑 | r_g2 | 临界阻尼弹簧消除突变 |
| Root Module | r_g3 | 神经网络融入风格和时序 |
| Decoder | r_g4 | 结合全身细节最终微调 |

## 7. Smart Object

### 意图关键帧
- 每个交互行为由多组关键帧定义
- **硬约束** (tau=0): 必须完全到达目标姿态（如攀爬手部接触）
- **软引导** (tau>0): 可提前 tau 帧过渡到下一阶段
- 布尔标志 omega: 是否围绕交互枢轴旋转关键帧

### 交互绑定
1. **检测**: 从物体几何体派生碰撞触发体积
2. **插槽与放置**: 便携物体的附着点和释放逻辑
3. **关键帧锚定**: 世界变换作为枢轴锚定和旋转关键帧

## 工程细节

- **UE5**: 插件系统，ONNX + TensorRT (C++)，内置 retargeter 实时重定向
- **机器人**: Jetson Orin，ONNX + TensorRT，5ms 延迟，10Hz 重规划
- **训练**: 32 GPU (H100)，batch 256/GPU，Adam lr=5e-5 cosine schedule，2M steps
