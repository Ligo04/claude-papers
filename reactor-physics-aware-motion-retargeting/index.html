Overview

Core Problem: Motion capture data from human actors doesn't work well for simulated characters with different body proportions, causing foot sliding, penetration, and physically impossible motions.

Main Innovation

Bilevel Optimization Framework

ReActor jointly optimizes two interdependent objectives:

  • Upper level: Adapt reference motion to be physically plausible
  • Lower level: Train RL policy to track adapted motion

Key Concepts

1. The Embodiment Gap

When motion capture data is retargeted from a human actor to a simulated character with different:

  • Mass distribution
  • Limb proportions
  • Joint limits
  • Actuator constraints

The resulting motion may be kinematically valid but physically infeasible.

2. Bilevel Optimization

Upper level (motion adaptation): min_θ L_motion(θ, π*(θ)) Lower level (policy training): π*(θ) = argmin_π L_tracking(π, θ)

The upper level's objective depends on the lower level's solution, creating a nested optimization problem.

3. Simplified Gradient Estimate

The Innovation

Instead of computing expensive inverse Hessians, ReActor uses:

∇_θ L ≈ ∇_θ L_motion + λ · E[∇_θ log π(a|s) · A(s,a)]

This approximation makes bilevel optimization tractable for deep RL.

4. Sparse Parameterization

Constant Offsets

Same offset applied to all frames

114 parameters for 34-DOF humanoid

vs Per-Frame

Different offset for each frame

34,200 parameters for 300 frames

Result: 100× fewer parameters, better generalization across motions

Technical Method

Retargeting Parameterization

Step 1: Nominal Retargeting

Standard kinematic retargeting (position matching, orientation transfer)

Step 2: Learnable Offsets

Per-joint rotation offsets (axis-angle) + end effector position offsets

Step 3: Apply Constant Offsets

Same offsets for all frames (sparse parameterization)

RL Setup

State Space

  • Joint positions & velocities
  • Root orientation & velocity
  • Reference motion
  • Contact information

Action Space

  • PD controller targets
  • Joint torques computed
  • Respects actuator limits

Reward Function

  • Pose tracking (50%): exp(-2·||q - q_ref||²)
  • End effector (30%): exp(-10·||p_ee - p_ref||²)
  • Velocity matching (10%): exp(-0.1·||q̇ - q̇_ref||²)
  • Contact consistency (5%): -|c - c_ref|
  • Smoothness (3%): -||a_t - a_{t-1}||²
  • Torque regularization (2%): -||τ||²
