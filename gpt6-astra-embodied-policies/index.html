先抓住核心问题

Astra 可以生成数值动作，但完整机器人行为还要经过 action interface、policy/PD/whole-body controller 和 evaluator。论文把同一个模型放进六类任务，用 Direct 和 Hybrid 拆开“模型决策”和“下游执行”的贡献。

准确读法：Hybrid 48% 是 Astra + π0.5 + EEF interface 的系统结果；不能写成 Astra 独立完成了 48% 的 RoboDojo。

为什么 Hybrid 有用

π0.5、RL 或 whole-body controller 提供连续动作先验，Astra 负责目标偏差、接触前置条件、任务顺序和恢复。RoboDojo 中只 14.4% 的执行步由 Astra 生成/修正，却把 Hybrid success 提到 48%。这支持“少量局部纠正可能很值钱”，但不代表模型调用很少。

为什么 Direct 在灵巧手上难

Direct 需要同时控制保持支撑的手指和重新建立接触的手指。Astra 有时能维持抓握，却不能持续旋转；cylinder at-goal rate 0.51%、cuboid 4.40%，远低于 RL 的 76.90%、63.50%。

论文没有证明什么

  • 没有证明 Astra 独立替代 learned policy 或 whole-body controller。
  • 没有证明 39.86 s 平均 call latency 满足实时控制。
  • 没有把 5 次 locomotion attempt 外推成所有运动任务的失败率。
  • 没有把一次 diagnosis 成功等同于可靠 online learning。

复现护栏

  • 保留每个 task 的 observation、interface、horizon 和 seed。
  • 固定 paired starts，并报告失败类型和预算耗尽。
  • 把 Direct、Hybrid、policy-only 分开评估。
  • 同时报告 success、介入率、tokens、requests 和 wall-clock。

快速自测

为什么 RoboDojo 的 85.6% 不是“只调用 14.4% Astra”？

它统计的是已执行 physical control steps 的来源。Astra 仍审核每个 proposal，model calls 和 tokens 可能很高。

为什么 HM3D 82% 还要看 SPL？

SR 只表示到达，SPL 还反映路径效率。论文中的 82% SR 配 43.69 SPL，说明搜索绕路明显。

为什么 HumanoidBench 结果不能只写“Astra return 581.9”？

这是 Astra + 冻结 whole-body controller 的平均 native return；各 task 的尺度和阈值不同，且下游 controller 承担了身体协调。

这篇论文最值得迁移的工程模式是什么？

把推理模型放在可审计的低频决策层，保留高频 policy/controller，并记录每次介入的原因、动作来源和三套时钟。
