# 研究反思与延伸

以下是阅读后的研究设想，未在本包实现，也不是论文实验结论。

## 1. 从 GPU 数据驻留到主机无同步

所查版本仍读回 cutting 数量与树层数量。可以研究固定上界 launch + device 计数屏蔽、持续 kernel、设备任务队列或适用的 graph 方案。应先用 Nsight 测量这些同步在小网格批处理中的占比，再决定是否值得增加 kernel 复杂性。不能凭静态调用次数推算收益。

## 2. 更好的候选，而非更深的树

Table 4 的深度 3 几乎不改善部件数却显著增加时间，提示可以优先研究候选去重、按凹边几何重要性分配预算、学习式 proposal。实验要在相同总候选评估次数或相同 wall time 下比较，防止把更多计算包装成更好算法。

## 3. 面向接触任务评估

在把手穿越、插接和夹持场景中，度量物体能否通过、接触法向误差和稳定抓取率。统一平均凹度可能遗漏任务关键区域。需要保留更密的独立误差评估，不应仅用训练/搜索过程中同一批表面采样。

## 4. 长期资产服务

测试 context 长期复用、多种尺度网格交替、有限 pool、并行请求与 OOM 后可恢复性。记录实际进程预留显存、内部高水位和泄漏，而不是只用一个 memory 数字。设备端相邻块合并无法消除所有跨 arena 碎片。

## 5. 最脆弱的假设

流形边界恢复、可靠体积、采样 Hausdorff 的覆盖、整数坐标量化、候选空间覆盖和 sticky heap 容量都可能成为真实资产的失败来源。论文 benchmark 零失败是一项有范围的经验事实。

本机没有运行官方 CUDA 部件或完整分解；这些问题只能作为后续可检验的假设。
