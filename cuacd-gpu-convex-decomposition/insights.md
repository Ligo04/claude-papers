# 核心理解与判断

## 一个 warp 负责一件几何工作

传统思路常先问“每个顶点交给哪个 thread”。CuACD 先划出独立候选，再让一组 32 个 lane 合作完成候选里的局部阶段。三角形很多时以 stride 32 扫描；输出长短变化时用 ballot 和 popcount 压缩；元数据更新可交给 lane 0。粗层候选并发和细层 lane 协作各司其职。[论文 §3]

这里的 warp 是 CUDA 硬件线程组，不是 NVIDIA Warp Python 框架。也不意味着每个 CUDA kernel 都只含一个 warp；公开代码的 launch 还能看到 64/128 threads 的 block。描述粒度要落到具体组件。[源码观察]

## 融合为什么依赖内存分配

一刀切下去，新增多少交点、多少封口三角形，运行前并不知道。只有计算移到 GPU，主机仍可能为了拿到数量、申请缓冲区而同步。设备端 heap 允许生产者阶段当场申请结果空间，并把指针交给后续阶段。因此 allocator 是融合的组成部分，而非一个可独立替换且与架构无关的小优化。[理解推导]

融合主要减少阶段边界，并不能让负载不平衡消失。warp 之间仍可能有长尾，寄存器保存的中间状态也更多。论文报告主要 kernel occupancy 25–50%，并指出寄存器压力；低 occupancy 本身既不能证明算法差，也不能证明已经达到硬件上限。

## “更快”与“更好”来自不同证据

凹边候选让切平面更容易落在结构凹陷处。更好的候选可以让浅搜索胜过单纯深搜。CPU 控制实验也获得接近的部件数，说明质量收益不应归因于“GPU 天然更聪明”。而 CPU 改版仍约 20.85 s，CuACD 为 0.23 s，支持系统实现是大部分速度差距的来源。[§5.3]

## 两种便宜替代，边界不同

搜索中用体积残差半径代替完整凹度，属于速度与搜索精细度的折中；最终需要完整的采样 Hausdorff 检查。方向极值预筛选则利用几何包含关系：见证点构成的内部凸包里，严格内部点不可能成为外部凸包顶点，因此可以安全删去。前者可能影响选刀质量；后者在正确谓词/坐标表示下不改变最终凸包。[§4.1、4.3]

所谓 exact hull 仍要关注整数坐标映射与量化；不要把整数谓词的稳定性直接扩展成对无限精度原始实数的绝对精确。

## 与相关方法的定位

| 方法 | 主要工作 | 控制与计算特点 | 本文能支持的判断 |
|---|---|---|---|
| V-HACD 方法 | 体素化与递归切分 | 常用几何近似路线 | 本文 Table 1 的 V-HACD 是数据集名，不是该列里的算法基线 |
| CoACD | 碰撞感知凹度 + MCTS | 搜索式 CPU 基线 | CuACD 继承凹度，改变候选与系统实现 |
| VisACD | 可见性凹度 | GPU/OptiX 加速评分，切割与 hull 仍在 CPU（按本文描述） | 单阶段 GPU 化与完整几何流水线加速的比较 |
| CuACD | warp 几何组件 + heap + 凹边候选 | 重几何计算在 GPU；所查源码仍有 host 控制 | 加速证据很强，但“零同步”叙述需单独核查 |

论文并非证明所有 ACD 首次上 GPU；相关工作也列出 GPU 动态破碎。作者的新颖性陈述针对其完整搜索式分解系统，应带着这个语境理解。

## 对仿真资产流程的意义

对 ManaEnv / IsaacLab 一类流程，最直接的候选用途是批量 collider 生成、资产迭代与预处理服务。[工程推断，未集成验证]

分解用时下降不会自动带来仿真 FPS 同倍提升。运行时碰撞成本仍受凸部件数、凸包顶点数、接触对、引擎 cooking 限制和场景布局影响。验证时应分别记录预处理、分解、凸包导出、引擎 cooking、加载、运行时接触性能，并固定缩放与阈值。

长期 GPU 服务还应关心 sticky heap：论文写 70%、所查源码实际为 80% 空闲显存的默认预留对训练/渲染共用 GPU 可能不合适。应显式设置 pool 并验证长期复用、碎片和失败恢复；这属于接入建议，不是本文已经完成的结果。

## 最需要保留的边界

- 同一目标阈值不等于每个输出都满足解析误差界。Hausdorff 是采样估计；Table 5 甚至报告最大凹度 0.059，大于 0.05。
- 作者报告基准零失败不等于未经预处理的任意三角汤零失败。
- 70% 预留、内部活跃内存、峰值 high-water mark 是不同量。
- CUB 比较针对论文中的 block-scope 方案，不能推广成“CUB 不能排序长数组”。
- 当前源码中的 host 同步不推翻几何 kernel 的 GPU 加速，但会影响零拷贝、异步串接和 CUDA Graph 集成设想。
