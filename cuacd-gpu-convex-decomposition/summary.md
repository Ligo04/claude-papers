# 论文概要

## 问题与背景

近似凸分解（ACD）的输入是一般三角网格，输出是数量可控的凸部件。凸体便于碰撞查询，但直接用整个物体的凸包会填平把手、凹槽和空洞；逐三角形使用又可能昂贵。ACD 在几何误差和部件数量之间折中。

CoACD 的搜索会反复执行“候选切平面 → 切开并封口 → 构建两侧凸包 → 计算凹度”。这产生大量小型、长度不固定、控制流复杂的几何任务。逐阶段移植成 CUDA kernel，会遇到阶段末尾 GPU 空闲，以及为取得输出长度而返回主机的问题。[论文 §1–4]

## 主要贡献

1. 以 warp 为协作单位：不同部件/候选提供粗粒度并发，一个 warp 的 32 个 lane 分担扫描、排序、过滤与局部几何操作。
2. 设备端 heap：64 个 arena 分摊竞争，按大小分桶，并合并相邻空闲块，让几何阶段内部的动态缓冲区可在 GPU 分配。
3. 可组合的几何组件：网格平面切割、D&C 凸包、方向极值预筛选、采样 Hausdorff、连通分量分解与凸包合并。
4. 候选集合增加凹边平面，配合较浅的 look-ahead 搜索，在实验中降低部件数。

“Fully GPU-Resident”是论文的系统定位。所查公开源码仍有主机控制与同步，详见 source-study.md；上述组件贡献不因此被否定。

## 数据来源与评测协议

没有训练集，也没有学习模型。输入来源是几何基准：V-HACD 的 61 个网格；PartNet-Mobility 的 2,347 个关节物体对应 14,085 个逐 link 合并网格；Objaverse 均匀抽样的 1,000 个网格。[§5.2]

硬件为 RTX 4090 + Intel i9-12900K，CUDA 12.1。所有方法输入同一份 PaMO 预处理网格（ratio 0.1、最少 10,000 面），表中计时排除 PaMO。作者扫各方法阈值，以 CoACD 默认目标附近的平均凹度建立比较点；表格实际凹度并不完全一致，尤其 Objaverse 的 NavACD 为 0.0950。[Table 1]

| 数据集 | 方法 | 平均凹度 ↓ | 平均部件数 ↓ | 平均分解时间/s ↓ |
|---|---|---:|---:|---:|
| V-HACD | CoACD | 0.0495 | 40.5 | 18.03 |
| V-HACD | NavACD | 0.0529 | 79.1 | 12.13 |
| V-HACD | VisACD | 0.0604 | 37.5 | 9.60 |
| V-HACD | CuACD | 0.0488 | 33.6 | 0.23 |
| PartNet-Mobility | CoACD | 0.0465 | 21.1 | 12.82 |
| PartNet-Mobility | NavACD | 0.0614 | 25.6 | 2.96 |
| PartNet-Mobility | VisACD | 0.0511 | 22.8 | 7.42 |
| PartNet-Mobility | CuACD | 0.0458 | 21.0 | 0.16 |
| Objaverse subset | CoACD | 0.0540 | 59.0 | 25.93 |
| Objaverse subset | NavACD | 0.0950 | 79.5 | 40.25 |
| Objaverse subset | VisACD | 0.0702 | 59.9 | 15.92 |
| Objaverse subset | CuACD | 0.0496 | 48.9 | 0.25 |

按表中舍入均值相除，CoACD / CuACD 分别约 78.4×、80.1×、103.7×；这是均值之比，不是逐网格 speedup 的平均。[由 Table 1 计算]

## 系统加速与候选质量的拆分

把凹边候选与参数移入 CPU CoACD 后，作者测得 33.7 个部件、0.0481 凹度、20.85 s；CuACD 为 33.6、0.0488、0.23 s。质量基本对齐但速度仍相差约 90.7×。这个控制实验支持“候选改善质量、GPU 系统改善速度”；它仍保留 MCTS 与 look-ahead 的差别，不能当作逐指令完全相同的 CPU/GPU 比较。[§5.3]

[Table 4] 深搜和加宽的边际收益小；逐轮拆连通分量有实际作用。

- V-HACD 单网格时间分布：最小 0.06 s、中位 0.22 s、最大 0.44 s；部件数 3–165。[Table 5]
- τ 从 0.05 收紧到 0.01：部件数约 34 → 194，时间 0.23 → 约 0.5 s，报告峰值内存约 1.4 → 1.6 GiB。[§5.5；近似数]
- Bistro 室内场景：1,043,077 三角形，τ=0.005，18.73 s，峰值 2355.6 MiB。[§5.6]
- 不能把报告的内部峰值用量等同于进程显存保留量：默认 heap 预留空闲 VRAM 的 70%。

所有上述性能是作者实验，本机仅核验文献、源码和教学 demo。
