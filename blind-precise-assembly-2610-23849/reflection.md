# 研究扩展与工程提案

以下为樵樵根据论文提出的待验证想法，不是原论文完成的实验，也没有修改 ManaEnv、Newton 或 UIPC 仓库。

## 1. 视觉加本体感知是否更好

在相同随机化、动作、训练预算下比较 RGB、proprioception、两者融合。分别评估接近、初次接触、局部搜索和就位阶段，避免只有总体成功率。融合策略可能缩短搜索，也可能过度依赖外观；需要用遮挡和几何分布外测试验证。

关键判据是可靠性和时间共同改善，且没有把测试零件或真实位姿泄漏给 actor。

## 2. 关节信号的可用性在哪里消失

分别改变编码器噪声、速度估计滤波、执行延迟、增益、关节摩擦和夹爪柔顺。看接触模式 probe、任务成功率、峰值力、卡住时长如何变化。

本文表 1 没有加入 observation noise，所以不能默认这部分鲁棒性已经得到验证。更高刚度可能让微小接触更难从关节运动识别；更低刚度可能带来更大误差与装配时间。这些方向需要实测。

## 3. 几何误差怎样传递到策略

选一个明确孔形和间隙，分别加入已知内侵、外扩或局部错误，然后训练/测试同一策略配置。比较几何误差相对间隙的比值，及策略是否学到真实世界不存在的接触。

先做无策略的墙面位置、接触起点和游隙测试，再进行策略测试。直接用成功率判断几何质量，会混入控制器补偿和接触柔顺。

## 4. 迁移到 ManaEnv / Newton / UIPC 的顺序

| 工作 | 产物 | 完成标准 |
|---|---|---|
| 固定一个销孔与真实间隙 | 可核对尺寸与单位的资产 | 导入后碰撞表面没有意外内侵 |
| 运行被动几何探针 | 墙面位置、横移/倾斜游隙报告 | 区分几何误差与求解器柔顺 |
| 对齐动作与关节反馈 | 同时记录 q、qdot、目标角、时间戳 | 50 Hz 策略与物理子步对应明确 |
| 加入历史 actor 和辅助监督 | 观测/标签分离的训练接口 | actor 推理无法访问真实零件位姿 |
| 从单任务扩展随机化 | 参数分布与失败分类 | 每次只增加可解释的难度 |
| 最后比较不同接触求解器 | 配置相同的场景与统计 | 报告任务表现、时间、误差和接触力 |

这里没有证明某个现有 adapter 能直接导入 `mjfit` 的全部资产。Newton 的不同后端、MuJoCo 的接触求解和 UIPC 的几何/接触模型需要分别核验。不要把表 4 直接搬成跨引擎排行榜。

## 5. 从起扣到完整拧紧

原任务在咬合后继续四分之一圈即成功。完整拧紧还涉及多圈旋转、夹爪重抓、轴向进给、终止力矩和错牙恢复。应先定义新的成功条件，再建立训练与评估；原论文的螺母成功率不能代表这些能力。

## 6. 真机统计和失败恢复

按零件、抓取偏差、初始倾角、接触位置分层报告失败。至少区分丢件、卡住、超时、夹具外滑落和控制限制触发。报告置信区间、全部计划 reset 及中止原因。

局部策略丢件以后需要上层恢复。可研究什么时候退出局部搜索并重新定位，但要把恢复成本计入总时间，不能仅保留成功段。
