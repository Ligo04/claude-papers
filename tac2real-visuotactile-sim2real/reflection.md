# 反思 —— 扩展、脆弱假设、失败模式

## 如果由我来扩展这篇论文

1. **把任务级标定(第 3 步)做成自动/在线。** 消融显示它最关键,却最依赖人工和具体任务。能否用少量真机交互
   做 **在线系统辨识**,或用一个可微仿真把 μ_isaac、接触刚度的标定变成梯度优化,从而新任务自动适配,减少
   "换任务重做"的代价?

2. **可形变物体与灵巧手。** 论文只验证刚性 peg/nut。把 PNCG-IPC 的软体能力用在 *被操作物体本身可形变*(布料、
   线缆)或 **多指灵巧手** 上,是显然的高价值方向(作者也列为 future work)。

3. **触觉 VLA 的大规模数据引擎。** Tac2Real 能高吞吐产出高质量触觉数据。把它接到 **视觉-语言-动作(VLA)** 训练,
   生成大规模"触觉 + 语言 + 动作"语料,可能比逐任务 RL 更通用。

4. **学习式触觉仿真加速。** 作者提到可用 AI 模型加速触觉仿真。一个想法:用神经网络蒸馏 PNCG-IPC 的"相对量 →
   位移场"映射,推理时跳过物理求解,把 FPS 再提一个量级——同时保留物理求解器做训练数据/校正。

5. **RGB + 标记点的混合表征。** 当前丢了纹理。对既需接触状态又需纹理识别的任务,能否设计一个 *任务自适应* 的
   表征选择,或轻量融合两者,而不牺牲 RL 的低维优势?

6. **跨传感器 / 跨本体泛化。** 现在绑定 GelSight Mini + Franka。把 TacAlign 做成对 *新传感器、新机器人* 的通用
   标定协议(论文已朝此设计),并验证 DIGIT、其他 VBTS、其他臂的可迁移性。

## 哪些开放问题仍存

- **"零样本"的边界在哪?** 策略不在真机训练,但系统做了大量真机标定(6-DOF 平台、压头、CMA-ES、任务微调)。
  一个诚实的问题:**总的人工 + 真机采样成本** 相比"少量真机微调(few-shot)"是否真的更省?论文未量化标定本身的
  时间/样本成本。
- **泛化到未见接触几何。** 真机只测了 0°、±15°(训练是 [-35°,35°])。对训练分布外的孔形、公差、材质,鲁棒性
  如何?
- **物理保真 vs 真机差距的因果。** 论文用 TacSL 的失败论证"保真重要",但没有 *单变量* 实验把"保真度"与"成功率"
  解耦——任务级标定的巨大作用暗示,**对齐** 可能比 **绝对保真** 更决定成败。
- **PNCG-IPC 的精度下界。** "几十次迭代收敛到足够精度"——"足够"对触觉够,但对力控精密装配(需要准确接触力)
  是否够?接触力的保真度未单独评估。

## 哪些假设脆弱

| 假设 | 为何是承重的 | 何时崩裂 |
|---|---|---|
| 触觉响应只取决于 **局部相对运动** | 支撑"只传相对量"的跨引擎插件 | 存在显著全局耦合(多接触点相互影响、整体动力学反馈)时 |
| 标记点位移场 **足以** 表征接触 | 决定观测空间设计与 RL 可行性 | 任务需要纹理、温度、或位移场分辨率不足以区分的细微接触 |
| **任务级标定** 能覆盖真实形变 | 真机成功率的命门(0.917 vs 0.250) | 接触模式比标定时的四种(静止/下压/前后碰撞)更丰富/更动态时 |
| "视觉合理 + 物理一致" 已足够 | 证明 PNCG 用精度换吞吐的合理性 | 需要 *精确接触力/机器精度* 的任务(精密力控装配) |
| 域随机化能补 **随机** 差距 | 第 4 步的全部依据 | 真实噪声结构与随机化分布不匹配(分布外噪声) |
| 伪结构网格的高 FPS 可用 | 并行性能卖点 | 复杂几何无法用伪结构网格,只能退回 1665 FPS 的非结构网格 |

## 实际中可能崩在哪

- **换新任务/新物体:** 很可能要重做任务级标定和部分随机化范围调整——"零样本"是对策略而言,对系统不是。
- **精密力控场景:** PNCG 的精度-吞吐权衡偏向"视觉合理",接触力可能不够准,精密装配/打磨类任务存疑。
- **复杂几何:** 只能用非结构网格,FPS 掉到 1665,大规模并行优势缩水。
- **gel 损耗与保护机制误触发:** MSE 阈值过敏则频繁回退打断任务、过钝则伤传感器;真机长期运行的稳定性未充分
  验证。
- **基础设施门槛:** 依赖 Ray 多节点多 GPU(4 节点 × 16 GPU)+ Taichi + 标定装置,复现门槛高,小团队难照搬。
- **分布外接触噪声:** 域随机化覆盖不到的真实噪声结构会让"随机差距"重新出现。

## 元层面的收获

这篇论文的经久教训:**仿真保真度和现实差距消除是正交且都必需的两件事**。再逼真的仿真(甚至仿真内 RL 成功),
没有系统化的 sim-to-real 对齐也会在真机上崩(TacSL:仿真 0.789 → 真机 0.15)。反过来,光有对齐流程而仿真不保真
(Tacchi 的 MPM 不稳)同样不行。Tac2Real 的价值不在某个单点算法,而在 **把"高保真 + 高并行 + 系统化对齐"
工程性地合到一起,并诚实地用消融指出"任务级标定"才是迁移的真正命门**——这对所有想把仿真训练策略送上真机的
工作都是一面镜子。
