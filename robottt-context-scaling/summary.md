# 论文总结：RoboTTT: Context Scaling for Robot Policies

## 背景

大语言模型（LLM）领域，上下文长度早已成为一条重要的 scaling 轴（GPT-3、LongRoPE 等工作持续把上下文从千级推向百万级 token）。但机器人基础模型完全没有跟上这个趋势：绝大多数 VLA（Vision-Language-Action）模型和部分 World Action Models 只接收**单步观测**，少数扩展到 2-8 帧的**短历史**，就已经是当前 SOTA。更长的历史信息，行业惯例是"下放"给更高层的语义结构（关键帧、语言摘要外部记忆库），而不是让视觉运动策略本身直接处理长序列。

这带来的代价是：策略天然缺乏一次性从人类视频学习（one-shot in-context imitation）、在线自我改进（on-the-fly policy improvement）、长时程多阶段任务的能力，因为这些能力都依赖对长视觉运动上下文的编码与利用。

## 问题陈述

论文提出的核心问题是：**如何构建能够从（并利用）任意长上下文中学习的视觉运动策略？**

直接的候选方案各有硬伤：
- **全量自回归处理整段 rollout 历史**（如部分序列模型）：能捕捉长程依赖，但 KV cache 下解码延迟随上下文线性增长，长时程真机部署代价过高。
- **传统 RNN（如 LSTM）**：推理成本恒定，但容量/表达力显著弱于全注意力模型。
- **朴素拼接历史帧**：论文实验证明这条路不可靠——在 Pup Go Car 任务上，GR00T N1.7 Hist.（多一帧历史）得分反而比无历史版本低（39.5% vs 57%），因为拼接历史容易引入虚假相关（causal confusion），且推理时可能超出训练所见的时间分布。

## 主要贡献

1. **模型架构**：将 Test-Time Training（TTT）机制接入机器人基础模型（以 GR00T N1.7 为例）。TTT 层插在 DiT action head 的自/交叉注意力层之后：attention 处理单时间步内的信息，TTT 层沿时间维度处理跨时间步信息。策略的"循环状态"是 fast weights——不同于训练后冻结的常规（慢）权重，fast weights 在训练和推理阶段都通过梯度下降持续更新，把历史压缩进参数空间，并在需要时检索出来。

2. **训练配方**：为了让训练上下文能够扩展到 8K 步，论文组合了两项技术：
   - **Sequence action forcing**：训练序列中每个 action chunk 独立采样 flow-matching 噪声水平 τ_t = s(1−u)，u ~ Beta(1.5, 1)，s = 0.999。如果整条序列共享一个噪声水平（"full-sequence diffusion"），会导致整条序列一致地"过易"或"过难"，训练变得不稳定。
   - **Truncated Backpropagation Through Time（TBPTT）**：把长序列切成若干 segment，梯度只在 segment 内反传，但 fast weights 本身跨 segment 边界持续传递（只是梯度在边界处被 detach）。这样 GPU 显存只取决于 segment 长度，而不是总序列长度，使任意长的训练上下文在固定显存预算下成为可能。

3. **上下文缩放律**：论文首次系统报告，机器人策略的闭环性能会随预训练上下文长度的增加而稳定提升——从 128 步到 8K 步，RoboTTT 的表现单调上升且无饱和迹象；而使用线性关联更新（无测试时梯度下降）的 Gated DeltaNet（GDN）基线则完全没有这一趋势，说明"能不能被外层损失元学习"是缩放能否发生的关键。

4. **新能力解锁**：长上下文让 RoboTTT 学会
   - **一次性人类视频模仿**：把人类视频段拼进训练序列，只用它更新 fast weights（对应的 flow-matching 损失被 mask 掉），动作损失只算在机器人轨迹段上；推理时输入一段未见配置的人类演示视频即可完成模仿。
   - **DAgger Distillation（在线自我改进）**：把 DAgger 式人机交互轨迹（含机器人的次优动作和人类纠正）整段作为 fast weights 的更新上下文，但 flow-matching 损失只算在人类纠正动作上——"失败作上下文，纠正作目标"。这是 Algorithm Distillation 思路在机器人领域的一次具体实例化。

## 关键结果

### 主实验：三个长时程装配任务的任务完成分数

| 方法 | 平均分 | Pup Go Car（成功数/20） | Circuit（成功数/20） | Gear Bot（成功数/10） |
|---|---|---|---|---|
| RoboTTT | 79% | 9/20 | 13/20 | **2/10（唯一完整成功）** |
| GR00T N1.7（单步基线） | 42% | 3/20 | 3/20 | 0/10 |
| GR00T N1.7 Hist.（一帧历史） | — | 0/20 | 8/20 | 0/10 |
| GDN（Gated DeltaNet） | 56% | 3/20 | 8/20 | 0/10 |

RoboTTT 比单步基线高 87%，比最强基线 GDN 高 41%。Gear Bot（十阶段、五分钟，最长任务）上只有 RoboTTT 有过完整成功。

### 上下文缩放律

预训练上下文从 128 步扩展到 8K 步，RoboTTT 闭环任务完成分数稳步上升，8K 时达到 71.5%：
- 比同模型 1K 上下文预训练版本（43.9%）高 **63%**
- 比最佳短上下文基线 GR00T N1.7 Hist.（45.6%）高 **57%**
- 无饱和迹象；GDN 无此缩放趋势

### 一次性模仿（Circuit 未见配置）

| 方法 | 任务完成分数 | 成功数 |
|---|---|---|
| RoboTTT | 65% | 6/10 |
| GDN | 33% | 0/10 |

### 抗扰动鲁棒性（Pup Go Car，移除车顶/轮胎后能否恢复）

| 方法 | 车顶扰动恢复 | 轮胎扰动恢复 |
|---|---|---|
| RoboTTT | 15/20 | 18/20 |
| GDN | 13/20 | 18/20 |
| GR00T N1.7 | 10/20 | 11/20 |
| GR00T N1.7 Hist. | 3/20 | 5/20 |

### DAgger 实验（100 条混合轨迹池：RoboTTT 与 GR00T N1.7 各收 50）

- 标准 DAgger（只用人类纠正微调）：四方法平均提升 9%，两个序列模型平均提升 13%
- DAgger Distillation（完整轨迹作上下文、损失只算纠正）：平均提升 **33%**（RoboTTT +36%，GDN +29%）
- 次优机器人动作单独作为模仿目标毫无价值：GR00T N1.7 用完整轨迹微调 vs 只用纠正微调，两者都是 57%，说明价值完全在于"作上下文"而非"作目标"

### 消融（Pup Go Car）

- 去掉 sequence action forcing：性能严重下降（动作不精确，机器人无法有效推进任务）
- Fast model 换成线性层（TTT-Linear）：比 MLP fast model 差 27%
- State tokens → +action tokens：相对提升 23%；→ +register tokens：再提升 18%
- Register tokens 单独加到 GR00T N1.7 上没有帮助——只有配合 TTT 的时间建模才起作用

## 实现要点

基于预训练 GR00T N1.7（Eagle VLM + DiT），16 个 DiT 层各加一层 TTT（每层约 10M 参数，模型从 538M 增至 690M），fast model 为两层 GeLU MLP，N=16 个 register tokens，tanh 门控（α 初始化 0.001）。预训练在桌面双臂机器人数据 + 第一人称人类数据（EgoScale）混合上进行，逐步把上下文加到目标长度（如 8K），30K 步、16 块 GB200 GPU，只调新增的 TTT/GDN 层、其余冻结。下游任务后训练时全参数微调，每任务 1K 上下文、20K 步、8 GPU。优化器 AdamW（wd 1e-5），预训练用 WSD 调度峰值学习率 2e-5，post-train 用 cosine 调度峰值 5e-5；TTT 内层学习率可学习，基础值 0.1；RoPE θ=10000。部署平台为 YAM 双臂机器人 + 4 个 RealSense D405（顶/底/左腕/右腕，480p），RTX 5090，30Hz 闭环控制。

三个评测任务：Pup Go Car（8 小时数据，平均 2 分钟一集）、Circuit（6 小时，1 分钟一集，80 种装配配置，训练 20 测试 60）、Gear Bot（5 小时，5 分钟一集，十阶段装配，最长时程任务）。

预训练轨迹长度分布：<512 步占 3.1%，512-1K 占 12.5%，1K-2K 占 25.9%，2K-4K 占 41.4%，>4K 占 17.1%。
