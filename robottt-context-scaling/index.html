02 / 机制

TTT 的 Update → Apply 循环

拖动时间轴，观察每个时间步 fast weights 如何先 update（把 K→V 的关联压进权重）， 再 apply（用更新后的权重产出输出）。右侧对比 Transformer KV cache 与 TTT 状态随上下文增长的内存占用。

时间步 t（拖动或点击）

① Update（更新 fast weights）

W₀ ← W₋₁ − η∇ℒ_FW

用自监督目标 ℒ_FW，把当前时间步的 K→V 关联压缩进权重 W，η 为可学习学习率。

② Apply（用新权重产出）

O₀ = f_W₀(Q₀)

fast model f_W 是两层 GeLU MLP，用刚更新的 W_t 处理当前 Query 得到输出 O_t。

内存占用 vs 上下文长度（示意）
Transformer KV cache（随上下文线性增长） TTT 状态（fast weights，大小恒定）

TTT 把历史压缩进固定大小的权重矩阵，因此推理成本不随上下文长度增长——这正是能把上下文扩展到 8K 的关键。

05 / 训练配方

训练配方交互卡

两项关键训练技巧：让整条序列噪声一致的 sequence action forcing，以及控制显存的 TBPTT。

Sequence Action Forcing

τ_t = s(1−u),  u ~ Beta(1.5, 1),  s = 0.999

每个 action chunk 的加噪水平 τ_t 由同一个 u 采样得到（共享），而不是每个 chunk 独立采样。

共享噪声让整条序列在同一个"难度"上（要么整体接近干净、要么整体接近纯噪声）， 使 TTT 层学到跨时间步一致的去噪信号；若每个 chunk 独立采样噪声，序列内难度参差不齐，反而更难学习。

TBPTT（截断反向传播）

拖动滑块调整 segment 长度：segment 边界处梯度被截断，但 fast weights 仍连续向前传递；显存占用 ∝ segment 长度。

06 / 速查

关键事实卡片

三项评测任务

  • Pup Go Car：玩具车装配，平均 2 分钟/episode，8 小时数据
  • Circuit：电路板装配，1 分钟/episode，6 小时数据，80 种配置
  • Gear Bot：十阶段装配，最长时序任务，平均 5 分钟，5 小时数据

部署设置

  • YAM 双臂机器人（bimanual）
  • 4 × RealSense D405 相机
  • 推理硬件：RTX 5090
  • 控制频率：30 Hz

训练设置

  • 预训练：16 × NVIDIA GB200，30K 步
  • 后训练（post-train）：8 GPU，20K 步
  • 优化器：AdamW；学习率调度 WSD（预训练 2e-5）/ cosine（后训练 5e-5）
  • TTT 内层学习率 η = 0.1，可学习（learnable）

模型规模

  • 基座参数量：538M
  • 加入 16 层 TTT 后：690M
  • 每层 TTT 约增加 10M 参数
  • fast model：两层 GeLU MLP
