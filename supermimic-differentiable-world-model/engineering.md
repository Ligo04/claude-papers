# 对仿真与机器人训练工程的含义

这里讨论 Newton、ManaEnv、UIPC 等工作中可以检验的方向，属于工程推断。本次未读取或修改这些项目的实现，没有完成任何 adapter 或 runtime 集成。

## 标准物理后端可以继续产生监督数据

SuperMimic 对训练数据和学习模型求导，不要求 Newton、MuJoCo 或接触求解器暴露梯度。理论上，可以保留高保真仿真后端，记录状态、执行动作和场景参数，再单独训练一个控制用模型。

可迁移的是这种职责划分，不能据此假定不同后端的数据能够直接互换。时间步、PD gain、action scale、关节定义、接触摩擦、reset 和终止规则会改变日志的含义。后端或配置变更应有版本标识，旧数据要按同一转移函数的假设重新审查。

## “机器人相同”不保证任何场景都能共享原模型

平地动作库的不同目标共享同一机器人和地面。若换成抓取、软包操作、布料接触，物体的状态、形变、材料和接触关系也影响下一状态。只输入机器人本体信息可能不再满足近似 Markov 假设。

对于 UIPC 一类包含变形体状态的仿真，模型还要面对高维网格、接触切换与材料参数。可以探索低维形变表示、任务相关状态或分层模型，但都属于待检验设计。论文没有给出这种扩展的精度、计算资源或物理约束保证。

## 学习模型和可微物理应分别评价

| 维度 | 学习动力学后反传 | 直接对物理离散系统求导 |
| --- | --- | --- |
| 数据与实现 | 需要覆盖相关分布的转移日志与模型训练 | 需要求解器和相关物理量的求导实现 |
| 梯度含义 | 学习代理目标的梯度，可能有模型偏差 | 所选离散模型及求导处理下的梯度 |
| 接触 | 可用平滑近似学习局部规律 | 依赖接触公式、切换与隐式求导处理 |
| rollout 成本 | 小模型和大批量可能有优势 | 取决于具体物理、求解器和批量 |
| 约束保证 | 不自动继承原仿真的约束 | 取决于具体方法的假设与实现 |

表格描述方法类别，不给所有求解器做统一性能排序。尤其不能因为训练数据来自具有不相交约束的仿真，就声称学习模型输出也具有相同保证。

## 一个可验证的接入顺序

1. 选固定机器人、平地和少量动作，统一控制步、执行器、状态坐标及记录格式。
2. 从真实后端采集连续窗口，包含执行动作、上下文、参考时间与 reset/termination 边界。
3. 用短自回归窗口训练模型，在独立日志上评价一步及多步误差，并单列接触切换片段。
4. 对小动作扰动检查预测变化与后端变化的方向，再检验一小步 actor 更新在后端的实际回报变化。
5. 分别做相同数据的 PPO-Sim、PPO-WM 和模型梯度更新对照。
6. 只有基础控制已经有效，才扩大数据量、增加下游目标或引入物体/地形交互。

这是一组建议实验，没有执行，也未设定未经测量的速度目标。

## 性能报告应该保留哪些分母

分别记录物理后端采样、模型训练、actor/critic 更新、数据搬运和检查点评估。每个 rollout step 明确是物理子步还是控制步；对齐并行环境数、precision、GPU 型号和控制周期。

不能把模型 forward 吞吐当作完整训练速度，不能把训练动作覆盖率当作未见测试泛化，也不能把真机展示片段当作全动作库真机验收。资源预算最好同时给出墙钟、每卡型号和卡时，而不是只给 GPU 数量。

## 真正值得带走的工程选择

先验证学习出的局部梯度确实有助于改进后端中的控制，再考虑扩大模型与动作库。若模型在常见接触状态都给出错误更新方向，增加 rollout 数量和训练卡数未必能补救。
